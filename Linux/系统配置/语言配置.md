# 1. locale 环境变量含义

每个 `LC_*` 变量控制系统某一方面的本地化行为：

| 变量 | 含义 | 影响范围 |
|---|---|---|
| `LANG` | 默认 locale | 控制字符编码、日期格式、排序规则、错误信息语言，当某个 `LC_*` 未设置时的回退值 |
| `LC_CTYPE` | 字符分类 | 识别字母、数字、大小写、空格等；==乱码通常与此有关== |
| `LC_NUMERIC` | 数字格式 | 小数点 `.` 还是 `,`，千位分隔符 |
| `LC_TIME` | 日期时间格式 | `2026/05/31` 还是 `31/05/2026`，月份星期名称语言 |
| `LC_COLLATE` | 排序顺序 | `a` 在 `B` 前还是后，是否区分大小写 |
| `LC_MONETARY` | 货币格式 | 货币符号位置、小数点位数 |
| `LC_MESSAGES` | 消息语言 | 程序输出信息（如 `ls` 错误提示）的语言 |
| `LC_PAPER` | 纸张大小 | A4 还是 Letter |
| `LC_NAME` | 姓名格式 | 姓在前还是名在前 |
| `LC_ADDRESS` | 地址格式 | 不同国家的地址书写习惯 |
| `LC_TELEPHONE` | 电话号码格式 | 不同国家的号码格式 |
| `LC_MEASUREMENT` | 度量衡 | 公制还是英制 |
| `LC_IDENTIFICATION` | locale 自身元信息 | 一般用不到 |
| `LC_ALL` | 强制覆盖所有 `LC_*` | 如果设置了这个，其他所有 `LC_*` 和 `LANG` 都被忽略 |

> [!important] 优先级
> `LC_ALL` > 各个 `LC_*` > `LANG`
>
> `LC_ALL` 不要滥用——设了它会覆盖所有单项，建议只设 `LANG` 加需要的单项覆盖即可。

# 2. 设置中文 locale

## 2.1 检查与生成中文 locale

1. 检查中文 locale 是否已生成：

```bash
locale -a | grep zh_CN
```

2. 如果没有，先生成它：

- **Arch Linux：**

```bash
sudo sed -i 's/^#zh_CN.UTF-8 UTF-8/zh_CN.UTF-8 UTF-8/' /etc/locale.gen
sudo locale-gen
```

- **Debian/Ubuntu：**

```bash
sudo sed -i 's/^# zh_CN.UTF-8 UTF-8/zh_CN.UTF-8 UTF-8/' /etc/locale.gen
sudo locale-gen
```

> [!info] Fedora/RHEL 一般已包含中文 locale，直接可用。

## 2.2 设为系统默认

- **Arch Linux**：编辑 `/etc/locale.conf`

```bash
LANG=zh_CN.UTF-8
```

- **Debian/Ubuntu**：编辑 `/etc/default/locale`

```bash
LANG=zh_CN.UTF-8
LC_CTYPE=zh_CN.UTF-8
LC_NUMERIC=en_US.UTF-8
LC_TIME=zh_CN.UTF-8
LC_MESSAGES=zh_CN.UTF-8
```

> [!tip] 保留英文数字/时间格式
> 如果想保留英文数字格式等习惯，可以不设 `LC_ALL`，只设 `LANG=zh_CN.UTF-8`，然后把想保留英文的项设回 `en_US.UTF-8`，比如 `LC_NUMERIC` 和 `LC_COLLATE`。

## 2.3 仅对当前用户生效

编辑 `~/.bashrc` 或 `~/.zshrc`，加入：

```bash
export LANG=zh_CN.UTF-8
export LANGUAGE=zh_CN:zh
export LC_ALL=zh_CN.UTF-8
```

然后执行 `source ~/.bashrc` 或重新登录。

# 3. WSL2 环境的特殊问题

> [!bug] WSL2 注入 locale 导致系统配置失效
> WSL2 的 `/init` 进程会检测 Windows 显示语言，并将 `LANG=en_US.UTF-8` ==注入到环境变量中==，发生在 shell 启动之前。而 `/etc/profile.d/locale.sh` 仅在 `LANG` 为空时才加载 `/etc/locale.conf`，所以系统配置被跳过了。

**症状：** `/etc/locale.conf` 已设 `LANG=zh_CN.UTF-8`，但 `locale` 命令仍显示 `en_US.UTF-8`。

**解决方案：** 创建一个在 `locale.sh` 之后执行的覆盖脚本：

```bash
sudo tee /etc/profile.d/zz-locale-zh.sh << 'EOF'
# Override WSL2-injected locale — runs after locale.sh due to zz- prefix
export LANG=zh_CN.UTF-8
export LANGUAGE=zh_CN.UTF-8
EOF
```

> [!info] 文件名以 `zz-` 开头
> `/etc/profile.d/` 下的脚本按字母序执行，`zz-` 前缀确保在 `locale.sh` 之后执行，从而覆盖 WSL 注入的值。

生效方式：`wsl --shutdown` 后重启 WSL。

# 4. 注意事项

> [!warning] 注意事项
> - **终端字体支持**：确保终端模拟器支持中文字体显示
> - **SSH 环境**：SSH 连接时可能会把客户端的 locale 变量带过来，可以在服务器端的 `~/.ssh/environment` 或 `/etc/ssh/sshd_config` 中 `AcceptEnv LANG LC_*` 来控制
> - **部分程序不认 locale**：某些旧程序或非 GNU 工具可能不响应 locale 设置
