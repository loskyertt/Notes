# 1. 切换用户

## 1.1 使用 `su` 命令

`su`（switch user）用于切换到其他用户身份，默认切换到 `root`。执行后需要输入**目标用户的密码**。

```bash
# 切换到 root 用户，同时加载 root 的完整登录环境（推荐）
su -

# 切换到 root 用户，但保留当前用户的环境变量（不推荐）
su

# 切换到指定用户
su - <username>
```

**`su` 与 `su -` 的区别**：

| 命令 | 环境变量 | 工作目录 | 说明 |
|---|---|---|---|
| `su` | 保留当前用户的环境 | 不变 | 仅切换身份，`PATH` 等变量不更新 |
| `su -` | 加载目标用户的完整登录环境 | 切换到目标用户的 `HOME` | 等同于以目标用户重新登录 |

绝大多数情况下应使用 `su -`，避免因 `PATH` 不正确导致命令找不到的问题。

## 1.2 使用 `sudo` 命令

`sudo`（superuser do）允许已授权用户以 `root` 或其他用户身份执行命令，执行时输入的是**当前用户自己的密码**（而非 root 密码）。当前用户需要在 `sudoers` 文件中拥有相应权限。

```bash
# 以 root 身份执行单条命令（最常用）
sudo <command>

# 示例：查看 root 目录
sudo ls /root

# 切换到 root 用户并加载其登录环境（等同于 su -，但使用当前用户密码）
sudo -i

# 以指定用户身份执行命令
sudo -u <username> <command>
```

## 1.3 使用 `sudo su` 命令

`sudo su -` 先通过 `sudo` 获取临时 root 权限，再调用 `su -` 切换到 root 用户并加载其完整登录环境。

```bash
sudo su -
```

这在**禁用了 root 密码**（如 Ubuntu 默认配置）但当前用户拥有 `sudo` 权限的场景下非常实用：此时无法直接用 `su -`（因为不知道 root 密码），可以用 `sudo su -` 绕过。

## 1.4 三种方式对比

| 命令 | 需要输入的密码 | 适用场景 |
|---|---|---|
| `su -` | root 用户密码 | 知道 root 密码，需要长期使用 root 环境 |
| `sudo <command>` | 当前用户密码 | 只需执行一条特权命令 |
| `sudo -i` | 当前用户密码 | 不知道 root 密码，需要进入 root 环境 |
| `sudo su -` | 当前用户密码 | 同 `sudo -i`，更兼容老系统 |

## 1.5 注意事项

- 在 Ubuntu 等基于 Debian 的发行版中，安装时默认**锁定 root 用户密码**，无法直接使用 `su -`，应使用 `sudo -i` 或 `sudo su -`。
- `sudo` 的授权配置文件为 `/etc/sudoers`，应通过 `visudo` 命令编辑，该命令会在保存时进行语法检查，避免配置错误导致无法获取权限。
- 切换为 root 后，命令提示符会从 `$` 变为 `#`，操作需格外谨慎。
- 使用完 root 权限后，用 `exit` 或 `Ctrl+D` 退出，回到普通用户。

# 2. 用户管理

## 2.1 查看用户信息

```bash
# 查看当前登录用户名
whoami

# 查看当前用户的 UID、GID 及所属组
id

# 查看指定用户的信息
id <username>

# 查看所有已登录用户
who

# 查看系统所有用户（每行一条记录）
cat /etc/passwd

# 查看用户账号的详细配置（密码过期策略等）
sudo chage -l <username>
```

`/etc/passwd` 每行格式为：`用户名:密码占位符:UID:GID:注释:主目录:登录 Shell`

## 2.2 创建用户

```bash
# 创建用户并自动生成主目录（推荐）
sudo useradd -m <new_username>

# 创建用户并指定 Shell（默认 Shell 通常为 /bin/sh）
sudo useradd -m -s /bin/bash <new_username>

# 创建用户并指定主目录路径
sudo useradd -m -d /home/custom_dir <new_username>

# 创建用户并指定 UID
sudo useradd -m -u 1100 <new_username>
```

**常用选项说明**：

| 选项 | 说明 |
|---|---|
| `-m` | 自动创建主目录（`/home/<username>`） |
| `-s <shell>` | 指定登录 Shell，如 `/bin/bash`、`/bin/zsh` |
| `-d <dir>` | 指定主目录路径 |
| `-u <uid>` | 指定用户 UID |
| `-g <group>` | 指定用户的主组 |
| `-G <groups>` | 指定用户附加组（逗号分隔） |
| `-c <comment>` | 添加备注信息（如全名） |

创建用户后，必须为其设置密码，否则账号处于锁定状态：

```bash
sudo passwd <new_username>
```

## 2.3 修改用户

```bash
# 修改用户名
sudo usermod -l <new_username> <old_username>

# 修改用户的主目录（-m 表示同时移动原主目录内容）
sudo usermod -d /new/home/path -m <username>

# 修改用户的登录 Shell
sudo usermod -s /bin/zsh <username>

# 修改用户备注
sudo usermod -c "Full Name" <username>

# 锁定账号（禁止登录）
sudo usermod -L <username>

# 解锁账号
sudo usermod -U <username>
```

## 2.4 删除用户

```bash
# 只删除用户账号，保留主目录和文件
sudo userdel <username>

# 同时删除用户账号、主目录及其所有文件（谨慎使用）
sudo userdel -r <username>
```

> **注意**：`-r` 选项会不可恢复地删除用户的主目录和邮件目录，执行前应确认数据已备份。

# 3. 用户组管理

## 3.1 查看组信息

```bash
# 查看当前用户所属的所有组
groups

# 查看指定用户所属的所有组
groups <username>

# 查看系统所有组
cat /etc/group
```

`/etc/group` 每行格式为：`组名:密码占位符:GID:成员列表`

## 3.2 创建与删除组

```bash
# 创建新组
sudo groupadd <groupname>

# 创建新组并指定 GID
sudo groupadd -g 1100 <groupname>

# 删除组
sudo groupdel <groupname>

# 修改组名
sudo groupmod -n <new_groupname> <old_groupname>
```

## 3.3 管理用户的组成员关系

```bash
# 将用户添加到附加组（-a 表示追加，不加 -a 会覆盖现有附加组）
sudo usermod -aG <groupname> <username>

# 将用户添加到 sudo 组（Debian / Ubuntu）
sudo usermod -aG sudo <username>

# 将用户添加到 wheel 组（RHEL / CentOS / Arch）
sudo usermod -aG wheel <username>

# 将用户从某个组中移除（需重新指定除目标组外的所有附加组）
sudo gpasswd -d <username> <groupname>
```

> **`-aG` 中 `-a` 不可省略**：`usermod -G <group> <username>` 会将用户的附加组**替换**为仅包含 `<group>`，导致用户脱离原有的其他附加组。

**`sudo` 组与 `wheel` 组的区别**：

| 组名 | 发行版 | 说明 |
|---|---|---|
| `sudo` | Debian / Ubuntu 系 | 成员可使用 `sudo` 执行特权命令 |
| `wheel` | RHEL / CentOS / Fedora / Arch 系 | 功能相同，名称不同 |
