# 1. 第一步：在【联网 Windows 端】打包源码与全量依赖

> 这里以 `pi-cc-extensions` 插件为例

1. 新建缓存目录并进入：

在 Windows 的 PowerShell 或 CMD 中执行：

```bash
mkdir pi-offline-cc && cd pi-offline-cc
```

2. 下载 `pi-cc-extensions` 的离线包：

```bash
npm pack pi-cc-extensions
```

这会在当前目录下生成一个形如 `pi-cc-extensions-1.0.4.tgz` 的压缩包。

3. 本地物理拉取全部依赖项：

```bash
# 初始化一份临时的配置清单
npm init -y

# 将刚才下载的 tgz 彻底安装到当前临时目录，让 npm 将依赖关系完全下载下来
npm install pi-cc-extensions-1.0.4.tgz
```

4. 一键压缩带走：

在 Windows 上，把整个 `pi-offline-cc` 文件夹（包含刚才下载的 *.tgz 和包含所有深层依赖的 node_modules 文件夹）压缩为 pi-offline-cc.zip。

---

# 2. 第二步：上传并部署到【内网服务器】

1. 将压缩包上传到服务器：

通过 scp、SFTP 或云控制台将 `pi-offline-cc.zip` 上传至目标服务器的某个工作目录（例如 /tmp/）。

2. 在服务器上进行物理接驳和解压：


```bash
cd /tmp/
unzip pi-offline-cc.zip && cd pi-offline-cc

# 1. 解压主插件包，解压后默认会产生一个叫 package 的文件夹
tar -zxvf pi-cc-extensions-*.tgz

# 2. 将解压出来的源码目录改名为其规范名称 pi-cc-extensions
mv package pi-cc-extensions

# 3. 将 Windows 端打包下载好的 node_modules 移动到这个插件根目录下，完成物理依赖装配
mv node_modules pi-cc-extensions/
```

---

# 3. 第三步：搬运至 Pi 全局扩展发现目录

利用 Pi 的 Auto-Discovery（自动发现机制） 让它在启动时静默识别，彻底免去执行需要联网的安装命令：

1. 将装配好的插件移动到 Pi 的全局扩展驻留路径下：

```bash
mkdir -p ~/.pi/agent/extensions/
mv pi-cc-extensions ~/.pi/agent/extensions/
```

2. 最终确保服务器上的文件结构如下所示：

```text
~/.pi/agent/extensions/pi-cc-extensions/
├── package.json
├── extensions/
├── themes/
└── node_modules/      <-- 这里是完整的离线依赖链
```
