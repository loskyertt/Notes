# 1. pip

## 1.1 说明

**pip** 是 Python 的官方包安装器，定位为**语言级包管理器**，类似于 npm（Node.js）、cargo（Rust）、gem（Ruby）。

核心特征：

- 只管理 **Python 包**（wheel / sdist）
- 逐步解析依赖，不保证全局兼容
- 不懂系统 ABI、CUDA、动态库
- `pip install 成功 ≠ 运行一定成功`（缺少系统级依赖时）

> [!summary]
> pip = Python 包安装器。它只负责把 wheel 解压进 `site-packages`，不关心系统级依赖。

## 1.2 安装

pip 随 Python 自带，通常无需单独安装。若需升级或重装：

```bash
# 升级 pip
python -m pip install --upgrade pip

# 通过 ensurepip 模块安装（Python 自带）
python -m ensurepip --upgrade
```

## 1.3 使用

### 1.3.1 包安装

```bash
pip install <package_name>                        # 安装最新版
pip install <package_name>==<版本号>               # 安装指定版本
pip install <package_name> -i <镜像源URL>          # 使用临时镜像源
pip install -r requirements.txt                    # 从文件批量安装
pip install --no-cache-dir <package_name>          # 安装时跳过缓存
```

### 1.3.2 包管理

```bash
pip uninstall <package_name>      # 卸载
pip list                          # 列出已安装的包
pip show <package_name>           # 查看包详情
pip freeze > requirements.txt     # 导出依赖列表
```

### 1.3.3 缓存管理

| 操作 | 命令 |
|---|---|
| 查看缓存位置 | `pip cache dir` |
| 查看缓存信息 | `pip cache info` |
| 列出缓存中的包 | `pip cache list` |
| 清除所有缓存 | `pip cache purge` |
| 删除特定包缓存 | `pip cache remove <package_name>` |

**各系统默认缓存路径**：

| 操作系统 | 缓存路径 |
|---|---|
| Linux | `~/.cache/pip` |
| macOS | `~/Library/Caches/pip` |
| Windows | `%LocalAppData%\pip\Cache` |

## 1.4 优缺点

| 优点 | 缺点 |
|---|---|
| Python 官方标配，零配置即可用 | 不懂系统 ABI / CUDA / 动态库 |
| 生态最完整，所有 PyPI 包均可安装 | 逐步解析依赖，不保证全局兼容 |
| 使用简单，一条命令即可 | 安装成功不等于运行成功 |
| | 无环境隔离（需配合 venv） |
| | 无项目管理能力（需配合 pip-tools） |

# 2. conda

## 2.1 说明

**conda** 不是单纯的 Python 包管理器，而是**可创建隔离用户态运行时的跨语言包管理器**。

可以把 conda 理解为"**用户态的小型 Linux 发行版包管理器**"，与 `apt`、`yum`、`dnf`、`pacman` 在设计思想上非常相似。

### 2.1.1 conda 环境的本质

conda 环境本质上是一个**独立前缀目录**，类似一个小型 rootfs：

```text
C:\Users\sky\miniforge3\envs\cloud_point
```

其内部结构类似 `/usr` 或 `/opt/custom_env`：

```text
bin/
Lib/
DLLs/
site-packages/
include/
Library/bin/
```

一个 conda 环境中包含的不仅是 Python，还有：

- 动态库（OpenSSL、libc 兼容层等）
- CUDA runtime
- numpy / scipy 等科学计算库
- ffmpeg 等系统级工具

### 2.1.2 为什么科学计算偏好 conda

许多 AI / 科学计算包**根本不是纯 Python**：

| 包 | 实际底层依赖 |
|---|---|
| numpy | BLAS / LAPACK |
| scipy | Fortran |
| pytorch | CUDA / C++ |
| open3d | 大型 C++ 工程 |
| opencv | ffmpeg / libjpeg |

这些包更接近 Linux 系统软件，而非简单 Python 模块。conda 能统一管理这些跨语言依赖，而 pip 无法做到。

### 2.1.3 conda 安装慢的原因

conda 安装包时会执行**全环境依赖求解**（SAT 约束满足问题）。

例如当执行 `conda install pytorch` 时，conda 需同时检查：

- Python 版本
- numpy ABI
- CUDA 版本
- MKL / OpenBLAS
- OpenSSL
- 编译器 ABI
- 已安装包兼容性

然后**重新求解整个环境**，找到一组全局兼容的版本。这比 pip 的逐步解析复杂得多，但也更可靠。

> [!warning]
> 当依赖约束冲突时（如 torch 需要 `numpy>=1.26`，某包需要 `numpy<1.25`），conda 求解会非常慢甚至失败。此时需手动调整版本约束。

### 2.1.4 conda 与 apt 的区别

| 维度 | apt / yum | conda |
|---|---|---|
| 管理对象 | 整个操作系统 | 用户态隔离环境 |
| 权限要求 | 需要 root | 不需要 root |
| 多版本共存 | 困难 | 轻松（`conda create -n py310` / `conda create -n py311`） |

## 2.2 安装与配置

### 2.2.1 Linux 环境

**Miniconda3**：

```bash
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
chmod +x Miniconda3-latest-Linux-x86_64.sh
./Miniconda3-latest-Linux-x86_64.sh
```

**Miniforge**（推荐）：

```bash
# x86_64 架构（大多数 PC）
wget https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh

# ARM64 架构（如 Raspberry Pi）
wget https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-aarch64.sh

chmod +x Miniforge3-Linux-*.sh
./Miniforge3-Linux-*.sh
```

> [!tip]
> 推荐使用 **Miniforge** 而非 Miniconda。Miniforge 默认使用 conda-forge 频道，社区维护更活跃，包更新更快。

**集成到 Zsh/Bash**（以 miniconda 为例，miniforge 操作方式完全相同）：

**步骤 1**：添加环境变量到 `~/.zshrc`：

```bash
export PATH=/opt/miniconda3/bin:$PATH
```

**步骤 2**：禁止 conda 自动激活 base 环境（建议）：

```bash
conda config --set auto_activate_base false
# 或者（新版命令）
conda config --set auto_activate false
```

查看当前 auto_activate 设置：

```bash
conda config --show auto_activate
```

> [!tip]
> 该命令同样适用于 Windows PowerShell。

**步骤 3**：重新加载配置：

```bash
source ~/.zshrc
```

**步骤 4**：初始化 conda：

```bash
/opt/miniconda3/bin/conda init zsh
```

**步骤 5**：再次重新加载配置：

```bash
source ~/.zshrc
```

**步骤 6**：验证安装：

```bash
conda --version
```

> [!tip]
> 也可以不执行 `conda init`，直接将以下内容手动添加到 `~/.zshrc`（注意修改安装路径）：
>
> ```bash
> # >>> conda initialize >>>
> __conda_setup="$('/opt/miniconda3/bin/conda' 'shell.zsh' 'hook' 2> /dev/null)"
> if [ $? -eq 0 ]; then
>     eval "$__conda_setup"
> else
>     if [ -f "/opt/miniconda3/etc/profile.d/conda.sh" ]; then
>         . "/opt/miniconda3/etc/profile.d/conda.sh"
>     else
>         export PATH="/opt/miniconda3/bin:$PATH"
>     fi
> fi
> unset __conda_setup
> # <<< conda initialize <<<
> export CRYPTOGRAPHY_OPENSSL_NO_LEGACY=1
> ```

> [!warning]
> 如果安装了 `starship`，为了避免 **conda 和 Starship 同时显示环境名**：
> - Conda 的 shell hook 默认修改 PS1，在顶部加 `(base)`
> - Starship 的 prompt 右侧也显示 `via 🅒 base`
> 建议执行 `conda config --set changeps1 false`，这样 conda 就不会再往 PS1 里加 `(base)`。

**OpenSSL 报错修复**：

运行 `conda activate base` 时出现 OpenSSL 3.0 legacy provider 错误时，在 `~/.zshrc` 中添加：

```bash
export CRYPTOGRAPHY_OPENSSL_NO_LEGACY=1
```

然后执行 `source ~/.zshrc`。

### 2.2.2 Windows 环境

- [下载 Miniforge](https://github.com/conda-forge/miniforge)（推荐）
- [下载 Miniconda](https://www.anaconda.com/docs/getting-started/miniconda/install#anaconda-website)

推荐安装 [最新版 PowerShell](https://github.com/PowerShell/PowerShell)（PowerShell 7+），其指令功能更强大。

**集成到 PowerShell**：

**步骤 1**：在 PowerShell 中执行初始化（替换为你的安装路径）：

```powershell
& 'C:\Users\sky\miniforge3\Scripts\conda.exe' init powershell
```

> `conda init powershell` 会将 conda 的初始化脚本写入 PowerShell 配置文件（`$PROFILE`），添加 `conda` 函数、激活/停用钩子及路径处理。

**步骤 2**：关闭并重新打开 PowerShell。

**步骤 3**：验证 conda 可用：

```powershell
conda --version
where.exe python
```

> [!warning]
> 如果第 1 步报"脚本被禁用"或权限错误，先执行：
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force
> ```
>
> 然后重试 `conda init` 与重启操作。

**cmake 误找 conda 的 FLANN 库**：

conda 环境激活后会将自己的库路径加入环境变量，导致 cmake 优先找到 conda 的 FLANN（带 lz4 依赖），而非 PCL 自带的 FLANN。构建前临时退出 conda 环境即可：

```powershell
conda deactivate
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_C_COMPILER=cl -DCMAKE_CXX_COMPILER=cl
```

## 2.3 使用

### 2.3.1 配置查看

```bash
conda config --show channels     # 查看镜像源
conda config --show-sources      # 查看配置文件内容
```

### 2.3.2 代理设置

```bash
# 添加代理
conda config --set proxy_servers.http http://127.0.0.1:10809
conda config --set proxy_servers.https http://127.0.0.1:10809

# 移除代理
conda config --remove-key proxy_servers
```

> [!info]
> 如果启用了代理软件的 TUN 模式，无需单独为 conda 配置代理。

### 2.3.3 环境管理

| 操作 | 命令 |
|---|---|
| 创建环境（指定名称） | `conda create -n <name> python=<版本>` |
| 创建环境（指定路径） | `conda create --prefix /path/to/env python=3.11` |
| 激活环境 | `conda activate <name>` |
| 退出环境 | `conda deactivate` |
| 查看所有环境 | `conda info --envs` 或 `conda env list` |
| **彻底删除**指定的虚拟环境及其中所有的包 | `conda remove -n <name> --all` / `conda env remove -n <name>` |
| 克隆/重命名环境 | `conda create -n <new_name> --clone <old_name>` |
| **清理全局缓存**，释放硬盘空间，不会删除任何环境 | `conda clean --all` |

> [!warning]
> `--prefix/-p` 与 `--name/-n` 不能同时使用。推荐使用 `-n` 命名方式，路径方式管理不便。

> [!tip]
> 删除环境后，可手动清理残留目录：
> - Windows：`C:\Users\<用户名>\miniforge3\envs\`
> - Linux：`~/miniforge3/envs/`

### 2.3.4 包安装

```bash
# 查询 conda-forge 中的包
conda search -c conda-forge <package_name>

# 从 conda-forge 安装
conda install -c conda-forge <package_name>

# 安装指定版本
conda install -c conda-forge <package_name>=<版本号>
```

> [!info]
> Miniforge 默认从 conda-forge 下载包，无需手动指定 `-c conda-forge`。

示例——安装 GDAL：

```bash
conda install geos proj              # 先装依赖
conda install -c conda-forge gdal=3.2.1  # 再装指定版本
```

### 2.3.5 环境迁移

**打包环境**：

```bash
conda pack -n <env_name> -o environment.tar.gz
```

如果提示 `No command 'conda pack'`，先安装：

```bash
conda install -c conda-forge conda-pack
```

**在新机器上还原**：

```bash
# 进入 conda 的 envs 目录
cd ~/miniforge3/envs/    # Linux
# 或 cd C:\Users\<用户名>\miniforge3\envs\    # Windows

mkdir <env_name>
tar -xzvf environment.tar.gz -C <env_name>
```

### 2.3.6 环境导出与导入

```bash
# 导出环境配置
conda env export -n <env_name> > environment.yml

# 从配置文件创建环境
conda env create -f environment.yml
```

> [!tip]
> `environment.yml` 比 `conda pack` 更轻量，只记录依赖信息而非二进制文件，适合环境迁移和版本控制。但不适合跨平台迁移（如 Windows → Linux）。

### 2.3.7 缓存清理

**一键清理**：

```bash
conda clean --all
```

该命令清理：未使用的包、索引缓存、tarball 缓存、临时文件。

**分项清理**：

```bash
conda clean --packages         # 删除未使用的包
conda clean --index-cache      # 清除索引缓存
conda clean --tarballs         # 清除下载的 tarball 文件
conda clean --force-pkgs-dirs  # 强制清理包目录
```

**预览清理内容**（不实际删除）：

```bash
conda clean --all --dry-run
```

| 项目 | 说明 |
|---|---|
| Tarball | conda 下载的安装包压缩文件，安装后不再需要 |
| Packages | 已解压但未被任何环境使用的包（如删除环境后的残留） |
| DryRun | 模拟清理，不实际删除 |

> [!warning]
> - `conda clean` 仅清理 `pkgs/` 缓存目录，不影响正在使用的环境，是安全的。
> - **不要手动删除** `pkgs` 文件夹内容，可能破坏硬链接导致环境损坏。

**各系统默认缓存路径**：

| 操作系统 | 缓存路径 |
|---|---|
| Linux / macOS | `~/miniconda3/pkgs/` 或 `~/anaconda3/pkgs/` |
| Windows | `C:\Users\<用户名>\miniconda3\pkgs\` |

## 2.4 优缺点

| 优点 | 缺点 |
|---|---|
| 跨语言环境管理（Python + CUDA + C++ 动态库） | 安装求解慢（SAT 问题） |
| 全环境依赖求解，保证整体兼容 | 不需要 root |
| 不需要 root 权限 | 包数量不如 PyPI 丰富 |
| 多版本环境轻松共存 | 生态不如 pip 大 |
| 科学计算场景几乎不可替代 | |

# 3. mamba

## 3.1 说明

**mamba** 是 conda 的 C++ 重写实现，使用 **libsolv** 作为依赖求解器（与 Zypper/rpm 同款），求解速度比 conda 的 SAT solver 快数倍到数十倍。

核心定位：**conda 的 drop-in 替代**——命令参数完全兼容，只是更快。

| 维度 | conda | mamba |
|---|---|---|
| 语言 | Python | C++ |
| 依赖求解器 | conda SAT solver | libsolv（rpm/Zypper 同款） |
| 求解速度 | 慢（复杂环境可能数分钟） | 快（通常秒级） |
| 并行下载 | 有限 | 原生多线程并行 |
| 命令兼容性 | — | 完全兼容 conda 子命令 |

## 3.2 安装

**方式一**：在已有 conda 环境中安装（推荐）：

```bash
conda install -c conda-forge mamba
```

**方式二**：安装 Miniforge（内置 mamba）：

> [!info]
> 自 Miniforge3 23.3 起，`mamba` 已内置在 Miniforge 中，安装 Miniforge 即自动获得 `mamba` 命令。无需单独安装。

## 3.3 使用

mamba 的子命令与 conda **完全一致**，只需将 `conda` 替换为 `mamba`：

```bash
# 环境管理
mamba create -n myenv python=3.11
mamba activate myenv
mamba env list

# 包安装（求解速度显著提升）
mamba install pytorch
mamba install -c conda-forge numpy=1.26

# 环境导出/导入
mamba env export -n myenv > environment.yml
mamba env create -f environment.yml
```

> [!tip]
> 日常使用中，只需将习惯的 `conda install` 替换为 `mamba install`，其余操作（`activate`、`deactivate`、`env list` 等）仍用 conda 即可。两者共享同一套环境和配置。

**mamba 独有功能**：

```bash
mamba repoquery search <package>    # 快速查询包信息（不下载完整索引）
mamba repoquery depends <package>   # 查看包的依赖树
mamba repoquery whoneeds <package>  # 查看谁依赖了该包
```

`repoquery` 使用本地缓存，响应速度远快于 `conda search`。

## 3.4 优缺点

| 优点 | 缺点 |
|---|---|
| 求解速度比 conda 快数倍到数十倍 | 仍是 conda 生态，包数量不如 PyPI |
| 与 conda 完全兼容，零学习成本 | 额外安装一个工具 |
| 多线程并行下载 | 社区规模小于 conda |
| `repoquery` 快速查询依赖关系 | |

> [!summary]
> mamba 的核心价值就一个字：**快**。安装零门槛，使用零学习成本。如果你受够了 conda install 的漫长等待，直接换 mamba。

# 4. uv

## 4.1 说明

**uv** 是由 Astral（ruff 的开发团队）用 Rust 编写的 Python 包管理器与项目管理工具，定位为 **pip + pip-tools + virtualenv + pyenv 的统一替代**。

| 维度 | pip | uv |
|---|---|---|
| 语言 | Python | Rust |
| 安装速度 | 基准 | 快 10-100 倍 |
| 全局缓存 | 无（每次独立下载） | 有（跨环境共享 wheel 缓存） |
| Python 版本管理 | 无 | 内置（类似 pyenv） |
| 项目管理 | 无（需配合 pip-tools） | 内置（类似 poetry/pdm） |
| 锁文件 | 无 | 自动生成 `uv.lock` |

> [!info]
> uv 与 conda/mamba 是**不同生态**的工具。uv 只管理纯 Python 包和 wheel，不理解 CUDA、动态库等系统级依赖。

## 4.2 安装

**Linux / macOS**：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows**：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**通过 pip 安装**（跨平台）：

```bash
pip install uv
```

**通过 conda 安装**：

```bash
conda install -c conda-forge uv
```

验证安装：

```bash
uv --version
```

## 4.3 使用

### 4.3.1 Python 版本管理

uv 内置 Python 版本管理，可替代 pyenv：

```bash
uv python list                       # 查看可用 Python 版本
uv python install 3.12               # 安装指定版本
uv python install 3.11 3.12 3.13     # 可同时安装多个版本
uv python list --only-installed      # 查看已安装版本
```

### 4.3.2 项目管理

uv 的项目管理模式类似 poetry / pdm，但速度远快于两者。

**初始化项目**：

```bash
uv init my-project
cd my-project

# 项目结构
# my-project/
# ├── .python-version    # Python 版本锁定
# ├── pyproject.toml     # 项目配置与依赖声明
# ├── uv.lock            # 锁文件（自动生成）
# ├── hello.py           # 示例入口
# └── .venv/             # 虚拟环境（自动创建）
```

**依赖管理**：

```bash
uv add requests                # 添加依赖
uv add "numpy>=1.26"           # 添加带版本约束的依赖
uv add --dev pytest            # 添加开发依赖
uv remove requests             # 移除依赖
uv sync                        # 安装项目所有依赖（根据 uv.lock）
uv run python hello.py         # 在项目虚拟环境中运行命令
uv run pytest                  # 运行测试
```

**锁文件**：

`uv.lock` 是 uv 自动生成的确定性锁文件，记录所有依赖的精确版本。**应纳入版本控制**，确保团队成员和 CI 环境使用完全一致的依赖。

### 4.3.3 常用速查

| 操作 | 命令 |
|---|---|
| 创建虚拟环境 | `uv venv` 或 `uv venv --python 3.12` |
| 临时运行脚本（自动创建环境） | `uv run script.py` |
| 一次性执行工具（不安装） | `uvx ruff check .` |
| 从 requirements.txt 安装 | `uv pip install -r requirements.txt` |
| 安装单个包 | `uv pip install <package>` |
| 卸载包 | `uv pip uninstall <package>` |
| 列出已安装包 | `uv pip list` |
| 导出依赖 | `uv pip freeze > requirements.txt` |

> [!tip]
> `uvx` 类似 `npx`，用于一次性运行 Python CLI 工具而不污染环境。例如 `uvx ruff check .` 会临时下载 ruff 并执行。

## 4.4 优缺点

| 优点 | 缺点 |
|---|---|
| 安装速度极快（Rust 编写） | 不理解系统级依赖（CUDA、动态库） |
| 内置 Python 版本管理（替代 pyenv） | 生态较新，社区规模尚小 |
| 内置项目管理（替代 poetry/pdm） | 不适合科学计算 / 深度学习场景 |
| 全局缓存，跨环境共享 wheel | |
| `uv.lock` 保证依赖一致性 | |
| `uvx` 零配置临时执行工具 | |

# 5. 四种包管理器对比与选择

## 5.1 全面对比

| 维度 | pip | conda | mamba | uv |
|---|---|---|---|---|
| 定位 | Python 包安装器 | 跨语言环境管理器 | conda 加速替代 | Python 项目管理器 |
| 实现语言 | Python | Python | C++ | Rust |
| 管理范围 | Python 包 | Python + CUDA + C++ + 动态库 | 同 conda | Python 包 + 项目 |
| 依赖求解 | 逐步解析 | 全环境 SAT 求解 | 全环境 libsolv 求解 | 全局解析 |
| 求解速度 | 快 | 慢 | 快 | 极快 |
| 环境隔离 | 需配合 venv | 内置 | 内置 | 内置 |
| Python 版本管理 | 无 | 有 | 有 | 有（替代 pyenv） |
| 项目管理 | 无 | 无 | 无 | 有（替代 poetry） |
| 锁文件 | 无 | 无 | 无 | `uv.lock` |
| CUDA / 动态库 | 不支持 | 支持 | 支持 | 不支持 |

## 5.2 场景选择

| 场景 | 推荐工具 | 原因 |
|---|---|---|
| 深度学习 / CUDA 项目 | conda / mamba | 需要管理 CUDA runtime、C++ 动态库 |
| 纯 Python Web / 数据分析 | uv | 依赖纯 Python，uv 速度碾压 |
| 需要跨语言系统级依赖 | conda / mamba | conda 能装 ffmpeg、GDAL 等 |
| Python 版本快速切换 | uv | 内置 pyenv 功能，一条命令搞定 |
| 团队协作项目 | uv | `uv.lock` 保证依赖一致性 |
| 脚本临时执行 | uv | `uv run` / `uvx` 零配置 |
| 快速安装 conda 包 | mamba | 求解速度比 conda 快数倍 |

## 5.3 混合使用策略

> [!tip]
> 记忆技巧：**conda/mamba 管地基，pip/uv 管装修**。

| 工具 | 负责管理 | 典型包 |
|---|---|---|
| **conda / mamba** | 基础设施（底层依赖） | python、pytorch、cuda、numpy、scipy、opencv |
| **pip / uv** | 纯 Python 上层库 | hydra、wandb、timm、black、rich |

conda/mamba 与 uv 可以共存：用 conda 创建带 CUDA 的环境，再用 `uv pip install` 安装纯 Python 包。

# 6. 镜像源配置

## 6.1 pip 常用镜像源

| 名称 | URL |
|---|---|
| 清华 | `https://pypi.tuna.tsinghua.edu.cn/simple` |
| 中科大 | `https://pypi.mirrors.ustc.edu.cn/simple` |
| 阿里云 | `http://mirrors.aliyun.com/pypi/simple/` |
| 豆瓣 | `http://pypi.douban.com/simple/` |

## 6.2 conda 镜像源配置

推荐直接编辑 `~/.condarc`（Linux/macOS）或 `C:\Users\<用户名>\.condarc`（Windows），写入以下内容：

```yaml
channels:
  - defaults
show_channel_urls: true
default_channels:
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/r
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/msys2
custom_channels:
  conda-forge: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
  pytorch: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
```

> [!warning]
> - `pkgs/free` 频道已于 2020 年停止维护，不要添加该频道。
> - Windows 用户若无法直接创建 `.condarc` 文件，可先执行 `conda config --set show_channel_urls yes` 生成该文件后再修改。

配置完成后，清除索引缓存使配置生效：

```bash
conda clean -i
```

> [!info]
> Miniforge 默认使用 conda-forge 频道，上述 `custom_channels` 配置会将 conda-forge 请求自动导向清华镜像，无需额外操作。

# 7. 常见问题排查

配置完成后 conda 仍无法正常使用时，按以下步骤逐项排查。

## 7.1 确认 conda 是否在 PATH 中

```bash
# Linux / macOS
which -a conda
# 或者
type -a conda

# Windows PowerShell
where.exe conda
```

若无输出，说明 conda 未加入 PATH。检查：

- `conda init` 是否执行过并重启了终端
- `~/.zshrc`（Linux）或 `$PROFILE`（Windows PowerShell）中是否包含 conda initialize 代码块

## 7.2 检查 .condarc 配置是否生效

```bash
conda config --show-sources
```

该命令会列出所有配置来源及其路径。确认：

- 镜像源 URL 是否正确加载
- 是否存在多个 `.condarc` 文件互相覆盖（常见于系统级与用户级配置并存）

## 7.3 查看详细安装日志

安装失败时使用 `-v` 参数获取详细输出：

```bash
conda install <package> -v        # 详细日志
conda install <package> -vv       # 更详细
conda install <package> -vvv      # 最详细（含 HTTP 请求）
```

重点关注：

- **HTTP 404 / ConnectionError**：镜像源 URL 有误或该频道不存在
- **ResolvePackageNotFound**：指定版本在当前频道不存在，尝试 `conda search <package>` 确认可用版本
- **CollectPackageMetadataError**：索引缓存损坏，执行 `conda clean -i` 后重试

## 7.4 检查网络与代理

```bash
# 测试镜像源连通性
curl -I https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/

# 查看当前代理配置
conda config --show proxy_servers
```

常见情况：

| 现象 | 原因 | 解决 |
|---|---|---|
| 连接超时 | 镜像源不可达或被墙 | 切换镜像源或配置代理 |
| SSL 证书错误 | 代理软件拦截 HTTPS | 配置 `proxy_servers` 或关闭代理的 HTTPS 拦截 |
| 下载极慢 | 未配置镜像源 | 按 6.2 节配置国内镜像 |
| 配了代理仍无法连接 | TUN 模式与手动代理冲突 | 移除 `conda config --remove-key proxy_servers`，让 TUN 模式接管 |

## 7.5 检查环境状态

```bash
conda info                    # 查看 conda 基本信息、安装路径、活跃环境
conda list -n <env_name>      # 查看指定环境已安装的包
conda doctor                  # 检查环境完整性（conda >= 4.11）
```

> [!tip]
> `conda doctor` 会检测环境中缺失的依赖、损坏的包和硬链接问题，是排查环境异常的首选命令。

Conda 会维护一个环境索引文件：

```text
# Linux / macOS
~/.conda/environments.txt

# Windows
C:\Users\sky\.conda\environments.txt
```

里面会记录所有环境路径。手动复制环境、中断创建、多次 `conda create`、使用不同 shell、升级 Miniforge/Conda 等操作都可能导致同一路径被写进去两次。如果遇到环境名重复的情况，可以在这里进行修改。

## 7.6 重置配置

当配置严重混乱时，可重置为默认状态：

```bash
# 备份当前配置
cp ~/.condarc ~/.condarc.bak

# 重置所有 conda 配置
conda config --remove-key channels
conda config --remove-key default_channels
conda config --remove-key custom_channels
conda config --remove-key proxy_servers
```

> [!warning]
> 重置后需重新配置镜像源（见 6.2 节），否则 conda 将使用默认的 repo.anaconda.com 源，国内访问可能极慢。

---

> [!summary]
> 本教程核心要点：
> 1. **pip** = Python 包安装器，最基础但能力有限
> 2. **conda** = 跨语言环境管理器，科学计算场景不可替代
> 3. **mamba** = conda 的加速替代，`conda install` → `mamba install`，零学习成本
> 4. **uv** = 纯 Python 项目的极速管理器，与 conda 互补而非替代
> 5. **conda/mamba 管地基，pip/uv 管装修**——这是最佳工程实践
> 6. **Miniforge 优于 Miniconda**——默认 conda-forge 频道，社区更活跃
> 7. **禁止手动删除 `pkgs/` 目录**——必须使用 `conda clean`
