# 1. 核心原则

Git 的参数体系遵循 **Unix 风格**：同一个短参数在不同命令里含义可能完全不同。

> [!warning]
> 不存在“Git 中 `-u` 永远表示什么”——**一定要结合具体命令理解参数含义**。

| 命令 | 参数 | 含义 |
|---|---|---|
| `git push -u` | **upstream** | 设置跟踪分支 |
| `git add -u` | **update** | 只更新 tracked 文件 |
| `git stash -u` | **untracked** | 包含未跟踪文件 |

学习 Git 参数的正确方式：**按命令分类理解**，而非死记所有参数。

# 2. 高频参数速查表

| 短参数 | 长参数 | 常见含义 | 备注 |
|---|---|---|---|
| `-m` | `--message` | 指定提交信息 | |
| `-a` | `--all` | 全部 | 不同命令范围不同 |
| `-u` | — | upstream / update / untracked | ==视命令而定== |
| `-f` | `--force` | 强制执行 | 危险，慎用 |
| `-d` | `--delete` | 删除 | 仅删已合并分支 |
| `-D` | — | 强制删除 | `--delete --force` 的简写 |
| `-c` | `--create` | 创建并切换 | `switch` 命令 |
| `-p` | `--patch` / `--prune` | 分块选择 / 清理引用 | ==视命令而定== |
| `-r` | `--remote` | 远程 | |
| `-A` | `--all` | 所有变更 | `add` 命令 |
| `-i` | `--interactive` | 交互式 | |
| `-v` | `--verbose` | 详细输出 | |

# 3. 深入理解：`-u` 与 upstream

`-u` 是最容易混淆的参数，本节以 `git push -u` 为例深入讲解 upstream 机制。

## 3.1 什么是 upstream（上游分支）

upstream 是**本地分支与远程分支的跟踪关系**。设置后，Git 知道 `git push` / `git pull` 默认与哪个远程分支同步。

```bash
git push -u origin branch-name
# -u = --set-upstream
# 建立"当前本地分支"与"远程分支"的跟踪关系
```

## 3.2 设置 upstream 的好处

设置后可省略远程名和分支名：

| 操作 | 有 upstream | 无 upstream |
|---|---|---|
| 推送 | `git push` | `git push origin branch-name` |
| 拉取 | `git pull` | `git pull origin branch-name` |

## 3.3 完整示例

```bash
# 1. 创建本地分支
git switch -c exp/hproto-ablation

# 2. 仅推送（不建跟踪）
git push origin exp/hproto-ablation
# → 远程有了分支，但 git status 会提示 "no upstream branch"

# 3. 推送 + 建立跟踪（推荐）
git push -u origin exp/hproto-ablation
# → 以后直接 git push / git pull 即可
```

## 3.4 查看与修改 upstream

```bash
# 查看所有分支的 upstream 及 ahead/behind 状态
git branch -vv
# 输出示例：* main abc123 [origin/main] 说明 upstream 是 origin/main

# 手动设置 upstream
git branch -u origin/main

# 取消 upstream
git branch --unset-upstream
```

## 3.5 upstream 的本质

设置 upstream 后，Git 会在 `.git/config` 中写入：

```ini
[branch "main"]
    remote = origin
    merge = refs/heads/main
```

执行 `git pull` 时，Git 就知道从 `origin/main` 拉取。

## 3.6 重命名分支后的常见问题

重命名分支后如果只 `git push origin new-name` 而不加 `-u`，upstream 仍指向旧分支。解决方法：

```bash
git branch -m old-name new-name    # 重命名
git push -u origin new-name        # 推送并更新跟踪
```

# 4. 按命令分类详解

## 4.1 `git add`

作用：工作区 → 暂存区（index）

| 参数 | 含义 | 范围 |
|---|---|---|
| `git add .` | 添加当前目录及子目录的所有变更 | modified + deleted + new |
| `git add -A` | 添加整个仓库的所有变更 | modified + deleted + new |
| `git add -u` | 只更新已跟踪文件的变更 | modified + deleted，**不含 new** |
| `git add -p` | 交互式分块选择提交 | 逐 hunk 选择 |

> [!tip]
> `git add .` 与 `git add -A` 的区别：`.` 只作用于当前目录，`-A` 作用于整个仓库。在仓库根目录下两者等价。

> [!warning]
> `git add -u` 中的 `-u` = **update**，与 `git push -u` 的含义完全不同。

`git add -p`（patch 模式）可在一个文件中只 add 部分修改，适合将 bug fix 和 refactor 分开提交。

## 4.2 `git commit`

作用：暂存区 → commit history

| 参数 | 含义 | 说明 |
|---|---|---|
| `-m "msg"` | 直接指定 commit message | |
| `-a` | 自动 add 所有 tracked 文件 | 相当于 `git add -u` + `git commit`，**不含新文件** |
| `--amend` | 修改最近一次 commit | 可改 message、补文件 |

## 4.3 `git push`

作用：本地 → 远程

| 参数 | 含义 | 说明 |
|---|---|---|
| `-u` | `--set-upstream` | 建立跟踪关系（见第 3 节） |
| `-f` | `--force` | 强制覆盖远程历史，==危险== |
| `--force-with-lease` | 安全版 force push | 会检查远程是否被别人更新，推荐替代 `-f` |

> [!danger]
> `git push -f` 会覆盖远程历史，可能导致他人工作丢失。除非确定需要，否则始终使用 `--force-with-lease`。

## 4.4 `git pull`

本质：`git fetch` + `git merge`

| 参数 | 含义 | 说明 |
|---|---|---|
| `--rebase` | 用 rebase 替代 merge | 避免产生 merge commit，保持线性历史 |

> [!tip]
> 科研项目推荐使用 `git pull --rebase`，避免 merge commit 污染历史。可设为默认行为：
> ```bash
> git config --global pull.rebase true
> ```

## 4.5 `git fetch`

只同步远程信息，**不修改工作区**，安全操作。

| 参数 | 含义 |
|---|---|
| `--all` | 拉取所有 remote |
| `-p` | `--prune`，清理已删除的远程分支引用 |

远程删除了 `origin/old-branch` 后，本地 `git branch -r` 仍会显示。执行 `git fetch -p` 可清理。

## 4.6 `git branch`

| 参数 | 含义 | 说明 |
|---|---|---|
| `-a` | 显示所有分支 | 本地 + 远程 |
| `-r` | 只显示远程分支 | |
| `-d` | 删除已合并的分支 | |
| `-D` | 强制删除分支 | |
| `-m old new` | 重命名分支 | `--move` |
| `-vv` | 显示 upstream、ahead/behind、commit | 非常实用 |

## 4.7 `git switch`

切换分支的现代写法（替代 `git checkout` 的分支功能）。

| 参数 | 含义 |
|---|---|
| `-c` | 创建并切换到新分支 |

```bash
git switch -c exp/new-feature
```

## 4.8 `git stash`

临时保存工作区修改。

| 参数 | 含义 | 包含范围 |
|---|---|---|
| （无参数） | 保存 tracked 文件的修改 | modified + staged |
| `-u` | `--include-untracked` | 上述 + untracked 文件 |
| `-a` | `--all` | 上述 + ignored 文件 |

## 4.9 `git log`

| 参数 | 含义 |
|---|---|
| `--oneline` | 简洁单行显示 |
| `--graph` | 显示 commit 树结构 |
| `--all` | 显示所有分支历史 |

常用组合（强烈推荐）：

```bash
git log --oneline --graph --all
```

## 4.10 `git diff`

| 用法 | 比较对象 |
|---|---|
| `git diff` | 工作区 vs 暂存区 |
| `git diff --staged` | 暂存区 vs HEAD |
| `git diff branch1..branch2` | 两个分支之间 |

## 4.11 `git reset`

移动 HEAD 和暂存区的位置。

| 参数 | HEAD | 暂存区 | 工作区 | 安全性 |
|---|---|---|---|---|
| `--soft` | 移动 | 保留 | 保留 | 安全 |
| `--mixed`（默认） | 移动 | 重置 | 保留 | 安全 |
| `--hard` | 移动 | 重置 | ==丢弃== | 危险 |

> [!danger]
> `git reset --hard` 会丢弃工作区所有未提交的修改，不可恢复。

## 4.12 `git restore`

现代恢复命令（替代 `git checkout --` 的恢复功能）。

| 用法 | 作用 |
|---|---|
| `git restore .` | 恢复工作区（丢弃未暂存的修改） |
| `git restore --staged .` | 取消暂存（从暂存区移回工作区） |

## 4.13 `git rebase`

重写提交历史。

| 参数 | 含义 |
|---|---|
| `-i` | `--interactive`，交互式 rebase |

交互式 rebase 可用于：
- 修改 commit message
- 合并（squash）多个 commit
- 删除 commit
- 调整 commit 顺序

```bash
git rebase -i HEAD~10  # 整理最近 10 个 commit
```

> [!warning]
> 已推送到远程的 commit 不要 rebase，会导致他人历史冲突。

# 5. 科研项目推荐工作流

| 场景 | 命令 |
|---|---|
| 查看实验历史 | `git log --oneline --graph --all` |
| 创建实验分支 | `git switch -c exp/hproto-ablation` |
| 推送并建立跟踪 | `git push -u origin exp/hproto-ablation` |
| 临时保存实验 | `git stash -u` |
| 查看跟踪状态 | `git branch -vv` |
| 整理 commit 历史 | `git rebase -i HEAD~10` |

> [!summary]
> 本节核心：Git 参数必须结合命令理解。`-u` 在 `push` 中是 upstream，在 `add` 中是 update，在 `stash` 中是 untracked。设置 upstream 后可简化日常 push/pull 操作，是高效使用 Git 的基础。
