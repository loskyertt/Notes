# 1. SSH 连接

**SSH**（Secure Shell）是 Git 与 GitHub 通信的推荐认证方式，相比 HTTPS + Token 方式更安全、更便捷，配置一次后无需重复输入凭证。

> [!tip]
> SSH 连接的核心流程：**生成密钥对 → 添加公钥到 GitHub → 验证连接 → 配置仓库使用 SSH URL**

## 1.1 前置条件

安装 **OpenSSH**：

```bash
# Arch Linux
sudo pacman -S openssh

# Ubuntu / Debian
sudo apt install openssh-client

# macOS（通常已预装）
brew install openssh
```

## 1.2 生成 SSH 密钥

| 算法 | 命令 | 特点 |
|---|---|---|
| **Ed25519**（推荐） | `ssh-keygen -t ed25519 -C "email"` | 更安全、密钥更短、性能更好 |
| RSA | `ssh-keygen -t rsa -b 4096 -C "email"` | 兼容性更广、密钥较长 |

推荐使用 **Ed25519**：

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

按照提示完成生成，默认在 `~/.ssh/` 目录下生成：

| 文件 | 说明 | 保密性 |
|---|---|---|
| `id_ed25519` | **私钥** | 绝对不能泄露 |
| `id_ed25519.pub` | **公钥** | 可以公开 |

> [!warning]
> 私钥等同于身份凭证，**绝不能分享给任何人**。如果私钥泄露，需立即删除并重新生成密钥对。

## 1.3 添加 SSH 公钥到 GitHub

1. 查看公钥内容：

```bash
cat ~/.ssh/id_ed25519.pub
```

输出示例：

```
ssh-ed25519 AAAAC3NzANDAKlZDI1NTE5AAAaaaN/oaWb4GZetVkiI5/8d1gezLHWpT46mnaAnkJAbwXpp loskyertt0403@gmail.com
```

2. 复制完整输出（从 `ssh-ed25519` 开始到邮箱结束）
3. 登录 GitHub → **Settings** → [SSH and GPG keys](https://github.com/settings/keys) → **New SSH key**
4. 粘贴公钥并保存

## 1.4 验证 SSH 连接

```bash
ssh -T git@github.com
```

成功时输出：

```
Hi <username>! You've successfully authenticated, but GitHub does not provide shell access.
```

添加 `-v` 参数可查看详细连接信息，用于排查问题：

```bash
ssh -T -v git@github.com
```

## 1.5 配置仓库使用 SSH URL

将远程仓库 URL 从 HTTPS 切换为 SSH：

```bash
git remote set-url origin git@github.com:<username>/<repo>.git
```

示例：

```bash
git remote set-url origin git@github.com:loskyertt/Recorder_Backup.git
```

验证修改结果：

```bash
git remote -v
```

## 1.6 常见问题

### 1.6.1 SSH 连接超时或无响应

**原因**：`~/.ssh/config` 配置文件损坏或不存在。

**解决**：创建或编辑配置文件：

```bash
nano ~/.ssh/config
```

添加以下内容：

```txt
Host github.com
  HostName ssh.github.com
  Port 22
  User git
```

> [!tip]
> 如果端口 `22` 连接缓慢，可改为 `443` 端口。GitHub 同时监听这两个端口以应对防火墙限制。

### 1.6.2 Git for Windows 使用系统 OpenSSH

Git for Windows 自带的 SSH 可能与系统 OpenSSH 冲突，需要手动指定。

1. 确认系统 OpenSSH 路径：

```powershell
Get-Command ssh
```

输出示例：

```
CommandType     Name            Version    Source
-----------     ----            -------    ------
Application     ssh.exe         10.0.0.0   C:\Program Files\OpenSSH\ssh.exe
```

2. 配置 Git 使用系统 SSH：

```bash
git config --global core.sshCommand "C:/PROGRA~1/OpenSSH/ssh.exe"
```

> [!info]
> `PROGRA~1` 是 `Program Files` 的 DOS 短名，用于避免路径中的空格问题。

# 2. 个人访问令牌（PAT）

**Personal Access Token**（PAT）是 GitHub 提供的替代密码认证方式，主要用于：

- 临时快速访问私有仓库
- SSH 连接不可用时的备选方案
- CI/CD 自动化场景

> [!summary]
> SSH vs PAT 对比

| 特性 | SSH | PAT |
|---|---|---|
| 安全性 | 高（非对称加密） | 中（令牌可能泄露） |
| 便捷性 | 配置一次，长期使用 | 需定期更换令牌 |
| 适用场景 | 日常开发 | 临时访问 / 自动化 |
| 认证方式 | 密钥对 | HTTPS + 令牌 |

## 2.1 生成个人访问令牌

1. 登录 GitHub → [Personal Access Tokens 设置页面](https://github.com/settings/tokens)
2. 点击 **Generate new token** → 选择 **Generate new token (classic)**
3. 填写令牌名称，选择权限范围（至少勾选 `repo` 权限以访问私有仓库）
4. 生成并**立即复制保存**

> [!warning]
> 令牌**仅显示一次**，关闭页面后无法再次查看。务必妥善保存。

## 2.2 使用令牌认证

当 Git 通过 HTTPS 操作提示输入密码时，**使用令牌代替密码**：

```bash
git push origin main
# Username: your_username
# Password: ghp_xxxxxxxxxxxx  ← 粘贴令牌
```

## 2.3 存储凭证

避免每次输入令牌，配置凭证存储：

```bash
git config --global credential.helper store
```

下次输入令牌后，Git 会自动记住凭证。

> [!warning]
> `store` 模式将凭证以**明文**保存在 `~/.git-credentials` 文件中。如需更高安全性，可使用 `cache` 模式（仅在内存中缓存，默认 15 分钟）：

```bash
git config --global credential.helper cache --timeout=3600
```

## 2.4 切换为 HTTPS 远程 URL

当 SSH 不可用时，可临时切换为 HTTPS：

```bash
git remote set-url origin https://github.com/<username>/<repo>.git
```

## 2.5 令牌安全管理

- 令牌与密码具有**同等权限**，必须像密码一样保护
- 如怀疑令牌泄露，立即在 GitHub 设置中**撤销**并重新生成
- 为不同用途创建不同令牌，按需分配最小权限
- 定期轮换令牌，设置合理的过期时间
