> [!note] 重点
> 整数化处理技巧。应避免使用浮点数表示，因为在计算机中转换成二进制后，容易丢失精度。

# 1. 题目

众所周知，在一些消费支付的场合中，往往有“支付宝九五折”的优惠。

这天小苹来到了超市购买物品，一共有 $n$ 种物品，每种物品只能购买一个，但有的物品支持优惠活动，有的并不支持。恰好本超市的结账是有“支付宝九五折”优惠的，小苹的支付宝余额还剩 $k$ 元，他想知道他仅使用支付宝进行支付的话，最多能买几件物品？

- **输入描述**：
  - 输入包含三行。
  - 第一行两个正整数 $n, k$（$1 \leq n \leq 10^5$, $1 \leq k \leq 10^9$）。
  - 第二行包含 $n$ 个正整数 $a_i$（$1 \leq a_i \leq 10^4$）表示每个物品的价格。
  - 第三行一个长度为 $n$ 的只含有 0 和 1 的**字符串**，表示每个物品是否支持优惠。（如果是 1 代表第 $i$ 个物品支持优惠，否则不支持。）

- **输出描述**：输出一行一个整数表示答案。

示例1

```
输入：5 9
3 4 2 3 1
11101

输出：4
```

> **说明**：选择买第 1，3，4，5 个物品。

---

# 2. 题解

本题本质上是一个**有限制条件的背包问题**，但由于题目只要求“最多能买几件”，且每种物品只有一个，其实可以简化为**贪心算法**问题。

## 2.1 贪心策略的选择

要想购买的物品数量最多，在预算有限的情况下，应当优先购买价格最低的物品。这是贪心算法的经典应用场景。

因此，解题步骤如下：
1. 计算每个物品的实际支付价格。
2. 将所有物品按实际价格从小到大排序。
3. 遍历排序后的物品，依次尝试购买，直到余额不足为止。

## 2.2 核心难点：浮点数精度问题

本题最大的陷阱在于“九五折”的处理。初学者容易想到直接使用浮点数进行计算：

```cpp
double price = a[i] * 0.95;  // a 是存放商品价格的容器
```

然而，这种方法存在严重的精度隐患。计算机中的浮点数（`float`/`double`）采用二进制存储，无法精确表示某些十进制小数。

- **精度丢失示例**：
  - `0.95` 在二进制中是一个无限循环小数。
  - 当计算 `a[i] * 0.95` 时，结果可能是一个近似值。例如，某个物品原价 2 元，打折后应为 1.9 元，但计算机内部存储的可能是一个极其接近 1.9 的值，如 `1.899999999999`。
- **判断失误**：
  - 若余额 `k` 为 1.9，判定条件 `if (k >= price)` 可能会因为 `1.9 < 1.89999...`（极端情况下的精度误差累积）或者 `k` 本身也存在存储误差，导致错误地判定为余额不足。

> **结论**：在算法竞赛或涉及金额计算的场景中，应尽量避免使用浮点数，改用整数运算。

---

# 3. 解题方案

## 3.1 整数化处理技巧

为了规避浮点数误差，可以采用**扩大倍数**的方法，将所有运算转移到整数域。

题目中的“九五折”等价于 $\text{实际价格} = \text{原价} \times 0.95 = \text{原价} \times \frac{95}{100} = \text{原价} \times \frac{19}{20}$。

我们可以将所有的价格和余额统一乘以 20：
- **支持优惠的物品**：实际花费 = `原价 * 19`。
- **不支持优惠的物品**：实际花费 = `原价 * 20`（相当于原价，乘以 20 是为了**统一量纲**）。
- **初始余额**：可用金额 = `k * 20`。

这样，所有的计算都变成了整数乘法，完全消除了精度误差。

## 3.2 数据范围与类型选择

题目给定：
- $k \le 10^9$
- $a_i \le 10^4$

处理后的数据范围：
- 余额 `total_k = k * 20`，最大值可达 $2 \times 10^{10}$。
- 单个物品价格最大值为 $10^4 \times 20 = 2 \times 10^5$。
- 累加总和可能在 `long long` 范围内。

C++ 中 `int` 类型的最大值约为 $2.1 \times 10^9$，显然无法容纳处理后的余额，因此必须使用 `long long` 类型存储余额和计算后的价格。

## 3.3 完整代码实现

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

void solve() {
  int n;
  long long k; // 使用 long long 存储余额
  if (!(std::cin >> n >> k))
    return;

  std::vector<long long> prices(n);
  for (int i = 0; i < n; ++i) {
    std::cin >> prices[i];
  }

  std::string s;
  std::cin >> s; // 直接读取整行字符串，如 "11101"

  std::vector<long long> final_prices(n);
  for (int i = 0; i < n; ++i) {
    if (s[i] == '1') {
      // 支持优惠：原价 * 19 (对应 0.95)
      // 注意：prices[i] 是 int 范围，乘以 19 后仍在 int 范围内，
      // 但存入 vector<long long> 会自动转换
      final_prices[i] = prices[i] * 19;
    } else {
      // 不支持优惠：原价 * 20 (对应 1.00)
      final_prices[i] = prices[i] * 20;
    }
  }

  // 余额同步放大 20 倍
  long long total_k = k * 20;

  // 贪心策略：从小到大排序
  std::sort(final_prices.begin(), final_prices.end());

  int count = 0;
  for (int i = 0; i < n; ++i) {
    if (total_k >= final_prices[i]) {
      total_k -= final_prices[i];
      count++;
    } else {
      break; // 排序后，当前买不起，后续更贵，直接结束循环
    }
  }

  std::cout << count << std::endl;
}

int main() {
  // 加速输入输出
  std::ios::sync_with_stdio(false);
  std::cin.tie(nullptr);
  
  solve();
  return 0;
}
```

# 4. 输入处理细节

题目描述第三行输入为一个“长度为 $n$ 的只含有 0 和 1 的字符串”。在代码实现中，使用 `std::string` 配合 `std::cin` 是最标准的处理方式。

**正确方式**：
```cpp
std::string s;
std::cin >> s; // 自动读取直到遇到空白符（换行或空格）
// s[0] 对应第一个物品的状态
```

**错误方式**：
尝试使用循环读取整数 `int x; cin >> x;` 来读取连续的数字字符（如 `11101`），除非格式中有空格分隔，否则会导致读取失败或逻辑错误。

# 5. 总结

本题考察了以下知识点：
1.  **贪心算法**：求解“数量最多”类问题时，优先考虑代价最小的元素。
2.  **精度处理**：将小数运算转化为整数运算，通过扩大倍数消除浮点误差，这是竞赛中处理折扣、概率问题的常用技巧。
3.  **数据类型**：当计算结果可能超过 $2 \times 10^9$ 时，必须使用 `long long` 防止溢出。
4.  **输入技巧**：对于连续的数字字符串，应作为字符串读入而非整数。
