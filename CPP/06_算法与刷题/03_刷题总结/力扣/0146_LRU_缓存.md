# 1. 题目

请你设计并实现一个满足 **LRU (最近最少使用) 缓存** 约束的数据结构。

实现 `LRUCache` 类：

- `LRUCache(int capacity)` 以 **正整数** 作为容量 `capacity` 初始化 LRU 缓存
- `int get(int key)` 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1`。
- `void put(int key, int value)` 如果关键字 `key` 已经存在，则变更其数据值 `value`；如果不存在，则向缓存中插入该组 `key-value`。如果插入操作导致关键字数量超过 `capacity`，则应该 **逐出** 最久未使用的关键字。

函数 `get` 和 `put` 必须以 $O(1)$ 的平均时间复杂度运行。

- **输入描述**：
  - 构造函数传入正整数 `capacity`（$1 \leq \text{capacity} \leq 3000$）
  - `get` 操作传入整数 `key`（$0 \leq \text{key} \leq 10000$）
  - `put` 操作传入整数 `key` 和 `value`（$0 \leq \text{value} \leq 10^5$）
  - 最多调用 $2 \times 10^5$ 次 `get` 和 `put`

- **输出描述**：根据操作序列返回对应结果数组，包含 `null`、整数值或 `-1`

示例

```
输入
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]

输出
[null, null, null, 1, null, -1, null, -1, 3, 4]
```

> **解释**：
> ```java
> LRUCache lRUCache = new LRUCache(2);
> lRUCache.put(1, 1); // 缓存是 {1=1}
> lRUCache.put(2, 2); // 缓存是 {1=1, 2=2}
> lRUCache.get(1);    // 返回 1
> lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3}
> lRUCache.get(2);    // 返回 -1 (未找到)
> lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3}
> lRUCache.get(1);    // 返回 -1 (未找到)
> lRUCache.get(3);    // 返回 3
> lRUCache.get(4);    // 返回 4
> ```

> **提示**：
> - $1 \leq \text{capacity} \leq 3000$
> - $0 \leq \text{key} \leq 10000$
> - $0 \leq \text{value} \leq 10^5$
> - 最多调用 $2 \times 10^5$ 次 `get` 和 `put`

# 2. 题解

## 2.1 题意详解

> [!note] LRU 的全称是 Least Recently Used，即“**最近最少使用**”。
> 假设你的书桌（缓存）空间有限，只能放下 **2** 本书。
> - 规则：如果书桌满了，你想放新书进去，就必须把**最久没看过**的那本书扔掉，给新书腾位置。
> - 目的：这是一种策略，假设“最近一直在用的书，未来大概率还会用；很久没碰过的书，未来可能也不用了”。

题目要求我们设计一个类 `LRUCache`，有以下几个功能：

- **初始化 (`LRUCache(int capacity)`)**：
	- 设定这个收纳盒的最大容量。比如设为 2，表示最多只能存 2 个数据。

- **获取数据 (`get(int key)`)**：
    - 当拿 Key 为 1 的数据时：
    - **情况A（有）**：缓存列表里有这个数据。它会把这个数据给你，并且**把这个数据标记为“最新用过”**（因为它刚被你碰过）。
    - **情况B（无）**：缓存列表里没这个数据，返回 -1。

- **存入数据 (`put(int key, int value)`)**：
    - 你往缓存列表里放一个数据。
    - **情况A（更新）**：如果 Key 已经存在，就更新它的 Value，并标记为“最新用过”。
    - **情况B（新增）**：如果 Key 不存在，就插入新数据。
        - 如果此时缓存列表**没满**：直接插入，标记为“最新用过”。
        - 如果此时缓存列表**满了**：先找到那个“**最久没碰过**”的数据扔掉，然后再插入新数据。

接下来，我们走一遍题目里的示例（假设容量 Capacity = 2）：

1. `put(1, 1)`：放入数据(1, 1)。当前缓存：`[(1, 1)]`
2. `put(2, 2)`：放入数据(2, 2)。当前缓存：`[(1, 1), (2, 2)]` （满了）
3. `get(1)`：获取 Key=1 的数据。
    - 返回 1。
    - **关键点**：Key=1 被访问了，它变成了“最新”的。Key=2 变成了“最久未用”的。
    - 当前缓存逻辑顺序（新->旧）：`[(1, 1), (2, 2)]`
4. `put(3, 3)`：放入数据(3, 3)。
    - 缓存满了，需要淘汰“最久未用”的数据（即 Key=2）。
    - Key=2 被扔掉，Key=3 被放入。
    - 当前缓存：`[(1, 1), (3, 3)]`
5. `get(2)`：获取 Key=2。
    - Key=2 已经被扔掉了，返回 **-1**。
6. `put(4, 4)`：放入数据(4, 4)。
    - 缓存满了，淘汰“最久未用”的数据。此时 Key=1 是最旧的（因为刚才**步骤3**用过它，但**步骤5**没找到 2，所以 1 相对较旧）。
    - Key=1 被扔掉，Key=4 被放入。
    - 当前缓存：`[(4, 4), (3, 3)]`
7. `get(1)`：返回 **-1**（刚才被扔了）。
8. `get(3)`：返回 3。
9. `get(4)`：返回 4。

## 2.2 解题思路

题目要求时间复杂度为 **O(1)**。这是解题的关键限制。

### 2.2.1 数据结构的选择

- **查找快 (O(1))**：立马想到 **哈希表**。我们可以用 `key` 作为哈希表的键，这样 `get` 和 `put` 的查找都是 O(1)。
- **维护顺序 + 删除/插入快 (O(1))**：
    - 我们需要时刻知道谁是最旧的，谁是新的。数组删除中间元素是 O(N)，不行。
    - 链表删除节点是 O(1)，但前提是你得先找到那个节点。如果是单链表，找到前驱节点需要 O(N)。
    - **双向链表**：每个节点存有前驱 和后继 指针。如果我们已经持有了某个节点，删除它只需要修改前后指针，时间是 O(1)。

**结论**：哈希表（`std::unordered_map`） + 双向链表（`std::list`）

### 2.2.2 设计逻辑

我们需要维护一个双向链表，**链表头部代表“最近使用”，尾部代表“最久未使用”**。

- **哈希表的作用**：`Map<Integer, Node>`。Key 是缓存的键，Value 是链表中的节点对象。这样我们可以通过 Key 在 O(1) 内直接找到链表中的对应节点。
- **双向链表的作用**：维护访问顺序。

**操作细节：**

1. **`get(key)`**：
    - 先去哈希表查。
    - 如果没查到，返回 -1。
    - 如果查到了（节点 `node`）：
        1. 把这个 `node` 从链表当前位置**删除**（O(1)）。
        2. 把这个 `node` 插入到链表**头部**（O(1)），代表“刚用过”。
        3. 返回 `node` 的值。

2. **`put(key, value)`**：
    - 先调用类似 `get` 的逻辑看 `key` 是否存在。
    - **如果存在**：更新节点的值，并把节点移到链表头部。
    - **如果不存在**：
        1. 创建新节点 `newNode`。
        2. 写入哈希表。
        3. 插入链表头部。
        4. **检查容量**：如果当前元素个数 > 容量：
            - 删除链表**尾部**的节点（最久未用）。
            - 同时在哈希表中删除对应的映射。

## 2.3 代码实现

```cpp
#include <iostream>
#include <list>
#include <unordered_map>
#include <utility>

class LRUCache {
 private:
  int m_capacity;  // 最大容量

  // 双向链表：存储 [key，value}
  // 规定：front(）是最近使用的，back(）是最久未使用的
  std::list<std::pair<int, int>> m_cache_list;

  // key 映射到 list 中的迭代器（节点位置）
  std::unordered_map<int, std::list<std::pair<int, int>>::iterator> m_cache_map;

 public:
  LRUCache(int capacity) : m_capacity(capacity) {}

  /* 根据 key 获取 value */
  int get(int key) {
    auto it = m_cache_map.find(key);

    // 如果没有找到就返回 -1
    if (it == m_cache_map.end()) {
      return -1;
    }

    int val = it->second->second;  // 先取出 list 迭代器（节点），再取出节点里的 value

    // splice 函数：将 m_cache_list 中 it->second 指向的节点，移动到 cache_list 的 begin(） 位置
    // 这是一个 O(1) 的操作，只是改变指针指向
    m_cache_list.splice(m_cache_list.begin(), m_cache_list, it->second);

    return val;
  }

  /* 存放或更新 {key, value} */
  void put(int key, int value) {
    auto it = m_cache_map.find(key);

    // --- Key 已存在：更新 value 并移到头部 ---
    if (it != m_cache_map.end()) {
      // key 已经存在，那就更新对应 key 的 value
      it->second->second = value;

      // 移动到头部
      m_cache_list.splice(m_cache_list.begin(), m_cache_list, it->second);

      return;
    }

    // --- Key 不存在：插入新节点 ---

    // 如果 cache 已满
    if (m_cache_list.size() == m_capacity) {
      int old_key = m_cache_list.back().first;  // 获取 cache 中的 key
      m_cache_map.erase(old_key);               // 从 map 中擦除
      m_cache_list.pop_back();                  // 从 list 中删除尾部
    }

    m_cache_list.push_front({key, value});    // 插入新节点到头部
    m_cache_map[key] = m_cache_list.begin();  // 在 map 中记录
  }
};
```

> [!tip] 重点知识讲解：为什么用 `splice`？

在 C++ 中，`std::list` 有一个非常有用的函数 `splice`。它的作用是将一个链表中的节点“剪切”下来，拼接到另一个位置（或者是同一个链表的其他位置）。

```cpp
// 将 it->second 指向的节点，移动到 cache_list.begin() 的位置
cache_list.splice(cache_list.begin(), cache_list, it->second);
```

- **时间复杂度**：O(1)。因为它只修改了前后节点的指针，没有发生数据的拷贝或移动。
- **迭代器有效性**：`splice` 之后，指向被移动节点的迭代器依然有效。这正是我们敢在 `unordered_map` 中存储迭代器的原因。如果使用 `vector` 或 `deque`，移动元素会导致内存地址变化，迭代器失效，那就无法实现 O(1) 了。
