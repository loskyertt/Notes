> 渲染管线就是 **"把 3D 数据变成屏幕上 2D 像素"** 的流水线。你可以把它想象成一条工厂流水线，每个阶段加工数据，最终输出画面。

# 1. 基础知识

> VAO / VBO / EBO 这三个对象是 OpenGL 管理显存数据的核心，必须理解。

## 1.1 VBO

> Vertex Buffer Object，顶点缓冲对象。

- 本质：GPU 显存里的一块**原始数据区域**
- 作用：把 CPU 的 `float[]` 顶点数据上传到显存

```cpp
unsigned int VBO;
glGenBuffers(1, &VBO);
glBindBuffer(GL_ARRAY_BUFFER, VBO);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
```

### 1.1.1 详细说明（补充）

> OpenGL 有一套独特的"状态机"设计思路，下面我们逐行拆解这几行代码。

首先需要理解 OpenGL 的核心设计：状态机

OpenGL 里有一个概念叫 **"当前绑定对象"**。你可以把它想象成一个 **工作台**，同一时间工作台上只能放一个东西，你对工作台的操作都作用于当前放上去的那个东西。
```
工作台（GL_ARRAY_BUFFER）
┌─────────────────────┐
│   当前绑定的 VBO    │  ← 所有操作都作用于这里
└─────────────────────┘
```

理解了这个，下面四行就清晰了。

1. 第一行：`unsigned int VBO;`

```cpp
unsigned int VBO;
```

这只是在 **CPU 侧**声明了一个普通整数变量。

OpenGL 用整数 ID 来引用 GPU 上的资源，就像文件系统用文件描述符（fd）引用文件一样。此时 VBO 还只是个未初始化的数字，GPU 上什么都还没创建。

2. 第二行：`glGenBuffers(1, &VBO);`

```cpp
glGenBuffers(1, &VBO);
//           ↑   ↑
//     创建1个  把生成的 ID 写入 VBO 变量
```

这一行才真正让 **GPU 分配了一块缓冲区**，并把它的 ID（比如 `1`）写回到 `VBO` 变量里。

之后 `VBO` 的值就是一个数字 ID，比如 `VBO = 1`，你可以通过这个 ID 来引用 GPU 上那块内存。

```
执行前：VBO = ???（未初始化）
执行后：VBO = 1  （GPU 上有了一块对应的缓冲区）
```

3. 第三行：`glBindBuffer(GL_ARRAY_BUFFER, VBO);`

```cpp
glBindBuffer(GL_ARRAY_BUFFER, VBO);
//           ↑                ↑
//     绑定到哪个工作台      把哪个缓冲区放上去
```

这一行把 VBO 放到 **工作台** 上，也就是"激活"它，让它成为当前操作对象。

`GL_ARRAY_BUFFER` 是工作台的名字，专门用来放顶点数据。

```
工作台（GL_ARRAY_BUFFER）
┌─────────────────────┐
│       VBO (id=1)    │  ← 现在它在这里了
└─────────────────────┘
```

4. 第四行：`glBufferData(...)`

```cpp
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
//           ↑                ↑                 ↑          ↑
//        往哪个工作台写    数据有多少字节     数据在哪里   使用方式提示
```

这一行把 CPU 里的 `vertices` 数组 **真正上传到 GPU 显存** 里。

- `GL_ARRAY_BUFFER`：操作当前工作台上的那个缓冲区（也就是刚才绑定的 VBO）
- `sizeof(vertices)`：告诉 OpenGL 要上传多少字节
- `vertices`：数据的来源（你的 float 数组指针）
- `GL_STATIC_DRAW`：提示 GPU"这个数据不会经常改变"，让驱动做优化

```
CPU 内存               GPU 显存
┌────────────┐        ┌────────────┐
│ vertices[] │ ──→    │    VBO     │
│-0.5,-0.5.. │  上传  │-0.5,-0.5...│
└────────────┘        └────────────┘
```

### 1.1.2 绑定与解绑

OpenGL **没有单独的"解绑"函数**，绑定和解绑用的是同一个函数 `glBindBuffer`，区别只在于传入的 ID：

```cpp
glBindBuffer(GL_ARRAY_BUFFER, VBOs[1]);  // 绑定：把 VBOs[1] 放上工作台
glBindBuffer(GL_ARRAY_BUFFER, 0);        // 解绑：把"空"放上工作台 = 清空工作台
```

**0 是 OpenGL 的特殊保留 ID，表示"空/无"**。传 0 就是把"没有任何东西"设为当前活跃对象，效果就是解绑。

所有 Bind 函数都遵循这个约定：

```cpp
glBindVertexArray(0);      // 解绑 VAO
glBindBuffer(..., 0);      // 解绑 Buffer
glBindTexture(..., 0);     // 解绑纹理
glUseProgram(0);           // 解绑着色器程序
```

类比理解：

```cpp
int* ptr = &someObject;  // 指向某个对象
ptr = nullptr;           // 指向"空" = 相当于解绑
// 用的是同一个赋值操作符 =，只是传入的值不同
```

### 1.1.3 多个 VBO 的解绑

> 多个 VBO 时只需解绑最后一个。

工作台同一时刻只能放一个对象，**绑定新的会自动顶走旧的**，因此不需要逐个显式解绑：

```cpp
glBindBuffer(GL_ARRAY_BUFFER, VBOs[0]);  // VBOs[0] 上台
// ...
glBindBuffer(GL_ARRAY_BUFFER, VBOs[1]);  // VBOs[1] 上台，VBOs[0] 自动离开
// ...
glBindBuffer(GL_ARRAY_BUFFER, 0);        // 清空工作台，只需解绑当前的 VBOs[1]
```

VAO 同理：

```cpp
glBindVertexArray(VAOs[0]);  // VAOs[0] 上台
glBindVertexArray(VAOs[1]);  // VAOs[1] 上台，VAOs[0] 自动离开
glBindVertexArray(0);        // 只需解绑当前的 VAOs[1]
```

### 1.1.4 显卡的数据管理

除了有 `GL_STATIC_DRAW`，还有 `GL_DYNAMIC_DRAW` 和 `GL_STREAM_DRAW`，这三个参数都是给 GPU 驱动的 **"使用提示"**，帮助驱动决定把数据放在哪块显存里以便优化性能。

每个名字由两部分组成：

|部分|含义|
|---|---|
|**STATIC**|数据上传一次，几乎不再改变|
|**DYNAMIC**|数据会被反复修改|
|**STREAM**|数据几乎每帧都完全替换|
|**DRAW**|数据从 CPU → GPU（程序员写，GPU 读）|

> 除了 `DRAW` 还有 `READ`（GPU写 → CPU读）和 `COPY`（GPU内部），但实际开发中 `DRAW` 系列用得最多。

三者对比：

||`GL_STATIC_DRAW`|`GL_DYNAMIC_DRAW`|`GL_STREAM_DRAW`|
|---|---|---|---|
|**更新频率**|一次或极少|偶尔（不规律）|几乎每帧|
|**驱动的优化策略**|放在最快的显存区域，不预留修改开销|放在易于更新的区域|放在专为频繁替换优化的区域|
|**典型场景**|静态地形、建筑|角色动画、可变形物体|粒子系统、实时生成的几何体|

具体使用场景如下：

- `GL_STATIC_DRAW` — 上传一次，反复使用

```cpp
// 场景里固定不动的山、地面、墙壁
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
```

- `GL_DYNAMIC_DRAW` — 会改，但不是每帧都改

```cpp
// 比如角色换装、可破坏的地形
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_DYNAMIC_DRAW);
// 之后某一帧局部修改：
glBufferSubData(GL_ARRAY_BUFFER, offset, size, newData);
```

- `GL_STREAM_DRAW` — 每帧几乎全部替换

```cpp
// 比如粒子系统：每帧几千个粒子位置全变
glBufferData(GL_ARRAY_BUFFER, sizeof(particles), particles, GL_STREAM_DRAW);
// 下一帧直接整体重新上传
glBufferData(GL_ARRAY_BUFFER, sizeof(particles), newParticles, GL_STREAM_DRAW);
```

**这三个值只是"提示"，不是强制命令**。用错了不会报错，只是可能损失一些性能，驱动可以完全忽略这个提示。

所以实际开发中的经验是：

```
不确定用什么？→ 先写 GL_STATIC_DRAW
发现有性能问题再考虑换 → GL_DYNAMIC_DRAW
每帧大量数据替换 → GL_STREAM_DRAW
```

> 当前入门阶段基本上写的所有示例都是 `GL_STATIC_DRAW`，后两个等遇到具体需求再换就行。

### 1.1.5 问题汇总

> Q：为什么要这么设计？

这是历史原因，OpenGL 是 1992 年的 API，当时用"绑定-操作"的状态机模式来避免每个函数都传一堆参数。现代的 Vulkan/Metal 已经不这么设计了，但 OpenGL 沿用至今。

开发时，只需要记住这个顺序：**先 Gen（创建）→ 再 Bind（激活）→ 再操作**，后面 VAO、纹理、帧缓冲都是同样的套路。

## 1.2 VAO

> Vertex Array Object，顶点数组对象。

- 本质：一份 **"如何解读 VBO 数据"的配置记录**
- 作用：记住"第 0 号属性是位置，从偏移 0 开始，每个顶点步长 12 字节"这类描述
- 好处：切换物体时只需 `glBindVertexArray(VAO)`，不用每次重新配置

```
VBO 里存的是：[-0.5, -0.5, 0.0,  0.5, -0.5, 0.0,  0.0, 0.5, 0.0]
                 ↑
VAO 记录的是：从位置 0 开始，每 3 个 float 是一个顶点的 xyz 坐标
```

多个 VAO 同时使用"编号 0 的属性"并不冲突，因为**属性编号是每个 VAO 内部独立的槽位，不是全局唯一的**。

```
VAOs[0] 的属性表：          VAOs[1] 的属性表：
┌────┬─────────────┐        ┌────┬─────────────┐
│编号│ 数据来源    │        │编号│ 数据来源    │
├────┼─────────────┤        ├────┼─────────────┤
│ 0  │ VBOs[0]     │        │ 0  │ VBOs[1]     │
└────┴─────────────┘        └────┴─────────────┘
```

两个 VAO 的"0 号属性"指向完全不同的 VBO，互不干扰。编号只是 VAO 内部的槽位名称，与 GLSL 里 `layout (location = 0)` 对应。

类比：两栋楼都有"1楼"，但指的是各自楼里的 1 楼，不会混淆。

## 1.3 EBO（或 IBO）

> Element Buffer Object（或者 Index Buffer Object），索引缓冲对象。

- 作用：避免重复顶点数据，用 **索引** 复用顶点
- 例子：画正方形只需 4 个顶点 + 6 个索引，而不是 6 个顶点

```cpp
// 4个顶点
float vertices[] = { 左上, 右上, 右下, 左下 };
// 用索引描述两个三角形
unsigned int indices[] = { 0, 1, 2,   0, 2, 3 };
```

## 1.4 三者关系

```
VAO
 ├── 绑定 VBO → 记录顶点数据的解读方式（位置、颜色、法线…）
 └── 绑定 EBO → 记录索引数据
```

### 1.4.1 创建阶段（Gen）

Gen 的顺序 **完全自由**，三者互不依赖，先创建谁都行：

```cpp
glGenVertexArrays(1, &VAO);  // 顺序无所谓
glGenBuffers(1, &VBO);       // 顺序无所谓
glGenBuffers(1, &EBO);       // 顺序无所谓
```

### 1.4.2 绑定与配置阶段

这里有两条强制规则：

**规则一：VAO 必须最先绑定**，之后的 VBO/EBO 配置才会被它记录下来：

```cpp
glBindVertexArray(VAO);          // ← 必须第一个，开始"录制"

glBindBuffer(GL_ARRAY_BUFFER, VBO);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
glVertexAttribPointer(...);
glEnableVertexAttribArray(0);

glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);
glBufferData(GL_ELEMENT_ARRAY_BUFFER, sizeof(indices), indices, GL_STATIC_DRAW);
```

> 注：这里 `glEnableVertexAttribArray(0);` 中的属性编号 0 区分的是 **一个顶点内部有哪几种数据**（位置、颜色、法线…），不是区分不同物体的。

**规则二：EBO 必须在 VAO 解绑之前绑定**，因为 VAO 会直接记录 EBO 的绑定关系（不像 VBO 只记录配置）：

```cpp
// ✅ 正确
glBindVertexArray(VAO);
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);  // EBO 在 VAO 解绑前绑定
glBindVertexArray(0);                        // VAO 解绑时顺便"锁住"了 EBO

// ❌ 错误
glBindVertexArray(VAO);
glBindVertexArray(0);                        // VAO 先解绑
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);  // EBO 在外面绑定，VAO 不知道
```

### 1.4.3 解绑阶段

**规则：VBO 可以在 VAO 解绑前解绑，但 EBO 绝对不行：**

```cpp
glBindBuffer(GL_ARRAY_BUFFER, 0);           // ✅ VBO 可以先解绑，VAO 已记住配置
// glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, 0); // ❌ 绝对不能在 VAO 解绑前解绑 EBO
glBindVertexArray(0);                       // VAO 解绑
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, 0);  // ✅ EBO 在 VAO 解绑后才能解绑
```

原因就是前面说的：VAO 对 VBO 和 EBO 的"记忆方式"不同：

```
VAO 对 VBO：记录的是 glVertexAttribPointer 的配置信息
            → VBO 解不解绑无所谓，配置已经存进 VAO 了

VAO 对 EBO：记录的是 EBO 绑定本身
            → EBO 一解绑，VAO 里记录的就变成"空"了
```

### 1.4.4 完整顺序总览

```cpp
// ── Gen：顺序随意 ──
glGenVertexArrays(1, &VAO);
glGenBuffers(1, &VBO);
glGenBuffers(1, &EBO);

// ── 配置：VAO 必须最先绑定 ──
glBindVertexArray(VAO);                                    // 1. VAO 先绑定

glBindBuffer(GL_ARRAY_BUFFER, VBO);                        // 2. VBO 随后
glBufferData(GL_ARRAY_BUFFER, ...);
glVertexAttribPointer(...);
glEnableVertexAttribArray(0);

glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, EBO);                // 3. EBO 在 VAO 内绑定
glBufferData(GL_ELEMENT_ARRAY_BUFFER, ...);

// ── 解绑：VBO 可先，EBO 必须后，VAO 居中 ──
glBindBuffer(GL_ARRAY_BUFFER, 0);                          // 4. VBO 先解绑（可选）
glBindVertexArray(0);                                      // 5. VAO 解绑
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, 0);                  // 6. EBO 最后解绑（可选）
```

- 创建顺序：VAO，VBO，EBO 的 Gen（创建）顺序无所谓；
- 绑定顺序：VAO 最先绑定，其次是 VBO 或者 EBO（这两者的绑定顺序无所谓）；
- 解绑顺序：**EBO 必须在 VAO 解绑之后才能解绑**。在VAO 之前可以解绑 VBO（也可以不解绑，或放到 VAO 之后）。

> 可以类比为：VAO 是容器，要先开箱再放东西，最后关箱。

# 3. 各阶段详解

## 3.1 顶点数据输入（CPU → GPU）

在 C++ 里定义顶点数据，比如一个三角形的三个点：

```cpp
float vertices[] = {
//   x      y     z
    -0.5f, -0.5f, 0.0f,  // 左下
     0.5f, -0.5f, 0.0f,  // 右下
     0.0f,  0.5f, 0.0f,  // 顶部
};
```

这些数据通过 **VBO（Vertex Buffer Object，顶点缓冲对象）** 上传到显存，GPU 才能读取。

## 3.2 顶点着色器（Vertex Shader）★

**每个顶点执行一次**，核心任务是做坐标变换。

```glsl
// 最简单的顶点着色器（GLSL 语言）
#version 330 core
layout (location = 0) in vec3 aPos;  // 从 VBO 读入顶点位置

uniform mat4 model;       // 模型矩阵（物体自身变换）
uniform mat4 view;        // 观察矩阵（摄像机）
uniform mat4 projection;  // 投影矩阵（透视效果）

void main() {
    // MVP 变换：把 3D 坐标最终变成屏幕坐标
    gl_Position = projection * view * model * vec4(aPos, 1.0);
}
```

这里会用到线性代数知识，坐标经历了：

```
模型空间 → (model矩阵) → 世界空间
        → (view矩阵)  → 观察空间
        → (projection矩阵) → 裁剪空间
```

## 3.3 图元装配

GPU 把顶点 **连接成几何图形**（点、线、三角形）。OpenGL 最常用三角形，因为任何复杂形状都能用三角形拼出来。

> 比如：一个正方形按斜对角线划分，可以由两个三角形拼出来。

```
顶点0, 顶点1, 顶点2  →  一个三角形 △
```

## 3.4 光栅化（Rasterization）

这是 2D/3D 的**分界点**，把矢量的三角形"打碎"成一个个**片段（Fragment）**，每个片段对应屏幕上的一个像素候选。

```
      △ 三角形
   ↓↓↓↓↓↓↓↓↓
  █ █ █ █ █ █    ← 片段（像素格子）
  █ █ █ █ █
  █ █ █ █
```

同时还会**插值**计算每个片段的属性（颜色、纹理坐标、法线…），这个插值非常重要：

```
顶点A（红色）    顶点B（蓝色）
        ↘    ↙
     中间片段（紫色）← 自动插值
```

## 3.5 片段着色器（Fragment Shader）★

**每个片段执行一次**，核心任务是决定这个像素的**最终颜色**。

```glsl
// 最简单的片段着色器
#version 330 core
out vec4 FragColor;  // 输出颜色（RGBA）

void main() {
    FragColor = vec4(1.0, 0.5, 0.2, 1.0);  // 橙色
}
```

实际项目中，片段着色器会做：
- **采样纹理**：查图片颜色
- **光照计算**：漫反射、镜面高光
- **阴影判断**

## 3.6 测试与混合

片段着色器输出颜色后，还要经过几道"检验"才能写入屏幕：

|测试|作用|
|---|---|
|**深度测试**|离摄像机近的物体遮挡远的（z-buffer）|
|**模板测试**|实现遮罩、描边等效果|
|**混合**|处理透明度（Alpha Blending）|

# 5. 着色器在 C++ 中的使用流程

> GLSL 代码需要在运行时被编译、链接，才能在 GPU 上执行。

## 5.1 完整流程

```
写 GLSL 源码字符串
       ↓
glCreateShader()   → 创建着色器对象
glShaderSource()   → 传入源码
glCompileShader()  → 编译（在 GPU 驱动里编译）
       ↓
glCreateProgram()  → 创建着色器程序
glAttachShader()   → 附加顶点 + 片段着色器
glLinkProgram()    → 链接
       ↓
glUseProgram()     → 激活，后续绘制调用都用这个程序
```

## 5.2 代码示例

```cpp
// 1. 编译顶点着色器
unsigned int vertexShader = glCreateShader(GL_VERTEX_SHADER);
glShaderSource(vertexShader, 1, &vertexShaderSource, NULL);
glCompileShader(vertexShader);

// 2. 编译片段着色器
unsigned int fragmentShader = glCreateShader(GL_FRAGMENT_SHADER);
glShaderSource(fragmentShader, 1, &fragmentShaderSource, NULL);
glCompileShader(fragmentShader);

// 3. 链接成着色器程序
unsigned int shaderProgram = glCreateProgram();
glAttachShader(shaderProgram, vertexShader);
glAttachShader(shaderProgram, fragmentShader);
glLinkProgram(shaderProgram);

// 4. 激活使用
glUseProgram(shaderProgram);

// 5. 编译完成后可删除中间对象
glDeleteShader(vertexShader);
glDeleteShader(fragmentShader);
```

## 5.3 向着色器传数据：Uniform

Uniform 是从 C++ 向 GLSL **传递参数** 的方式（每次 draw call 可以不同）：

```cpp
// C++ 侧：传一个颜色值
int location = glGetUniformLocation(shaderProgram, "ourColor");
glUniform4f(location, 0.0f, 1.0f, 0.0f, 1.0f);  // 绿色
```

```glsl
// GLSL 侧：接收
uniform vec4 ourColor;
void main() {
    FragColor = ourColor;
}
```

| 类型 | 含义 | 例子 |
|---|---|---|
| `float` | 单精度浮点 | `float x = 1.0;` |

| `mat4` | 4×4 矩阵 | MVP 矩阵 |
| `sampler2D` | 2D 纹理采样器 | `texture(tex, uv)` |
| `uniform` | CPU 传入的只读变量 | 矩阵、颜色、时间… |

# 7. 核心代码结构

在实际开发中，正因为骨架固定，真正的项目都会把它封装起来：

```
常见封装方式
├── Shader 类       → 把着色器编译链接流程包起来
├── Mesh 类         → 把 VAO/VBO 管理包起来
└── Application 类  → 把 GLFW 初始化和渲染循环包起来
```

代码结构：

```cpp
#include <glad/glad.h>
#include <GLFW/glfw3.h>

#include <iostream>

void framebuffer_size_callback(GLFWwindow *window, int width, int height);
void processInput(GLFWwindow *window);

// settings
const unsigned int SCR_WIDTH = 800;
const unsigned int SCR_HEIGHT = 600;

// 顶点着色器源码（⚠️会变）
const char *vertexShaderSource =
    "#version 330 core\n"
    "layout (location = 0) in vec3 aPos;\n"
    "void main()\n"
    "{\n"
    "   gl_Position = vec4(aPos.x, aPos.y, aPos.z, 1.0);\n"
    "}\0";

// 片段着色器源码（⚠️会变）
const char *fragmentShaderSource =
    "#version 330 core\n"
    "out vec4 FragColor;\n"
    "void main()\n"
    "{\n"
    "   FragColor = vec4(1.0f, 0.5f, 0.2f, 1.0f);\n"
    "}\n\0";

int main() {
  /* step1. 初始化 GLFW 和窗口 */
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ✅ 固定不变：初始化三件套
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  glfwInit();
  glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);  // OpenGL 主版本号 = 3
  glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);  // OpenGL 次版本号 = 3
  glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);  // 使用核心模式

#ifdef __APPLE__
  glfwWindowHint(GLFW_OPENGL_FORWARD_COMPAT, GL_TRUE);
#endif

  // glfw 窗口创建
  // --------------------
  GLFWwindow *window = glfwCreateWindow(SCR_WIDTH, SCR_HEIGHT, "标题", NULL, NULL);
  if (window == NULL) {
    std::cout << "Failed to create GLFW window" << std::endl;
    glfwTerminate();
    return -1;
  }

  glfwMakeContextCurrent(window);  // 把 OpenGL 上下文绑定到这个窗口，之后所有 OpenGL 调用都作用于这个窗口）
  glfwSetFramebufferSizeCallback(window, framebuffer_size_callback);

  // 初始化 GLAD
  // ---------------------------------------
  // GLAD 负责找到显卡驱动里 OpenGL 函数的实际地址。
  // 必须在创建窗口之后、调用任何 OpenGL 函数之前执行，否则后面所有 gl 开头的函数都是空指针。
  if (!gladLoadGLLoader((GLADloadproc)glfwGetProcAddress)) {
    std::cout << "Failed to initialize GLAD" << std::endl;
    return -1;
  }

  /* step2. 编译着色器 */
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ⚠️  会变：着色器源码内容会变，但编译流程固定不变
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ── 顶点着色器 ──
  unsigned int vertexShader = glCreateShader(GL_VERTEX_SHADER);  // 创建
  glShaderSource(vertexShader, 1, &vertexShaderSource, NULL);    // 传入源码
  glCompileShader(vertexShader);                                 // 编译
  // 错误检查（可选）
  int success;
  char infoLog[512];
  glGetShaderiv(vertexShader, GL_COMPILE_STATUS, &success);
  if (!success) {
    glGetShaderInfoLog(vertexShader, 512, NULL, infoLog);
    std::cout << "ERROR::SHADER::VERTEX::COMPILATION_FAILED\n"
              << infoLog << std::endl;
  }
  // ── 片段着色器 ──
  unsigned int fragmentShader = glCreateShader(GL_FRAGMENT_SHADER);  // 创建
  glShaderSource(fragmentShader, 1, &fragmentShaderSource, NULL);    // 传入源码
  glCompileShader(fragmentShader);                                   // 编译
  // 错误检查（可选）
  glGetShaderiv(fragmentShader, GL_COMPILE_STATUS, &success);
  if (!success) {
    glGetShaderInfoLog(fragmentShader, 512, NULL, infoLog);
    std::cout << "ERROR::SHADER::FRAGMENT::COMPILATION_FAILED\n"
              << infoLog << std::endl;
  }
  // ── 链接成着色器程序 ──
  unsigned int shaderProgram = glCreateProgram();
  glAttachShader(shaderProgram, vertexShader);
  glAttachShader(shaderProgram, fragmentShader);
  glLinkProgram(shaderProgram);
  // 错误检查（可选）
  glGetProgramiv(shaderProgram, GL_LINK_STATUS, &success);
  if (!success) {
    glGetProgramInfoLog(shaderProgram, 512, NULL, infoLog);
    std::cout << "ERROR::SHADER::PROGRAM::LINKING_FAILED\n"
              << infoLog << std::endl;
  }
  // 链接完成后，单独的着色器对象就没用了，删掉释放资源
  glDeleteShader(vertexShader);
  glDeleteShader(fragmentShader);

  /* step3. 设置顶点数据 (和缓冲区) 并配置顶点属性 */
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ⚠️  会变：顶点数据和解读方式会变，但 Gen→Bind→Data 流程固定
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // 示例：三角形顶点
  float vertices[] = {
      -0.5f, -0.5f, 0.0f,  // 左下角
      0.5f,  -0.5f, 0.0f,  // 右下角
      0.0f,  0.5f,  0.0f   // 顶部
  };
  /*
   *   OpenGL 的坐标范围是 -1.0 到 1.0，屏幕中心是 (0,0)：
   *           (0, 0.5)  ← 顶部顶点
   *              △
   *             /  \
   *   (-0.5,-0.5)──(0.5,-0.5)
   */

  // 接下来是 VAO + VBO 的创建（Gen 顺序无所谓）
  unsigned int VBO, VAO;
  glGenVertexArrays(1, &VAO);  // 创建 VAO
  glGenBuffers(1, &VBO);       // 创建 VBO

  glBindVertexArray(VAO);      // 必须先绑定 VAO
  glBindBuffer(GL_ARRAY_BUFFER, VBO);  // 再绑定 VBO

  glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);

  // VAO 才能记录这个配置
  // 分别为：属性编号、每个顶点 3 个分量、类型、不归一化、步长(每个顶点12字节)、从偏移0开始
  // 即 VBO 里的数据，从头开始，每隔 12 字节（3个float）取一个顶点，每个顶点取 3 个 float，存入着色器的第 0 号属性（也就是 aPos）
  glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, 3 * sizeof(float), (void *)0);
  glEnableVertexAttribArray(0);  // 启用编号为0的属性

  // 注意，这是允许的，调用 glVertexAttribuPointer 注册了 VBO 作为顶点属性的绑定顶点缓冲区对象，因此之后我们可以安全地解绑
  glBindBuffer(GL_ARRAY_BUFFER, 0);

  // 之后可以解绑 VAO，这样其他 VAO 调用就不会意外地修改这个 VAO，但这种情况很少发生
  // 修改其他 VAO 需要调用 glBindVertexArray
  glBindVertexArray(0);

  // uncomment this call to draw in wireframe polygons.
  // glPolygonMode(GL_FRONT_AND_BACK, GL_LINE);

  /* 渲染循环 */
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ✅ 固定不变：渲染循环结构
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  while (!glfwWindowShouldClose(window)) {
    processInput(window);  // 检查有没有按 ESC

    // ── 清屏 ──
    glClearColor(0.2f, 0.3f, 0.3f, 1.0f);  // 设置背景色（深青色）
    glClear(GL_COLOR_BUFFER_BIT);          // 用背景色填满屏幕

    // ── 绘制 ──
    glUseProgram(shaderProgram);       // 激活着色器程序
    glBindVertexArray(VAO);            // 绑定 VAO（告诉 GPU 用哪份顶点配置）
    glDrawArrays(GL_TRIANGLES, 0, 3);  // ⚠️ 参数会变：这里是画三角形，从第 0 个顶点开始，共 3 个

    // ── 双缓冲交换 ──
    glfwSwapBuffers(window);  // 把画好的帧显示出来
    glfwPollEvents();         // 处理系统事件（鼠标、键盘等）
  }

  /* 释放资源 */
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // ✅ 固定不变：清理结构
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // optional: de-allocate all resources once they've outlived their purpose:
  // ------------------------------------------------------------------------
  glDeleteVertexArrays(1, &VAO);
  glDeleteBuffers(1, &VBO);
  glDeleteProgram(shaderProgram);

  // glfw: terminate, clearing all previously allocated GLFW resources.
  // ------------------------------------------------------------------
  glfwTerminate();
  return 0;
}

// process all input: query GLFW whether relevant keys are pressed/released this
// frame and react accordingly
// ---------------------------------------------------------------------------------------------------------
void processInput(GLFWwindow *window) {
  if (glfwGetKey(window, GLFW_KEY_ESCAPE) == GLFW_PRESS)
    glfwSetWindowShouldClose(window, true);
}

// glfw: whenever the window size changed (by OS or user resize) this callback
// function executes
// ---------------------------------------------------------------------------------------------
void framebuffer_size_callback(GLFWwindow *window, int width, int height) {
  // make sure the viewport matches the new window dimensions; note that width
  // and height will be significantly larger than specified on retina
  // displays.
  glViewport(0, 0, width, height);
}
```

> 接下来再逐行拆解 `processInput` 和 `framebuffer_size_callback` 这两个函数。

- 对于函数 `processInput`：

```cpp
void processInput(GLFWwindow *window) {
    if (glfwGetKey(window, GLFW_KEY_ESCAPE) == GLFW_PRESS)
        glfwSetWindowShouldClose(window, true);
}
```

- `glfwGetKey(window, GLFW_KEY_ESCAPE)` — 查询 ESC 键当前的状态，返回 `GLFW_PRESS`（按下）或 `GLFW_RELEASE`（松开）
- `glfwSetWindowShouldClose(window, true)` — 把窗口标记为"应该关闭"

然后渲染循环里的条件就会变成 `false`，循环退出：

```cpp
while (!glfwWindowShouldClose(window))  // 检测到 true → 取反 → false → 退出
```

这个函数在 **每帧** 都被调用一次，所以只要你按下 ESC，下一帧就会退出。

- `framebuffer_size_callback` 是窗口大小改变时的回调：

```cpp
void framebuffer_size_callback(GLFWwindow *window, int width, int height) {
    glViewport(0, 0, width, height);
}
```

先理解 `glViewport` 是什么：

```
屏幕窗口（比如 800×600）
┌─────────────────────┐
│                     │
│   Viewport（视口）  │  ← OpenGL 实际渲染的区域
│                     │
└─────────────────────┘
```

`glViewport(0, 0, width, height)` 的意思是："把渲染区域设置为从左下角 (0,0) 开始，宽 width、高 height"，也就是让渲染区域始终铺满整个窗口。

> 为什么需要这个回调？

当你拖动窗口边框改变大小时，如果不更新 Viewport，渲染区域还是旧的尺寸，画面就会拉伸或出现黑边。

它是一个**回调函数**，意味着是你不会主动调用它，而是注册给 GLFW，让 GLFW 在窗口大小变化时自动调用它：

```cpp
// 在初始化时注册，之后 GLFW 自动管理
glfwSetFramebufferSizeCallback(window, framebuffer_size_callback);
```

这两个函数都属于 **固定骨架** 的一部分，几乎每个 OpenGL 项目都会有，内容基本不变。后续项目里 `processInput` 会扩展更多按键逻辑，但 `framebuffer_size_callback` 基本上永远就这一行。
