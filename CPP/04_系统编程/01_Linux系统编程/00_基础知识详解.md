# 1. 系统调用错误处理机制

**系统调用**是用户态与内核态的边界。规范处理调用失败状态是构建健壮系统的基础。

## 1.1 errno 的底层机制与线程安全

POSIX 标准规定，系统调用失败时返回 `-1`，并将具体错误原因写入 `errno`。
- **线程局部存储（TLS）**：现代 Linux 中 `errno` 并非传统全局变量，而是通过宏 `(*__errno_location())` 实现的线程局部变量。各线程独立维护，避免并发冲突。
- **惰性赋值原则**：系统调用**成功时不会清零 `errno`**，其值保持未定义状态。仅在返回 `-1` 时，`errno` 才具备诊断意义。
- **易变性**：任何后续的系统调用或标准库函数（如 `printf`、`malloc`）均可能覆盖 `errno`。

## 1.2 标准化错误检查范式

为保障错误码的准确性与代码可维护性，需遵循“立即读取、局部保存、统一抛出”原则。

```cpp
#include <cerrno>
#include <cstring>
#include <stdexcept>
#include <string>

// 统一错误检查工具：系统调用返回负值时抛出异常
int check_syscall(int ret, const char* call_name) {
    if (ret < 0) {
        // 立即捕获当前线程的 errno，防止被后续操作覆盖
        int saved_errno = errno;
        throw std::runtime_error(
            std::string(call_name) + " failed: " + std::strerror(saved_errno)
        );
    }
    return ret;
}
```

> [!note] `ret` 的含义
> `ret` 是 **"Return Value"（返回值）** 的缩写。它是系统调用执行后的结果。
> 在 Unix/Linux 系统编程中，系统调用遵循一个几乎通用的**约定**：
> - **如果成功**：返回一个**非负整数**（0 或正数）。例如 `open` 成功会返回文件描述符 `3`，`fork` 成功会返回子进程的 `PID`。
> - **如果失败**：返回 **`-1`**。

调用示例：

```cpp
// 一行代码搞定，出错自动抛异常
int fd = check_syscall(::open("config.txt", O_RDONLY), "open");
```

这行代码可以拆解为三个部分来理解：
1. **`::` (全局作用域解析符)**
	- 在 C++ 中，`::` 前面什么都不加，表示调用**全局命名空间**中的函数，即系统库（C 标准库/POSIX）提供的那个原始 `open` 函数。

2. **`open` (系统调用)**
	- 它的作用是请求内核打开一个文件：
		- 如果成功，内核会给你一个文件描述符 `fd`，也就是上面说的 `ret`。
		- 如果你指定的路径不存在，或者你没有权限，它就会返回 `-1`。

3. **参数部分**
	- **`"config.txt"`**：文件名。
	- **`O_RDONLY`**：全称是 **O**pen **R**ead **O**nly（以只读方式打开）。这是一个宏定义，通常在 `<fcntl.h>` 中。

> [!warning] 常见错误模式
> ```cpp
> // ❌ 错误示范：延迟读取 errno
> read(fd, buf, len);
> printf("checking...\n"); // printf 内部可能触发 malloc/write，覆盖 errno
> if (errno == EAGAIN) { ... } // 此时 errno 已不可靠
> ```
> **正确做法**：在系统调用返回后第一条语句立即执行 `int err = errno;`，后续逻辑仅依赖局部变量 `err`。

# 4. 进程创建与管道通信

多进程架构依赖 `fork()` 实现执行流复制，依赖管道实现进程间数据交换。

## 4.1 fork 系统调用语义与写时复制

`fork()` 通过复制调用进程的 PCB（进程控制块）创建子进程。核心特性如下：
- **地址空间复制**：采用写时复制（Copy-on-Write, COW）。父子进程初始共享物理内存页，仅在任一方执行写操作时触发内核页表复制。
- **文件描述符表复制**：子进程获得父进程 FD 表的副本，但指向**相同的内核打开文件表项**。共享表项的引用计数加一。
- **返回值分流**：父进程返回子进程 PID（`>0`），子进程返回 `0`，失败返回 `-1`。

## 4.2 管道创建与单向数据流

匿名管道（Anonymous Pipe）通过 `pipe()` 创建，本质为内核维护的环形字节缓冲区，遵循先进先出（FIFO）原则。

```cpp
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <cstdio>
#include <cstring>

int main() {
    int pipefd[2];
    if (pipe(pipefd) == -1) {
        perror("pipe creation failed");
        return 1;
    }

    pid_t pid = fork();
    if (pid < 0) {
        perror("fork failed");
        return 1;
    }

    if (pid == 0) {
        // ===== 子进程（读取端） =====
        ::close(pipefd[1]); // 关闭未使用的写端
        
        char buf[64];
        ssize_t n = read(pipefd[0], buf, sizeof(buf) - 1);
        if (n > 0) {
            buf[n] = '\0';
            printf("Child received: %s\n", buf);
        }
        ::close(pipefd[0]);
        _exit(0); // 使用 _exit 避免刷新标准 I/O 缓冲区
    } else {
        // ===== 父进程（写入端） =====
        ::close(pipefd[0]); // 关闭未使用的读端
        
        const char* msg = "hello from parent";
        write(pipefd[1], msg, strlen(msg));
        ::close(pipefd[1]); // 关键：关闭写端触发子进程 read 返回 0 (EOF)
        
        int status;
        waitpid(pid, &status, 0);
    }
    return 0;
}
```

上面这段代码是一个经典的 **POSIX 进程间通信（IPC）** 示例，具体实现了 **匿名管道（Anonymous Pipe）** 在父子进程间的单向数据传输。

### 4.2.1 核心技术说明

#### A. 管道（Pipe）机制

`int pipefd[2]` 定义了一个包含两个文件描述符的数组。
- `pipe(pipefd)` 系统调用会在内核中创建一个管道缓冲区（通常为 64KB）。
- **`pipefd[0]`**：读端（Read End）。
- **`pipefd[1]`**：写端（Write End）。

> 管道是**半双工**的，数据遵循 **FIFO（先进先出）** 原则。

#### B. 进程克隆（Fork）

`fork()` 系统调用用于创建一个与父进程几乎完全相同的子进程。
- **资源继承**：子进程继承父进程打开的所有文件描述符（File Descriptors）。
- **写时拷贝（COW）**：父子进程拥有独立的地址空间，但初始时共享内存页。
- **返回值**：在父进程中返回子进程的 PID，在子进程中返回 0。

#### C. 文件描述符的管理与引用计数

在 `fork()` 之后，同一个管道端口会有两个描述符指向它（父子各一个）。
- **关闭未使用端**：这是为了维护内核中文件对象的**引用计数**。
- **EOF（文件结束符）触发**：当所有指向管道写端的描述符都被 `close()` 后，读端的 `read()` 操作会返回 `0`。如果父进程不关闭其持有的 `pipefd[1]`，子进程的 `read()` 将会永久阻塞。

#### D. 进程同步与收尾

- **`waitpid()`**：父进程挂起执行，直到指定的子进程状态发生变化（退出）。这是为了回收子进程的 **PCB（进程控制块）** 资源，防止产生僵尸进程。
- **`_exit()`**：相比 `exit()`，它直接终止进程而不触发 `atexit` 处理器或刷新用户态标准 I/O 缓冲区（如 `printf` 的内部缓冲区），在子进程中使用更为安全。

### 4.2.2 程序执行过程模拟

#### 阶段一：初始化与创建管道

1. **进程 P1（父进程）** 启动。
2. 调用 `pipe(pipefd)`。内核创建管道，假设分配 `fd 3` 为读端，`fd 4` 为写端。
    - `pipefd[0] = 3`, `pipefd[1] = 4`。

#### 阶段二：派生子进程

1. 执行 `fork()`。
2. **内核动作**：创建 **进程 P2（子进程）**。P2 的 `fd 3` 和 `fd 4` 同样指向该管道。

#### 阶段三：角色分化与环境清理

1. **P2（子进程）** 执行 `if (pid == 0)` 分支：
    - 调用 `close(4)`：关闭写端。此时管道写端的引用计数由 2 变为 1（父进程还拿着）。
    - 执行 `read(3, ...)`：由于管道为空，P2 进入 **阻塞（Blocked）** 状态，等待数据。

2. **P1（父进程）** 执行 `else` 分支：
    - 调用 `close(3)`：关闭读端。此时管道读端的引用计数由 2 变为 1。
    - 执行 `write(4, "hello from parent", 17)`：将字符串写入内核缓冲区。

#### 阶段四：数据传输与同步

1. 内核检测到管道有数据，唤醒阻塞的 **P2**。
2. **P2** 从 `fd 3` 读取数据，存入 `buf`，并通过 `printf` 打印。
3. **P1** 调用 `close(4)`：关闭写端。此时管道写端的引用计数变为 0。
4. **P2** 再次尝试 `read`（循环或后续操作），内核发现写端已全部关闭，返回 `0`。
5. **P2** 调用 `_exit(0)` 退出。

#### 阶段五：资源回收

1. **P1** 正在执行 `waitpid(P2_PID, ...)`，捕获到 P2 的退出信号。
2. **P1** 回收 P2 的剩余资源，`waitpid` 返回，P1 执行 `return 0` 彻底结束任务。

## 4.3 文件描述符继承与端口关闭策略

管道通信的阻塞与终止行为严格依赖文件描述符的引用计数。

| 操作场景 | 未关闭冗余端口的后果 | 正确行为 |
|:---|:---|:---|
| 子进程未关闭写端 | 父进程关闭写端后，内核写端引用计数仍大于 0。子进程 `read()` 永久阻塞，无法感知 EOF。 | 读取方必须关闭写端 |
| 父进程未关闭读端 | 不阻塞通信，但浪费文件描述符资源，违反最小权限原则。 | 写入方必须关闭读端 |
| 双方关闭所有写端 | 内核缓冲区数据耗尽后，后续 `read()` 返回 `0`，表示数据流结束。 | 依赖引用计数判断生命周期 |

> [!warning] `_exit()` 与 `exit()` 的差异
> - `exit()`：刷新标准 I/O 流缓冲区，执行 `atexit()` 注册的清理函数。在子进程中调用可能导致父进程已缓冲的内容被重复输出。
> - `_exit()`：直接终止进程，交由内核回收资源。`fork()` 后的子进程必须使用 `_exit()`。

# 5. 进程生命周期与异步信号处理

服务器架构中，父进程需异步感知子进程退出状态，并防御异常网络事件。

## 5.1 僵尸进程成因与 waitpid 回收机制

子进程调用 `_exit()` 后，内核释放其内存与资源，但保留 PCB 中的退出状态码，等待父进程读取。此状态称为僵尸进程（`Z` 状态）。
- **危害**：占用系统 PID 资源与内核 PCB 内存。累积过多将导致 `fork()` 失败。
- **回收方法**：父进程调用 `wait()` 或 `waitpid()` 读取状态。

## 5.2 SIGCHLD 信号处理与 errno 保护

服务器需异步回收并发子进程，通过注册 `SIGCHLD` 信号处理函数实现。

```cpp
#include <signal.h>
#include <sys/wait.h>
#include <cerrno>

static void sigchld_handler(int signo) {
    (void)signo;
    int saved_errno = errno; // 关键：信号异步触发，可能中断主流程系统调用并覆盖 errno
    
    // 循环回收：信号可能合并，单次触发可能对应多个子进程退出
    while (waitpid(-1, nullptr, WNOHANG) > 0) {
        // 可在此记录日志或更新连接计数
    }
    
    errno = saved_errno; // 恢复原始 errno，保证主流程错误判断准确
}

static void setup_sigchld() {
    struct sigaction sa{};
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART; // 自动重启被信号中断的阻塞系统调用（如 accept, read）
    if (sigaction(SIGCHLD, &sa, nullptr) == -1) {
        perror("sigaction failed");
    }
}
```

> [!info] 关键标志位解析
> - `WNOHANG`：非阻塞模式。无退出子进程时立即返回 `0`，避免信号处理函数阻塞主业务线程。
> - `SA_RESTART`：内核自动重试被信号中断的系统调用（如 `read`、`accept`）。避免业务代码需手动处理 `EINTR` 错误。

## 5.3 SIGPIPE 信号的防御性处理

向已关闭对端连接的 TCP Socket 执行 `write()` 时，内核默认向进程发送 `SIGPIPE`，其默认动作为终止进程。单客户端断线导致整个服务器崩溃是典型架构缺陷。

```cpp
// 方案一：全局忽略（推荐，服务器启动时执行一次）
signal(SIGPIPE, SIG_IGN);

// 方案二：单次操作屏蔽（适用于细粒度控制）
ssize_t safe_send(int sockfd, const void* buf, size_t len) {
    ssize_t n = send(sockfd, buf, len, MSG_NOSIGNAL);
    if (n < 0 && errno == EPIPE) {
        // 对端已断开，按业务逻辑优雅降级
    }
    return n;
}
```

# 6. 综合实战与核心知识总结

## 6.1 健壮的多进程服务器基础框架

整合文件描述符管理、信号处理与进程创建机制，构建最小可用的高并发服务器骨架。

```cpp
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
#include <cerrno>
#include <cstdio>

static void sigchld_handler(int) {
    int saved = errno;
    while (waitpid(-1, nullptr, WNOHANG) > 0);
    errno = saved;
}

static void setup_signals() {
    signal(SIGPIPE, SIG_IGN); // 防御断线崩溃
    
    struct sigaction sa{};
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGCHLD, &sa, nullptr);
}

int main() {
    setup_signals();

    for (int i = 0; i < 3; ++i) {
        pid_t pid = fork();
        if (pid < 0) { perror("fork"); return 1; }
        
        if (pid == 0) {
            printf("[Child %d] Processing task %d\n", getpid(), i);
            sleep(1); // 模拟业务耗时
            _exit(0);
        }
    }

    printf("[Parent] Waiting for children to complete...\n");
    sleep(3); // 父进程可继续执行事件循环或接受新连接
    printf("[Parent] All tasks handled.\n");
    return 0;
}
```

## 6.2 核心知识体系对照表

| 知识模块 | 核心机制 | 关键系统调用/标志 | 复习要点 |
|:---|:---|:---|:---|
| **文件描述符** | 内核对象引用计数管理 | `open`, `close`, `dup` | `fd` 为进程级索引；内核打开文件表项共享；引用计数归零触发物理释放 |
| **错误处理** | 线程局部错误码与立即捕获 | `errno`, `strerror` | 仅失败时有效；必须立即保存至局部变量；避免在信号处理函数中使用非安全函数 |
| **资源管理** | RAII 与移动语义 | `std::exchange`, `noexcept` | 禁止拷贝防二次关闭；析构函数保证异常安全；显式 `close` 避免资源长期占用 |
| **进程通信** | 写时复制与单向管道 | `fork`, `pipe`, `read`, `write` | 双方必须关闭冗余端；写端全关触发 EOF；子进程必须用 `_exit` 终止 |
| **信号处理** | 异步通知与僵尸回收 | `sigaction`, `waitpid` | `WNOHANG` 防阻塞；`SA_RESTART` 防 `EINTR`；`SIGPIPE` 必须忽略或捕获 |

> [!summary] 学习路径指引
> 本节构建了从底层资源抽象（fd）到多进程并发控制（fork/pipe/signals）的完整知识链。下一步应深入 **网络字节序与 Socket 地址结构**，将管道通信模型迁移至跨主机 TCP/UDP 通信，并引入 `select`/`epoll` 实现 I/O 多路复用。
