# 1. 题目

菲谢尔在稻妻冒险途中遇到一排神奇的元素方碑，其中第 $i$ 个方碑初始时的能量为 $a_i$。只要她对第 $i$ 块方碑施放雷元素，就会发生能量转移：

- **正面轰击**：雷元素从第 $i-1$ 块流向第 $i+1$ 块，使 $a_{i-1}$ 减 1、$a_{i+1}$ 加 1；
- **反面轰击**：雷元素从第 $i+1$ 块流向第 $i-1$ 块，使 $a_{i+1}$ 减 1、$a_{i-1}$ 加 1。

操作只能在 $2 \leq i \leq n-1$ 的方碑上进行，且任何时刻所有方碑能量 $a_i$ 必须保持非负。

当所有方碑的能量 $a_1, a_2, \dots, a_n$ 全部相等时，菲谢尔即可开启隐藏宝箱。菲谢尔可以无限次进行操作。请判断，她是否一定能够让所有方碑能量相等。

**输入格式**：
- 第一行输入一个整数 $t$（$1 \leq t \leq 10^4$）——测试用例组数。
- 对于每组测试数据：
  - 第一行输入一个整数 $n$（$1 \leq n \leq 2 \times 10^5$）——方碑数量；
  - 第二行输入 $n$ 个整数 $a_1, a_2, \dots, a_n$（$1 \leq a_i \leq 10^9$）——初始能量。
- 保证单个测试文件中全部测试用例的 $n$ 之和不超过 $2 \times 10^5$。

**输出格式**：对每组测试数据，在一行上输出 `YES` 或 `NO`，表示能否通过若干次操作使所有方碑能量相等。

**样例**：

```
输入：
8
3
3 2 1
3
1 1 3
4
1 2 5 4
4
1 6 6 1
5
6 2 1 4 2
4
1 4 2 1
5
3 1 2 1 3
3
2 4 2

输出：
YES
NO
YES
NO
YES
NO
NO
NO
```

> [!info] 样例说明
> - **第 1 组**（`3 2 1`）：对 $i=2$ 正面轰击一次，得到 $\{2,2,2\}$，输出 YES。
> - **第 3 组**（`1 2 5 4`）：先正面轰击 $i=3$，再反面轰击 $i=2$，最终得到 $\{3,3,3,3\}$，输出 YES。
> - **第 8 组**（`2 4 2`）：总能量 $2+4+2=8$，$8 \bmod 3 \neq 0$，无论如何操作均无法均分，输出 NO。

# 2. 题解

## 2.1 核心考点

- **不变量（Invariant）分析**：寻找在所有合法操作下保持不变的量。对"能否达到目标状态"类问题，不变量是最有力的工具——若目标状态要求某不变量取某值，而初始状态该量取另一值，则目标不可达。
- **必要条件与充分条件**：不变量只能导出"不可达"的排除结论（必要条件）。还需额外论证当不变量满足时目标是否真的可达（充分条件）。
- **奇偶下标分析**：操作的影响范围与施力位置的下标奇偶性密切相关。

## 2.2 操作本质：奇偶分流

对位置 $i$（$2 \leq i \leq n-1$）施加任意一次操作，其影响**仅涉及 $a_{i-1}$ 和 $a_{i+1}$ 两个位置**，且两者的变化量大小相等、方向相反（一个 $+1$，另一个 $-1$）。

**关键观察**：$i-1$ 与 $i+1$ 的奇偶性**相同**，因为 $(i+1)-(i-1)=2$。因此：

| 施力位置 $i$ 的奇偶 | 受影响位置 $i-1$、$i+1$ 的奇偶 | 能量流向 |
| :---: | :---: | :--- |
| $i$ 为**偶数** | $i-1$、$i+1$ 均为**奇数** | 能量在**奇数位之间**转移 |
| $i$ 为**奇数** | $i-1$、$i+1$ 均为**偶数** | 能量在**偶数位之间**转移 |

> [!note] 奇偶分流的本质
> **任何操作都不能将能量从奇数位转移到偶数位，也不能从偶数位转移到奇数位。** 奇数位与偶数位的能量池是完全隔离的两个独立系统。

## 2.3 不变量的严格证明

**定义**：设 $S_{odd} = \displaystyle\sum_{i \text{ 为奇数}} a_i$，$S_{even} = \displaystyle\sum_{i \text{ 为偶数}} a_i$。

**命题**：对任意合法操作，$S_{odd}$ 和 $S_{even}$ 均保持不变。

**证明**：对位置 $i$ 施加操作，设变化量为 $\delta \in \{+1, -1\}$（正面轰击时 $a_{i-1}$ 变化 $-\delta$、$a_{i+1}$ 变化 $+\delta$，反面轰击相反，但以下分析对两种情形均成立）：

- **若 $i$ 为偶数**：$a_{i-1}$（奇数位）变化 $+\delta$，$a_{i+1}$（奇数位）变化 $-\delta$。
  $$\Delta S_{odd} = \delta + (-\delta) = 0, \quad \Delta S_{even} = 0$$

- **若 $i$ 为奇数**：$a_{i-1}$（偶数位）变化 $+\delta$，$a_{i+1}$（偶数位）变化 $-\delta$。
  $$\Delta S_{odd} = 0, \quad \Delta S_{even} = \delta + (-\delta) = 0$$

两种情况下 $S_{odd}$ 与 $S_{even}$ 均不变。$\blacksquare$

## 2.4 平衡状态的必要条件

若最终所有方碑的能量均等于 $Avg$，则：

**条件一：总能量可被 $n$ 整除。**

$$S_{total} = n \times Avg \implies Avg = \frac{S_{total}}{n} \in \mathbb{Z} \implies S_{total} \bmod n = 0$$

**条件二：奇数位的初始总能量与奇数位的目标总能量相等。**

由不变量知 $S_{odd}$ 在操作中保持不变，最终状态下共 $count_{odd}$ 个奇数位、每位取值 $Avg$，故：

$$S_{odd} = count_{odd} \times Avg$$

> [!tip] 条件二蕴含偶数位的结论
> 当条件一、二均成立时：
> $$S_{even} = S_{total} - S_{odd} = n \times Avg - count_{odd} \times Avg = count_{even} \times Avg$$
> 偶数位的条件自动满足，**无需单独检查**。

## 2.5 充分性论证

上述两个条件不仅是必要的，也是**充分的**——满足这两个条件时，一定存在合法操作序列使所有方碑能量相等。

**论证**：奇数位 $1, 3, 5, \ldots$ 之间可通过位于其间的偶数位操作（$i = 2, 4, 6, \ldots$）相互传递能量：相邻奇数位 $2k-1$ 和 $2k+1$ 可经由操作 $i=2k$ 完成单位传输。这些奇数位构成一条**路径连通图**，能量可沿路径逐步搬运。

由于总量正确（条件一、二保证奇数位总量 = $count_{odd} \times Avg$），始终存在从"高于均值"的位置向"低于均值"的位置输送的路径，且搬运方向由多向少，中间节点的能量值不会降至负数。偶数位同理。

因此，两个条件合在一起，既排除了所有不可达情形，也保证了可达性。

## 2.6 示例验证

| 用例 | 数组 | $S_{total}$ | $n$ | $Avg$ | $S_{odd}$ | $count_{odd} \times Avg$ | 结论 |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| 1 | $\{3,2,1\}$ | 6 | 3 | 2 | $3+1=4$ | $2\times2=4$ ✓ | **YES** |
| 2 | $\{1,1,3\}$ | 5 | 3 | — | — | — | **NO**（$5\bmod3\neq0$）|
| 3 | $\{1,2,5,4\}$ | 12 | 4 | 3 | $1+5=6$ | $2\times3=6$ ✓ | **YES** |
| 4 | $\{1,6,6,1\}$ | 14 | 4 | — | — | — | **NO**（$14\bmod4\neq0$）|
| 5 | $\{6,2,1,4,2\}$ | 15 | 5 | 3 | $6+1+2=9$ | $3\times3=9$ ✓ | **YES** |
| 6 | $\{1,4,2,1\}$ | 8 | 4 | 2 | $1+2=3$ | $2\times2=4$ ✗ | **NO**（条件二不满足）|
| 7 | $\{3,1,2,1,3\}$ | 10 | 5 | 2 | $3+2+3=8$ | $3\times2=6$ ✗ | **NO**（条件二不满足）|
| 8 | $\{2,4,2\}$ | 8 | 3 | — | — | — | **NO**（$8\bmod3\neq0$）|

## 2.7 代码

```cpp
#include <ios>
#include <iostream>

/**
 * 判断能否通过操作使所有方碑能量相等。
 *
 * 不变量：S_odd（奇数位总和）与 S_even（偶数位总和）在操作中保持不变。
 * 必要且充分条件：
 *   1. total_sum % n == 0
 *   2. S_odd == count_odd * avg
 */
void solve() {
    int n;
    std::cin >> n;

    long long sum_odd = 0, sum_even = 0;
    int count_odd = 0;

    for (int i = 1; i <= n; ++i) {
        long long val;
        std::cin >> val;
        // 位运算判奇偶：i & 1 等价于 i % 2 == 1，但执行速度更快
        if (i & 1) {
            sum_odd += val;
            ++count_odd;
        } else {
            sum_even += val;
        }
    }

    // n == 1 时数组已满足均等，直接输出 YES
    // 注意：此特判必须在读完所有数据后执行，避免输入流偏移（见 3.2 节）
    if (n == 1) {
        std::cout << "YES\n";
        return;
    }

    long long total_sum = sum_odd + sum_even;

    if (total_sum % n != 0) {
        std::cout << "NO\n";
        return;
    }

    long long avg = total_sum / n;
    std::cout << (sum_odd == (long long)count_odd * avg ? "YES" : "NO") << '\n';
}

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    int t;
    std::cin >> t;
    while (t--) {
        solve();
    }
}
```

## 2.8 复杂度分析

设所有测试用例数组长度之和为 $L$（题目保证 $L \leq 2 \times 10^5$）。

| 步骤 | 时间复杂度 | 说明 |
| :--- | :---: | :--- |
| 读入并遍历数组 | $O(L)$（总计）| 每个元素恰好被访问一次 |
| 条件判断 | $O(1)$（每组）| 常数次整数运算 |
| **总体** | $O(L)$ | 瓶颈在遍历，与组数 $t$ 无关 |

**空间复杂度**：$O(1)$。在线处理（on-the-fly），不存储数组，仅维护累计和与计数器。

# 3. 实现要点

## 3.1 性能优化

### 3.1.1 Fast I/O

将以下三行写在 `main()` 最开头，在任何 I/O 操作之前：

```cpp
std::ios::sync_with_stdio(false);  // 关闭与 C stdio 的同步，cin/cout 速度接近 scanf/printf
std::cin.tie(nullptr);             // 解除 cin 与 cout 的绑定，取消每次读取前的强制刷新
// 输出时用 '\n' 代替 std::endl（endl 每次强制 flush，开销极大）
```

> [!caution] 开启 Fast I/O 后的限制
> 禁止在同一程序中混用 `cin/cout` 与 `scanf/printf`；交互题中需手动 `flush`，不适用 Fast I/O 全套方案。

### 3.1.2 空间优化：在线处理

本题无需将整个数组存入内存。读入时直接累加，处理完立即丢弃，空间复杂度从 $O(n)$ 降为 $O(1)$：

```cpp
for (int i = 1; i <= n; ++i) {
    long long val;
    std::cin >> val;   // 读入后立即累加，不保存到 vector 或数组
    if (i & 1) sum_odd += val;
    else sum_even += val;
}
```

### 3.1.3 位运算加速

用 `i & 1` 替代 `i % 2 == 1` 判断奇偶。按位与直接操作最低二进制位，是 CPU 原生支持的最快基本指令之一，避免了取模运算的除法开销。

## 3.2 多组数据的输入流同步

> [!caution] 核心陷阱
> **严禁在读完当前组所有数据前提前 `return` 或 `continue`**。未被读走的数据会留在输入流中，被下一组的读取操作错误消费，引发 TLE 或 RE。

**错误写法**：

```cpp
// ❌ 在读数据前提前 return，后续数据未被消费
void solve() {
    int n;
    std::cin >> n;
    if (n == 1) {
        std::cout << "YES\n";
        return;             // 致命：a[1] 留在输入流，下一组误读
    }
    for (int i = 1; i <= n; ++i) { std::cin >> val; }
}
```

**正确写法**：

```cpp
// ✅ 先将所有数据无条件读完，再做提前退出的判断
void solve() {
    int n;
    std::cin >> n;
    for (int i = 1; i <= n; ++i) {
        std::cin >> val;    // 无论 n 为何值，均完整读取
        // ...累加操作...
    }
    if (n == 1) {           // 数据已全部读完，此处 return 安全
        std::cout << "YES\n";
        return;
    }
}
```

> [!tip] 金律
> 将 `solve()` 明确划分为两个阶段：**读取阶段**（无条件读完本组全部数据，不插入任何 `return`）和**处理阶段**（基于已读数据进行逻辑判断，此时的 `return` 是安全的）。
