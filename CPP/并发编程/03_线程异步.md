# 1. 基本概念

> [!abstract]
线程异步（Asynchronous Threading）是一种编程范式，用于执行任务或操作而不阻塞主线程或其他线程的执行。这种方法特别适用于需要同时处理多个操作或在后台执行长时间运行的任务的场景。线程异步的核心思想是将耗时的操作与主执行流程分离，使得系统能够继续处理其他任务，而无需等待耗时操作完成。

**多线程**和**异步**这两个概念都是为了解决同一个问题：“**如何在等待某件事的时候，不让程序傻站着什么都不干**”，但它们的思路截然不同。

1. **多线程（Multithreading）**
	**核心思想**：雇多个工人，同时干多件事。

> [!example]
> 比如一家餐厅，每来一位客人，就专门安排一个服务员全程陪同——点餐、等餐、上菜都是这个服务员负责。客人多了，服务员也得多。

- **优点**：
	- 模型直观，可以实现并行执行（在多核 CPU 上）
- **缺点**：
    - 线程本身有开销（内存、创建时间）
    - 线程之间共享数据容易出问题（竞态条件、死锁）
    - 大量线程时，CPU 频繁"切换"反而浪费资源

2. **异步（Async / 异步非阻塞）**
	**核心思想：** 一个工人，聪明地利用等待时间。

> [!example]
> 还是那家餐厅，但只有一个服务员。他把菜单给 A 桌之后，不傻等，而是去招呼 B 桌；A 桌想好了按铃，他再回来。一个人高效地服务多桌。

- **优点**：
    - 开销极小，轻松支撑数万个并发任务
    - 没有线程切换、没有锁的烦恼
- **缺点**：
    - 如果某个任务是 CPU 密集型（比如大量计算），它会"堵住"整个流程
    - 编程模型相对复杂，需要理解"事件循环"的概念

> [!note] 从上面的例子我们可以总结出异步的特点：
> - **定义**：当你发起一个调用后，**不等结果出来**，直接去做别的事。等结果好了，通过回调、通知或信号来告诉你。
> - **本质**：它是关于“**等待方式**”的。同步是“死等”，异步是“边干别的边等”。

现代程序往往两者并用——用**多线程**处理 CPU 密集的计算，用**异步**处理大量的网络请求。比如一个 Web 服务器：多个线程各自运行一个异步事件循环，兼顾吞吐量和资源效率。

# 1. `std::future`

`std::future` 是 C++ 标准库里用于 **跨线程获取“将来某个结果”** 的同步原语。它把“结果的产生”和“结果的消费”解耦：生产者在线程 A 里计算，消费者在线程 B 里**等待/查询**这个结果。
