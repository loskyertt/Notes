# 1. decltype 关键字

`decltype` 是 C++11 引入的关键字，用于**在编译期推导表达式的类型**，而不需要实际计算这个表达式的值。它常与 `auto`、模板编程结合使用，尤其在泛型代码中非常有用。

## 1.1 基本用法

```cpp
int x = 5;
decltype(x) y = 10;      // y 的类型是 int

double f();
decltype(f()) z;         // z 的类型是 double（f() 并不会被调用）
```

## 1.2 decltype 的推导规则

`decltype` 的推导规则和 `auto` 不同，比较特殊，主要分三种情况：

1. **如果表达式是一个不加括号的变量名**：结果就是该变量声明时的类型（保留 `const`、引用等修饰）。

```cpp
const int ci = 0;
decltype(ci) x = 1;   // x 的类型是 const int
```

2. **如果表达式是一个函数调用**：结果是该函数的返回类型。

```cpp
int foo();
decltype(foo()) a;    // a 的类型是 int
```

3. **如果表达式是其他左值（lvalue）表达式（比如加了括号的变量、解引用等）**：结果是该类型的**引用**（`T&`）。

```cpp
int x = 0;
decltype(x) a = x;     // int，因为 x 是不加括号的变量名
decltype((x)) b = x;   // int&，因为 (x) 是左值表达式，多了一层括号就变了！
```

> [!warning]
> 这个“加括号会改变结果”的特性经常让人踩坑，需要特别注意。

## 1.3 常见应用场景

**1. 结合 `auto` 用于返回类型推导（C++11 的尾置返回类型）**

```cpp
template<typename T, typename U>
auto add(T t, U u) -> decltype(t + u) {
    return t + u;
}
```

> [!note]
> C++14 之后，一般可以直接用 `auto` 自动推导返回类型，不再需要这种写法。

**2. `decltype(auto)`（C++14 引入）**

用于精确保留表达式的值类别（左值/右值、引用与否），常用于转发函数：

```cpp
int x = 10;
int& getRef() { return x; }

decltype(auto) r = getRef();  // r 的类型是 int&（保留引用）
auto r2 = getRef();           // r2 的类型是 int（auto 会退化，丢失引用）
```

**3. 泛型编程中声明依赖于其他类型的变量**

```cpp
template<typename Container>
void process(Container& c) {
    decltype(c.begin()) it = c.begin();  // 自动获取迭代器类型
}
```

## 1.4 与 `auto` 的区别

||`auto`|`decltype`|
|---|---|---|
|是否需要初始化|需要|不需要|
|是否丢失引用/const|会（除非用 `auto&`）|不会（保留原始类型信息）|
|使用场景|变量声明时根据初始值推导|根据已有表达式获取精确类型|

简单来说：`auto` 是“看初始值猜类型”，`decltype` 是“精确复刻表达式的类型”，两者常常配合使用，尤其在模板和泛型代码中。

# 2. 标识符和函数的区别

标识符和函数不是同一层面的概念，容易混淆是因为函数**也需要**一个标识符来命名它。可以这样理解：

## 2.1 标识符（Identifier）

标识符**只是一个名字**，是语言层面的一个语法元素，用来指代程序中的某个“东西”。它本身不做任何事情，只是一个标签。

```cpp
int count;        // count 是标识符，指代一个变量
void foo();       // foo 是标识符，指代一个函数
class Dog {};      // Dog 是标识符，指代一个类型
namespace ns {}    // ns 是标识符，指代一个命名空间
```

标识符可以指代：变量、函数、类、命名空间、模板、枚举值……几乎所有你能命名的东西。

## 2.2 函数（Function）

函数是一个**具体的实体**——是一段可执行的代码逻辑，接收参数、执行操作、返回结果。

```cpp
int add(int a, int b) {
    return a + b;
}
```

这里 `add` 是**标识符**（名字），而“接收两个 int、返回它们的和”**这段逻辑才是函数本身**。

> [!tip] 关系类比
> 
> 标识符和函数的关系，就像“门牌号”和“房子”：
> 
> - **门牌号（标识符）**：只是一个用来指向某处的名字，比如“3号楼”。
> - **房子（函数/变量/类）**：是门牌号背后真正存在的实体，有实际的内容和作用。
> 
> 一个函数**必须**通过一个标识符来命名和调用，但标识符本身不等于函数——标识符也可以指向变量、类型等其他东西。
> 
> ```cpp
> int add(int a, int b) { return a + b; }  // add 是标识符，指向“函数”这个实体
> int result;                                // result 是标识符，指向"变量"这个实体
> ```
> 
> 所以简单说：**标识符是“名字”这个语法概念，函数是“名字所指代的一种具体实体”**，两者不是平级对立的关系，而是“名字”与“名字所指代对象的一种类型”的关系。

# 3. 求值表达式和不求值表达式

这是理解 `decltype` 为什么特殊的关键。

## 3.1 求值表达式（Evaluated Expression）

表达式会被**实际执行**，产生副作用（side effect），比如修改变量、调用函数体、进行 I/O 操作等。

```cpp
int x = 0;

int foo() {
    x = 100;        // 修改了 x，这是一个副作用
    return x;
}

int y = foo();       // foo() 被求值：函数体真正执行了，x 变成 100
// 此时 x == 100
```

这里 `foo()` 是一个求值表达式，编译器会生成调用 `foo` 的实际机器码，程序运行时会真正执行这次调用。

## 3.2 不求值表达式（Unevaluated Expression）

表达式**只在编译期被分析其类型或某些静态属性**，并不会真正执行，也不会产生任何运行时副作用。

比如第一章我们所说的 `decltype`：

```cpp
int x = 0;

int foo() {
    x = 100;         // 这行代码不会被执行！
    return x;
}

decltype(foo()) y;    // foo() 出现在 decltype 里，只是用来“问类型”
// 此时 x 仍然是 0，foo() 从未真正被调用
```

`decltype(foo())` 中的 `foo()` 只是编译器用来**推断类型**（这里是 `int`）的一个“形式上的表达式”，编译器并不会生成调用 `foo` 的代码，`foo` 函数体里的 `x = 100` 也就永远不会执行。这也正是为什么 `decltype(foo())` 即使 `foo()` **从未被定义实现（只有函数声明）**，也能编译通过——因为编译器根本不需要真正调用它，只需要知道它的返回类型即可。

## 3.3 C++ 中的不求值上下文（unevaluated context）

C++ 中有几个专门的“不求值上下文”，表达式写在里面只用来做静态分析：

```cpp
decltype(expr)     // 推导类型
sizeof(expr)       // 计算类型大小
typeid(expr)       // 获取类型信息（某些情况下也不求值）
noexcept(expr)     // 检查是否可能抛异常
```

例如：

```cpp
int arr[10];
sizeof(arr[100]);     // 不求值！即使数组越界访问，也不会真正执行，不会崩溃
                      // sizeof 只关心 arr[100] 的类型是 int，结果是 sizeof(int)
```

## 3.4 对比总结

||求值表达式|不求值表达式|
|---|---|---|
|是否真正执行|是|否|
|是否产生副作用|会|不会|
|编译器生成运行时代码|会|不会（只做静态分析）|
|典型场景|普通语句、赋值、函数调用|`decltype(...)`、`sizeof(...)`、`noexcept(...)`|
|举例|`int y = foo();`|`decltype(foo()) y;`|

# 4. 模板

1. 模板声明语法  
   • `template <class T>` 与 `template <typename T>` **功能等价**，后者语义更直观。  
   • 模板模板参数必须用 `template <template<class> class C>`（C++20 前不能用 `typename`）。

| 语法                      | 说明                                              |
| ----------------------- | ----------------------------------------------- |
| `template <class T>`    | `class` 在这里并不特指“类”，而是泛指“**任何类型**”（包括基本类型、结构体、联合体等）。 |
| `template <typename T>` | 更明确地表示“T 是一个类型”，避免误解为“只能是 class 类型”。  |

比如：

```cpp
template <class Container>  // ✅ 必须用 class
struct MyStruct {};

template <typename Container>  // ❌ 错误，C++20 前不允许
struct MyStruct {};
```


2. 模板定义必须对编译器可见  
   • 模板**不是**普通函数；只有当编译器在**当前翻译单元**看到完整定义时，才能实例化。  
   • **不能把模板实现放到单独的 `.cpp` 里再链接**，否则会报 “undefined reference”。

## 4.2 使用方法

> [!note]
> 使用模板时，需要把声明与实现放在一起。

### 4.2.1 函数模板

指定类型：

```cpp
template <int a, int b>  
int add() {  
  return a + b;  
}

// 使用
std::cout << "add<1, 2> = " << add<1, 2>() << std::endl;  // 输出为 add<1, 2> = 3
```

使用万能类型：

```cpp
template <typename T>
T max(T a, T b) {
    return a > b ? a : b;
}

// 使用
int m = max<int>(3, 5); // 显式指定类型
double d = max(3.2, 5.1); // 隐式推导类型
```

### 4.2.2 类模板

```cpp
template <typename T>
class Stack {
private:
    std::vector<T> elements;
public:
    void push(const T& element);
    T pop();
};

// 使用
Stack<int> intStack;
Stack<std::string> stringStack;
```

由于**模板不是普通函数，而是一个“生成代码的蓝图（Blueprint）”**。因此如果在头文件中进行模板函数或者模板类的声明时，实现基本都在头文件中，没有对应的 `.cpp` 文件。绝大多数模板（template）实现的标准库组件，例如 `std::vector`、`std::list`、`std::map`、`std::unordered_map` 等都是这样做的。

因此，模板是做不到“头文件暴露接口，cpp 隐藏实现”的。
