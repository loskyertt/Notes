# 1. 核心结论

`class` 与 `struct` 在 C++ 中几乎拥有相同的语言能力：二者都可以包含数据成员、成员函数、构造函数、析构函数、运算符重载、继承、虚函数和模板。

二者的**标准层面差异只有两个默认值**：

| 对比项 | `struct` 默认值 | `class` 默认值 |
|---|---|---|
| 成员访问权限 | `public` | `private` |
| 继承访问权限 | `public` | `private` |

> [!summary]
> `struct` 与 `class` 的差异不是“能不能面向对象”，而是**默认访问控制不同**。工程上通常约定 `struct` 表示公开数据聚合，`class` 表示有封装边界的对象。

# 2. 默认访问权限

## 2.1 成员访问权限

`struct` 中未显式标注访问级别的成员默认为 `public`，`class` 中未显式标注的成员默认为 `private`。

```cpp
struct Point {
    double x;  // public
    double y;  // public
};

class Account {
    double balance;  // private

public:
    double getBalance() const { return balance; }
};
```

访问权限只影响**外部代码能否直接访问成员**，不改变对象的内存模型，也不改变成员函数是否存在。

## 2.2 继承访问权限

继承时如果不写 `public`、`protected` 或 `private`，默认继承权限也不同。

```cpp
struct Base {
public:
    int pub;
protected:
    int prot;
};

struct SDerived : Base {
    // 等价于 struct SDerived : public Base
};

class CDerived : Base {
    // 等价于 class CDerived : private Base
};
```

| 写法 | 实际含义 | 外部能否把派生类当基类使用 |
|---|---|---|
| `struct D : Base` | `public` 继承 | 可以 |
| `class D : Base` | `private` 继承 | 不可以 |
| `class D : public Base` | `public` 继承 | 可以 |

> [!warning]
> `class Derived : Base` 很容易被误读为普通继承，但它实际是**私有继承**。如果要表达 “Derived 是一种 Base”，应显式写成 `class Derived : public Base`。

# 3. 工程语义约定

## 3.1 适合使用 struct 的场景

`struct` 通常用于表达**数据形状**。它强调对象主要是若干字段的组合，外部直接读写字段是合理的。

| 场景 | 特征 | 示例 |
|---|---|---|
| 数据聚合 | 字段公开，成员函数很少 | `struct Point { double x, y; };` |
| 配置参数 | 作为函数或模块的输入配置 | `struct ServerOptions` |
| C 接口兼容 | 需要稳定布局或与 C ABI 交互 | `struct sockaddr_in` |
| 类型标签 | 用作模板标签或策略类型 | `struct fast_tag {};` |

```cpp
struct WindowSize {
    int width = 0;
    int height = 0;
};

WindowSize size{1280, 720};
```

## 3.2 适合使用 class 的场景

`class` 通常用于表达**有不变式的对象**。它强调内部状态需要被保护，只能通过受控接口修改。

| 场景 | 特征 | 示例 |
|---|---|---|
| 资源管理 | 构造获取资源，析构释放资源 | 文件句柄、锁、Socket |
| 状态封装 | 成员修改必须满足规则 | `BankAccount` |
| 多态接口 | 通过虚函数定义扩展点 | `Shape`、`Renderer` |
| 复杂行为 | 对象内部有业务逻辑 | `Parser`、`Scene` |

```cpp
class Circle {
public:
    explicit Circle(double radius) {
        setRadius(radius);
    }

    void setRadius(double radius) {
        if (radius < 0) {
            throw std::invalid_argument("radius must be non-negative");
        }
        m_radius = radius;
    }

    double area() const {
        return 3.14159 * m_radius * m_radius;
    }

private:
    double m_radius = 0.0;
};
```

# 4. 聚合类型与初始化关系

`struct` 常和聚合初始化一起出现，但**是否是聚合类型不取决于关键字是 `struct` 还是 `class`**，而取决于类型是否满足聚合规则。

常见聚合类型通常具有以下特征：

- 没有用户声明或用户提供的构造函数，具体规则随 C++ 标准版本有细微变化。
- 没有私有或受保护的非静态数据成员。
- 没有虚函数。
- 没有虚基类。

```cpp
struct Point {
    int x;
    int y;
};

Point p{1, 2};  // 聚合初始化
```

如果需要控制参数合法性、维护不变式或隐藏内部表示，聚合初始化通常就不是最合适的工具，此时更适合使用 `class` 与构造函数。

# 5. 常见误区

## 5.1 struct 不能有成员函数

这是错误的。`struct` 可以拥有完整的 C++ 类能力。

```cpp
struct Drawable {
    virtual void draw() const = 0;
    virtual ~Drawable() = default;
};
```

## 5.2 class 不能做简单数据类型

这也是错误的。只要显式写出 `public`，`class` 也可以像 `struct` 一样公开字段。

```cpp
class Point {
public:
    double x;
    double y;
};
```

但从可读性上看，公开数据载体通常优先用 `struct`。

## 5.3 私有继承等价于成员私有

私有继承不是“把成员变 private”这么简单。它更准确的语义是：派生类**用基类实现自己**，但不向外暴露 “is-a” 类型关系。

```cpp
class Logger {
public:
    void log(const std::string& message);
};

class Service : Logger {
    // private 继承：Service 内部可复用 Logger
};

void write(Logger& logger);

Service service;
// write(service);  // 错误：Service 不能隐式转换为 Logger&
```

# 6. 实践准则

1. 如果类型只是公开数据组合，优先使用 `struct`。
2. 如果类型需要维护不变式、隐藏状态或管理资源，优先使用 `class`。
3. 写继承时显式标注 `public`、`protected` 或 `private`，避免依赖默认值。
4. 不要用关键字本身判断类型能力，判断依据应是访问控制、对象语义和不变式。

> [!summary]
> `struct` 和 `class` 是同一套类型系统的两种入口。语言差异很小，工程语义差异很大：`struct` 偏数据，`class` 偏封装。
