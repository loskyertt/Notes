# 1. 问题背景

当类只包含 `int`、`double` 这类值成员时，编译器自动生成的拷贝通常是正确的。但当类直接管理堆内存、文件句柄、锁、Socket 等资源时，默认逐成员拷贝可能会复制“资源句柄”本身，而不是复制资源内容。

典型错误如下：

```cpp
class String {
public:
    explicit String(const char* text) {
        m_size = std::strlen(text);
        m_buffer = new char[m_size + 1];
        std::memcpy(m_buffer, text, m_size + 1);
    }

    ~String() {
        delete[] m_buffer;
    }

private:
    char* m_buffer = nullptr;
    std::size_t m_size = 0;
};

String a("hello");
String b = a;  // 编译器生成的拷贝构造：只复制指针值
```

此时 `a.m_buffer` 和 `b.m_buffer` 指向同一块堆内存。两个对象析构时会对同一地址执行两次 `delete[]`，这是未定义行为。

> [!warning]
> 只要类直接拥有资源，就必须明确思考拷贝、赋值、移动和析构语义。否则默认生成的特殊成员函数可能制造双重释放、悬垂指针或资源泄漏。

# 2. 浅拷贝与深拷贝

## 2.1 浅拷贝

浅拷贝复制成员的值。对指针成员来说，复制的是地址，而不是地址指向的内容。

```text
a.m_buffer ─┐
            ├──> "hello\0"
b.m_buffer ─┘
```

浅拷贝的问题：

- 两个对象共享同一份可变资源。
- 一个对象修改资源会影响另一个对象。
- 两个对象都析构时可能重复释放资源。

## 2.2 深拷贝

深拷贝为新对象分配独立资源，并复制资源内容。

```text
a.m_buffer ───> "hello\0"
b.m_buffer ───> "hello\0"
```

```cpp
String(const String& other)
    : m_buffer(new char[other.m_size + 1]),
      m_size(other.m_size) {
    std::memcpy(m_buffer, other.m_buffer, m_size + 1);
}
```

> [!summary]
> 浅拷贝复制“指向哪里”，深拷贝复制“拥有的内容”。资源所有权类不能让编译器默认决定这一点。

# 3. 拷贝构造函数

## 3.1 定义

拷贝构造函数用同类型对象初始化一个新对象。

```cpp
class T {
public:
    T(const T& other);
};
```

参数必须通常写成 `const T&`。如果按值传参，传参本身又要调用拷贝构造函数，会导致递归。

## 3.2 触发场景

```cpp
String a("hello");

String b = a;     // 拷贝初始化，调用拷贝构造
String c(a);      // 直接初始化，调用拷贝构造

void print(String s);
print(a);         // 按值传参，可能调用拷贝构造

String make();
String d = make(); // 返回值可能被复制或移动，也可能被消除
```

C++17 起，部分返回值场景要求强制复制消除，因此不要把“语法上像拷贝”简单等同于“一定产生运行时拷贝”。

# 4. 拷贝赋值运算符

## 4.1 与拷贝构造的区别

```cpp
String b = a;  // 新对象 b 正在创建：拷贝构造
b = a;         // b 已经存在：拷贝赋值
```

拷贝赋值面对的是一个已经拥有资源的对象，所以它必须先处理旧资源，再接收新资源。

## 4.2 基本实现

```cpp
String& operator=(const String& other) {
    if (this == &other) {
        return *this;
    }

    char* newBuffer = new char[other.m_size + 1];
    std::memcpy(newBuffer, other.m_buffer, other.m_size + 1);

    delete[] m_buffer;
    m_buffer = newBuffer;
    m_size = other.m_size;

    return *this;
}
```

先分配新资源、再释放旧资源，可以避免 `new` 抛出异常后对象已经丢失原资源。

## 4.3 Copy-and-Swap 惯用法

```cpp
class String {
public:
    friend void swap(String& lhs, String& rhs) noexcept {
        using std::swap;
        swap(lhs.m_buffer, rhs.m_buffer);
        swap(lhs.m_size, rhs.m_size);
    }

    String& operator=(String other) {
        swap(*this, other);
        return *this;
    }

private:
    char* m_buffer = nullptr;
    std::size_t m_size = 0;
};
```

参数 `other` 按值传入，意味着拷贝或移动已经在进入函数前完成；交换后，旧资源交给 `other`，由它析构释放。

# 5. 三法则、五法则与零法则

## 5.1 三法则

如果一个类需要显式定义以下任意一个，通常也需要定义另外两个：

| 函数 | 作用 |
|---|---|
| 析构函数 | 释放资源 |
| 拷贝构造函数 | 用已有对象创建新对象 |
| 拷贝赋值运算符 | 用已有对象覆盖已存在对象 |

三者共同决定资源如何被释放和复制。

## 5.2 五法则

C++11 引入移动语义后，资源管理类还应考虑：

| 函数 | 作用 |
|---|---|
| 移动构造函数 | 从临时对象接管资源 |
| 移动赋值运算符 | 释放自身旧资源后接管对方资源 |

```cpp
String(String&& other) noexcept
    : m_buffer(other.m_buffer),
      m_size(other.m_size) {
    other.m_buffer = nullptr;
    other.m_size = 0;
}

String& operator=(String&& other) noexcept {
    if (this == &other) {
        return *this;
    }

    delete[] m_buffer;
    m_buffer = other.m_buffer;
    m_size = other.m_size;

    other.m_buffer = nullptr;
    other.m_size = 0;
    return *this;
}
```

移动后源对象必须处于**可析构、可赋值**的有效状态，但不要求保留原值。

## 5.3 零法则

现代 C++ 最推荐的做法是让资源由标准库 RAII 类型管理，使类本身不需要手写任何特殊成员函数。

```cpp
class Text {
public:
    explicit Text(std::string value) : m_value(std::move(value)) {}

private:
    std::string m_value;
};
```

`std::string` 会正确处理析构、拷贝和移动，`Text` 可以依赖编译器生成的默认特殊成员函数。

> [!summary]
> 三法则是资源类的最低安全线，五法则补上移动语义，零法则是现代 C++ 的首选设计目标。

# 6. 禁止拷贝

有些资源天然不能复制，例如互斥锁、独占文件句柄、线程对象和唯一所有权指针。此时应删除拷贝操作。

```cpp
class FileHandle {
public:
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    FileHandle(FileHandle&&) noexcept = default;
    FileHandle& operator=(FileHandle&&) noexcept = default;
};
```

这样错误会在编译期暴露，而不是在运行期表现为资源重复关闭或状态损坏。

---

# 7. 实践准则

1. 能用 `std::string`、`std::vector`、`std::unique_ptr` 等 RAII 成员，就不要手写裸资源管理。
2. 如果必须手写析构函数，立刻检查是否需要拷贝构造和拷贝赋值。
3. 资源可转移时提供 `noexcept` 移动构造和移动赋值，便于标准容器优化。
4. 资源不可复制时使用 `= delete` 明确禁止拷贝。
5. 拷贝赋值必须考虑自我赋值和异常安全。

> [!warning]
> 裸指针成员不一定表示所有权，但如果它表示所有权，就必须在类型设计中说清楚谁负责释放、能否拷贝、能否移动。
