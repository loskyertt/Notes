# 1. 多态的前提

C++ 运行时多态通常需要同时满足三个条件：

1. 基类中有虚函数。
2. 派生类重写该虚函数。
3. 通过基类指针或引用调用该虚函数。

```cpp
class Animal {
public:
    virtual void speak() const = 0;
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() const override {
        std::cout << "woof\n";
    }
};

void call(const Animal& animal) {
    animal.speak();  // 动态绑定
}
```

> [!summary]
> “有继承”和“有虚函数”还不够。若对象被按值拷贝成基类对象，多态仍会失效。

---

# 2. 为什么需要指针或引用

## 2.1 对象大小在编译期必须确定

按值声明对象时，编译器必须知道变量占多少字节。

```cpp
Animal animal;  // 抽象类不能实例化；即使不是抽象类，也只能容纳 Animal 部分
Dog dog;
```

派生类通常比基类包含更多成员。一个 `Animal` 类型的变量不能容纳完整的 `Dog` 对象。

## 2.2 指针和引用保留完整对象

指针和引用不存储对象本身，而是指向或绑定已有对象。

```cpp
Dog dog;
Animal& ref = dog;
Animal* ptr = &dog;

ref.speak();  // 调用 Dog::speak
ptr->speak(); // 调用 Dog::speak
```

`ref` 和 `ptr` 的静态类型是 `Animal`，但它们访问的实际对象仍然是完整的 `Dog`。

# 3. 对象切片

## 3.1 定义

对象切片是指将派生类对象按值拷贝到基类对象中时，派生类特有部分被丢弃，只保留基类子对象。

```cpp
class Base {
public:
    virtual void run() const {
        std::cout << "Base\n";
    }
};

class Derived : public Base {
public:
    void run() const override {
        std::cout << "Derived\n";
    }

private:
    int extra = 42;
};

Derived d;
Base b = d;  // 对象切片
b.run();     // 输出 Base
```

`b` 是一个真正的 `Base` 对象，不再是 `Derived` 对象。`Derived::extra` 被切掉，虚函数分发也不再指向 `Derived`。

## 3.2 常见切片场景

| 场景 | 示例 | 后果 |
|---|---|---|
| 按值赋给基类变量 | `Base b = derived;` | 派生类部分丢失 |
| 按值传参 | `void f(Base b);` | 实参被切片 |
| 存入基类对象容器 | `std::vector<Base>` | 每个元素都是基类对象 |
| 按值返回基类 | `Base make();` | 返回值无法保留派生类动态类型 |

```cpp
void render(Base object) {
    object.run();  // 已经切片
}
```

正确做法是使用引用、指针或智能指针。

```cpp
void render(const Base& object) {
    object.run();
}
```

# 4. 多态对象的容器管理

## 4.1 错误做法：存对象本身

```cpp
std::vector<Base> objects;
objects.push_back(Derived{});  // 切片
```

`std::vector<Base>` 的每个元素大小都是 `sizeof(Base)`，无法保存不同大小的派生类对象。

## 4.2 正确做法：存智能指针

```cpp
std::vector<std::unique_ptr<Base>> objects;
objects.push_back(std::make_unique<Derived>());

for (const auto& object : objects) {
    object->run();
}
```

使用 `std::unique_ptr<Base>` 时必须确保基类析构函数是虚函数。

```cpp
class Base {
public:
    virtual void run() const = 0;
    virtual ~Base() = default;
};
```

## 4.3 引用容器的替代方式

标准容器不能直接存引用，但可以存 `std::reference_wrapper`。

```cpp
std::vector<std::reference_wrapper<Base>> refs;

Derived d;
refs.push_back(d);

refs.front().get().run();
```

这种方式不拥有对象，只适合对象生命周期由外部保证的场景。

# 5. 值语义与多态的边界

运行时多态通常需要间接层，而值语义强调对象自包含、可复制、生命周期清晰。二者并不冲突，但要明确边界。

## 5.1 需要共享抽象接口

适合使用基类指针或引用：

```cpp
void updateAll(std::vector<std::unique_ptr<Entity>>& entities) {
    for (auto& entity : entities) {
        entity->update();
    }
}
```

## 5.2 类型集合封闭

如果所有可能类型在编译期已知，`std::variant` 可以避免虚函数和堆分配。

```cpp
using Entity = std::variant<Player, Enemy, Npc>;

std::visit([](auto& entity) {
    entity.update();
}, entity);
```

## 5.3 需要复制多态对象

基类指针默认只能复制指针，不会复制动态对象。若需要“多态克隆”，常见做法是提供虚 `clone()`。

```cpp
class Shape {
public:
    virtual std::unique_ptr<Shape> clone() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Circle>(*this);
    }
};
```

# 6. 常见误区

## 6.1 指针本身导致多态

指针不是多态的充分条件。被调用函数必须是虚函数。

```cpp
class Base {
public:
    void run();
};

class Derived : public Base {
public:
    void run();
};

Base* ptr = new Derived();
ptr->run();  // 调用 Base::run，因为 run 不是虚函数
```

## 6.2 引用不会切片

引用绑定不会创建新对象，因此不会切片。

```cpp
Derived d;
Base& b = d;  // 不切片
```

但是如果通过引用再按值拷贝成基类对象，仍然会切片。

```cpp
Base copy = b;  // 切片
```

## 6.3 shared_ptr 可以随便从裸指针构造

不要用同一个裸指针构造多个 `std::shared_ptr`。

```cpp
Base* raw = new Derived();
std::shared_ptr<Base> p1(raw);
std::shared_ptr<Base> p2(raw);  // 错误：两个独立控制块，可能双重释放
```

正确做法：

```cpp
auto p = std::make_shared<Derived>();
std::shared_ptr<Base> base = p;
```

# 7. 实践准则

1. 多态参数使用 `Base&`、`const Base&`、`Base*` 或智能指针，避免 `Base` 按值传递。
2. 多态容器使用 `std::unique_ptr<Base>` 或 `std::shared_ptr<Base>`，不要使用 `std::vector<Base>`。
3. 多态基类必须提供虚析构函数。
4. 需要复制多态对象时提供虚 `clone()`，不要直接复制基类对象。
5. 类型集合封闭且性能敏感时，考虑 `std::variant`。

> [!summary]
> C++ 多态的关键是保留完整动态对象，并通过虚函数进行间接调用。对象切片一旦发生，派生类状态和动态类型都会丢失。
