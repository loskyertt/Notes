# 1. 继承的语义

继承用于表达类型之间的关系。最常见的 `public` 继承表示 **is-a**：派生类对象可以被当作基类对象使用。

```cpp
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    double area() const override;
};
```

`Circle` 是一种 `Shape`，因此 `Circle*` 可以隐式转换为 `Shape*`。

> [!summary]
> 继承首先是类型关系，其次才是代码复用手段。若只是复用实现，优先考虑组合。

# 2. 访问控制与继承方式

## 2.1 成员访问级别

| 成员级别 | 本类内部 | 派生类内部 | 类外部 |
|---|---:|---:|---:|
| `public` | 可以 | 可以 | 可以 |
| `protected` | 可以 | 可以 | 不可以 |
| `private` | 可以 | 不可以 | 不可以 |

`private` 成员不会因为继承层级变深而变得可访问。派生类只能通过基类暴露的 `public` 或 `protected` 接口间接使用它。

```cpp
class Base {
private:
    int secret = 0;

protected:
    int state = 0;
};

class Derived : public Base {
    void f() {
        state = 1;   // 正确
        // secret = 1; // 错误
    }
};
```

## 2.2 继承方式

继承方式决定基类的 `public` 和 `protected` 成员在派生类中对外呈现为什么权限。

| 继承方式 | 基类 `public` 成员在派生类中 | 基类 `protected` 成员在派生类中 | 类型替换关系 |
|---|---|---|---|
| `public` | `public` | `protected` | 保留 |
| `protected` | `protected` | `protected` | 对外不保留 |
| `private` | `private` | `private` | 对外不保留 |

```cpp
class PublicD : public Base {};
class PrivateD : private Base {};
```

只有 `public` 继承通常表示可公开替换的 is-a 关系。

> [!warning]
> `class D : Base` 默认是 `private` 继承。为了可读性，继承时应始终显式写出继承方式。

# 3. 构造、析构与特殊成员

## 3.1 构造顺序

派生类对象构造时，顺序固定为：

1. 虚基类子对象。
2. 直接基类子对象。
3. 当前类成员对象。
4. 当前类构造函数体。

```cpp
class Base {
public:
    explicit Base(int value);
};

class Derived : public Base {
public:
    Derived(int value, std::string name)
        : Base(value),
          m_name(std::move(name)) {
    }

private:
    std::string m_name;
};
```

如果基类没有默认构造函数，派生类必须在初始化列表中显式调用基类构造函数。

## 3.2 析构顺序

析构顺序与构造相反：

1. 当前类析构函数体。
2. 当前类成员对象。
3. 直接基类子对象。
4. 虚基类子对象。

如果类打算被多态删除，基类析构函数必须是 `virtual`。

## 3.3 构造函数不会普通继承

构造函数、析构函数、拷贝构造函数和拷贝赋值运算符不是普通成员函数，它们不会以普通方式被继承。

C++11 支持用 `using` 引入基类构造函数：

```cpp
class Base {
public:
    explicit Base(int value);
};

class Derived : public Base {
public:
    using Base::Base;
};

Derived d(42);
```

如果派生类有自己的成员需要初始化，通常仍应手写构造函数。

# 4. 名称遮蔽与 using 声明

派生类中只要声明了与基类同名的成员函数，就会遮蔽基类中的同名函数集合，即使参数列表不同。

```cpp
class Object {
public:
    void addChild(Object* child);
};

class Scene : public Object {
public:
    void addChild(class ScreenObject* child);
};

Scene scene;
Object* object = nullptr;
// scene.addChild(object);  // 错误：Scene::addChild 遮蔽了 Object::addChild
```

使用 `using` 可以把基类重载集合引入派生类作用域。

```cpp
class Scene : public Object {
public:
    using Object::addChild;

    void addChild(ScreenObject* child);
    void addChild(WorldObject* child);
};
```

> [!warning]
> 名称遮蔽不是虚函数重写。重写要求基类函数是 `virtual`，并且派生类函数签名匹配；名称遮蔽只和名字查找有关。

# 5. 多重继承

## 5.1 基本语法

C++ 允许一个类继承多个基类。

```cpp
class Renderable {
public:
    virtual void render() = 0;
};

class Updatable {
public:
    virtual void update(float dt) = 0;
};

class Actor : public Renderable, public Updatable {
public:
    void render() override;
    void update(float dt) override;
};
```

接口型多重继承较常见；带数据成员和复杂状态的多重继承更容易产生布局、二义性和初始化问题。

## 5.2 同名成员二义性

```cpp
class A {
public:
    void reset();
};

class B {
public:
    void reset();
};

class C : public A, public B {};

C c;
// c.reset();  // 错误：不知道调用 A::reset 还是 B::reset
c.A::reset();
c.B::reset();
```

# 6. 菱形继承与虚继承

## 6.1 菱形继承问题

```text
      A
     / \
    B   C
     \ /
      D
```

如果 `B` 和 `C` 都普通继承自 `A`，那么 `D` 对象中会包含两份独立的 `A` 子对象。

这会带来两个问题：

- 数据冗余：两份 `A` 状态可能不一致。
- 访问二义性：`D` 调用 `A` 成员时不清楚走 `B` 路径还是 `C` 路径。

## 6.2 虚继承

虚继承可以让最终派生类中只保留一份共享虚基类子对象。

```cpp
class A {};

class B : virtual public A {};
class C : virtual public A {};

class D : public B, public C {};
```

虚基类由**最派生类**负责初始化。

```cpp
class A {
public:
    explicit A(int value);
};

class B : virtual public A {
public:
    B() : A(1) {}  // 当构造 D 时，这里的 A(1) 不负责最终虚基类初始化
};

class C : virtual public A {
public:
    C() : A(2) {}
};

class D : public B, public C {
public:
    D() : A(3), B(), C() {}  // 最派生类 D 初始化虚基类 A
};
```

> [!warning]
> 虚继承会增加对象布局和构造规则复杂度。只有在确实需要共享唯一基类子对象时才使用。

# 7. 组合优于继承

当类型关系不是稳定的 is-a，而只是想复用功能时，应优先使用组合。

```cpp
class Player {
public:
    void update(float dt) {
        m_physics.update(dt);
        m_animation.update(dt);
    }

private:
    PhysicsComponent m_physics;
    AnimationComponent m_animation;
};
```

| 设计方式 | 语义 | 优点 | 风险 |
|---|---|---|---|
| 继承 | is-a | 支持多态替换 | 耦合强，基类变化影响大 |
| 组合 | has-a | 职责清晰，替换灵活 | 需要显式转发接口 |

---

# 8. 实践准则

1. 用 `public` 继承表达稳定的 is-a 关系。
2. 只是复用实现时，优先组合。
3. 基类若有虚函数，析构函数也应为虚函数。
4. 派生类中重写虚函数时始终写 `override`。
5. 多重继承优先用于纯接口；状态复杂时谨慎使用。
6. 遇到同名函数遮蔽时，用 `using Base::name` 恢复基类重载集合。

> [!summary]
> 继承可以建立强大的抽象层级，也会引入强耦合。好的继承关系应该经得起“派生类是否真的是一种基类”的追问。
