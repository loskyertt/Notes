# 1. 核心问题

C++ 内存管理首先要区分两件事：

| 维度 | 关注点 | 典型问题 |
|---|---|---|
| **存储位置** | 对象的字节放在哪里 | 栈、堆、静态区 |
| **生命周期** | 对象从构造到析构活多久 | 离开作用域是否自动销毁 |
| **所有权** | 谁负责释放资源 | 自动释放、手动 `delete`、RAII |

> [!summary]
> **栈和堆不是类型特性，而是对象的存储位置。**同一个类型既可以创建在栈上，也可以创建在堆上。

---

# 2. 常见内存区域

## 2.1 自动存储区

自动存储区通常对应函数调用栈。局部变量在进入作用域时创建，离开作用域时自动销毁。

```cpp
void f()
{
    int x = 42;
    std::array<int, 4> a{1, 2, 3, 4};
} // x 与 a 在这里自动销毁
```

**特点：**

- 分配和释放速度快，本质上通常只是移动栈指针。
- 生命周期清晰，和作用域绑定。
- 空间有限，不适合放巨大对象或运行期大小未知的大数组。

## 2.2 动态存储区

动态存储区通常称为堆。对象通过 `new`、`malloc` 或标准库容器在运行期申请。

```cpp
int* p = new int(42);
delete p;
p = nullptr;
```

**特点：**

- 大小可在运行期决定。
- 生命周期不再自动等于作用域，必须由所有权规则管理。
- 分配器需要维护空闲块、处理碎片和同步，开销通常高于栈分配。

## 2.3 静态存储区

全局变量、命名空间作用域变量、`static` 局部变量具有静态存储期。

```cpp
int global_count = 0;

void f()
{
    static int once = 1;
}
```

这类对象在程序启动前后初始化，在程序结束时销毁。它们不适合表达短生命周期资源，尤其要警惕跨翻译单元初始化顺序问题。

# 3. 栈对象与堆对象

## 3.1 `std::array` 的存储模型

`std::array<T, N>` 是一个固定大小数组包装器，元素直接嵌在 `std::array` 对象内部。

```cpp
void f()
{
    std::array<int, 4> a{1, 2, 3, 4};
}
```

若 `a` 是局部变量，整个对象通常在栈上：

```text
栈:
+-----------------------------+
| a[0] | a[1] | a[2] | a[3]   |
+-----------------------------+
```

若 `std::array` 是类成员，则元素嵌在该类对象内部；类对象在哪里，数组数据就在哪里。

## 3.2 `std::vector` 的存储模型

`std::vector<T>` 对象本身通常只保存指针、大小和容量；元素数据存放在堆上。

```cpp
void f()
{
    std::vector<int> v{1, 2, 3, 4};
}
```

```text
栈:                         堆:
+------------------+        +-----------------------------+
| data | size | cap | -----> | v[0] | v[1] | v[2] | v[3] |
+------------------+        +-----------------------------+
```

因此，`v` 离开作用域会自动析构，但析构函数内部会释放它管理的堆内存。这就是标准库容器提供的 RAII。

# 4. 性能差异

## 4.1 分配成本

栈分配通常非常便宜：函数进入时为一批局部变量预留栈帧，函数退出时整体回收。

堆分配更复杂：

- 查找合适的空闲块。
- 维护分配器元数据。
- 可能触发锁竞争。
- 空闲块不足时可能向操作系统申请更多内存。

因此，频繁的小对象堆分配是内存池和对象池要优化的重点。

## 4.2 访问成本

`std::array` 访问元素时，元素和对象本身在同一块连续内存中：

```cpp
std::array<int, 4> a{};
a[0] = 1;
```

`std::vector` 访问元素时，需要先读取 `vector` 对象里的数据指针，再跳到堆上的元素区：

```cpp
std::vector<int> v(4);
v[0] = 1;
```

这种二次寻址通常不是最大开销，但在极端热路径中会影响流水线和缓存表现。

## 4.3 Cache 命中率

CPU 读取内存时通常按缓存行加载，常见缓存行大小为 64 字节。连续访问的数据更容易被一次性带入缓存。

| 数据组织 | Cache 友好性 | 说明 |
|---|---|---|
| 连续数组 | 高 | 相邻元素地址连续，硬件预取器容易识别 |
| 指针跳转结构 | 低 | 节点或行可能散落在堆上，容易 Cache Miss |
| 小对象频繁堆分配 | 不稳定 | 分配位置受分配器状态影响 |

> [!tip]
> 性能敏感代码优先追求**数据连续性**，而不只是减少语法上的指针数量。

# 5. 生命周期与所有权

## 5.1 `delete` 释放的是对象

```cpp
TreeNode* root = new TreeNode(2);
delete root;
root = nullptr;
```

`delete root` 的含义是：

1. 调用 `root` 指向对象的析构函数。
2. 将该对象占用的动态内存归还给分配器。
3. `root` 这个指针变量本身仍然存在。

```text
delete 前:

栈:                 堆:
+--------+          +-------------+
| root --|--------> | TreeNode(2) |
+--------+          +-------------+

delete 后:

栈:                 堆:
+--------+          +-------------+
| root --|----X     | 已释放内存  |
+--------+          +-------------+
```

若不将 `root` 置为 `nullptr`，它会保存一个已经失效的地址，形成悬空指针。

## 5.2 优先使用 RAII

手动 `new/delete` 容易出现泄漏、重复释放和异常安全问题。现代 C++ 应优先使用 RAII 类型：

| 需求 | 推荐工具 |
|---|---|
| 独占拥有一个对象 | `std::unique_ptr<T>` |
| 共享拥有一个对象 | `std::shared_ptr<T>` |
| 动态数组 | `std::vector<T>` |
| 固定大小数组 | `std::array<T, N>` |
| 原始缓冲区 | `std::vector<std::byte>` 或专用分配器 |

# 6. 易错点

> [!warning]
> 常见问题集中在“对象生命周期”和“指针变量生命周期”混淆。

1. **把 `delete p` 理解为删除指针变量**：错误。它释放的是 `p` 指向的动态对象。
2. **返回局部变量地址**：局部变量离开作用域后销毁，返回其地址会产生悬空指针。
3. **大数组放栈上**：可能导致栈溢出，应改用 `std::vector` 或堆分配。
4. **保存 `vector` 元素指针后继续扩容**：扩容会搬迁元素，旧指针和引用会失效。
5. **把堆分配等同于慢代码**：真正要看分配频率、访问局部性、对象大小和生命周期。

---

# 7. 总结

| 概念 | 核心结论 |
|---|---|
| 栈 | 快、自动释放、容量有限、生命周期随作用域 |
| 堆 | 灵活、需要所有权管理、分配成本更高 |
| `std::array` | 数据嵌在对象内部，固定大小，连续 |
| `std::vector` | 对象本身管理堆上连续数组，动态大小 |
| RAII | 用对象生命周期管理资源生命周期 |

> [!summary]
> C++ 内存管理的主线是：**明确对象在哪里、活多久、由谁释放**。只要这三点清楚，指针、容器、内存池和对象池都能放到同一套逻辑中理解。
