> 在大型 C++ 项目中，**预编译头文件（Precompiled Headers，简称 PCH）** 可以提升编译速度。它的核心思想很简单：**不再重复编译那些永远不会改变的代码。**

在典型的 C++ 开发中，你可能会在几百个 `.cpp` 文件里都包含 `<iostream>`、`<vector>` 或者像 `Windows.h` 这样巨大的头文件。

- **传统方式**：编译器在处理每一个 `.cpp` 时，都要把这些头文件从磁盘读入、解析、转换成机器码。这导致了大量的重复劳动。
    
- **PCH 方式**：编译器只编译一次这些头文件，并将编译后的中间状态（二进制快照）保存到一个 `.pch` 或 `.gch` 文件中。后续编译其他文件时，可以快速加载这个快照。

---

# 1. 在 Visual Studio 中设置

> Visual Studio 对 PCH 的支持非常成熟，通常默认使用 `pch.h`（旧版本叫 `stdafx.h`）。

- **step 1**：创建一个 `pch.h`，把你常用的、不常变动的库放进去：

```cpp
// pch.h
#pragma once
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <Windows.h> // 这种巨大的头文件最适合放这里
```

- **step 2**：创建一个 `pch.cpp`，内容只有一行：

```cpp
// pch.cpp
#include "pch.h"
```

- **step 3**：配置项目属性
	1. 右键项目 -> **属性** -> **C/C++** -> **预编译头**。
	2. 将 **预编译头** 选项设为 **创建 (/Yc)**。
	3. **关键点**：针对整个项目设为 **使用 (/Yu)**，但唯独对 `pch.cpp` 这个文件，右键属性设为 **创建 (/Yc)**。这样 VS 就会以 `pch.cpp` 为入口生成二进制快照。

# 2. 在 CMake 中设置

> 在过去，CMake 处理 PCH 非常麻烦，需要手写很多复杂的宏。但从 **CMake 3.16** 开始，官方引入了内置支持，变得异常简单。

## 2.1 基本配置

假设项目结构如下：

```txt
Project/
├── CMakeLists.txt
├── src/
│   ├── pch.h      <-- 你想预编译的头文件
│   ├── main.cpp
│   └── player.cpp
```

在 `CMakeLists.txt` 中写入：

```cmake
cmake_minimum_required(VERSION 3.16)
project(MyGame)

# 1. 正常添加你的执行程序或库
add_executable(MyGame src/main.cpp src/player.cpp)

# 2. 指定哪个目标使用哪个预编译头
target_precompile_headers(MyGame PRIVATE src/pch.h)
```

1. **自动生成触发文件**：CMake 会在编译目录下自动生成一个临时的 `.c` 或 `.cpp` 文件（效果等同于 `pch.cpp`），用来触发 PCH 的生成。
    
2. **强制包含 (Force Include)**：CMake 会自动给该项目下的所有 `.cpp` 文件加上编译参数（例如 GCC 的 `-include` 或 MSVC 的 `/FI`）。

> 使用 cmake 构建好项目后，可以不用在 `main.cpp` 或 `player.cpp` 的第一行写 `#include "pch.h"`。当你编译项目时，编译器会**自动**在每个源文件的开头插入这个头文件。如果你习惯于在每个 `.cpp` 里显式地写上 `#include "pch.h"`，你也可以这样做。CMake 会检测到这一点，并依然利用已经预编译好的二进制快照来加速，而不会报错。

## 2.2 进阶配置

> 多个项目共享一个 PCH。

如果你有一个解决方案，里面有好几个子项目（比如一个游戏引擎和几个小游戏），它们都想用同一个 `common_pch.h`，你可以这样写：

```cmake
# 定义一个 Interface 目标来存放 PCH 配置
add_library(my_pch_setup INTERFACE)
target_precompile_headers(my_pch_setup INTERFACE src/common_pch.h)

# 让不同的项目链接这个配置
target_link_libraries(Game01 PRIVATE my_pch_setup)
target_link_libraries(Game02 PRIVATE my_pch_setup)
```

## 2.3 注意事项

1. **PRIVATE vs PUBLIC**：
    - `PRIVATE`：只有当前这个项目（MyGame）会使用这个 PCH。
    - `PUBLIC`：如果别的项目链接了 MyGame，它们也会强制使用这个 PCH（通常不建议，除非你很确定）。

2. **混合 C/C++**：如果你的项目里既有 `.c` 又有 `.cpp`，你可能需要分开指定，因为 C 和 C++ 的预编译快照是不通用的：
    ```cmake
    target_precompile_headers(MyGame PRIVATE 
        "$<$<COMPILE_LANGUAGE:CXX>:src/pch.hpp>"
        "$<$<COMPILE_LANGUAGE:C>:src/pch.h>"
    )
    ```

# 3. 使用建议

> Q：哪些东西该放进 PCH？

- **标准库**：`vector`, `map`, `iostream` 等。
- **第三方库**：`GLFW`, `Glad`, `ImGui`, `Boost` 等。
- **项目内的底层工具类**：前提是这些类几乎不再修改。

> Q：哪些东西**不要**放进 PCH？

- **频繁变动的头文件**：如果你把一个每天都要改代码的头文件放进 PCH，那么一旦它变了，**整个项目的所有文件都要重新编译**。这反而会让 PCH 变成性能负担。

> 通常建议在项目根目录创建一个 `src/pch.h`（或 `src/hzpch.h` 这种带前缀的名字，以防冲突），并只包含那些真正“稳定”的代码。
