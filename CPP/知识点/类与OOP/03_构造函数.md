# 1. 构造函数的职责

构造函数负责在对象生命周期开始时建立对象的有效状态。它不是普通的初始化工具，而是类不变式的入口。

```cpp
class User {
public:
    explicit User(std::string name) : m_name(std::move(name)) {
        if (m_name.empty()) {
            throw std::invalid_argument("name must not be empty");
        }
    }

private:
    std::string m_name;
};
```

> [!summary]
> 构造函数应保证：对象一旦构造完成，就处于可安全使用的状态。不要把必要初始化留给调用者之后手动补齐。

# 2. 成员初始化列表

## 2.1 基本语法

成员初始化列表位于构造函数参数列表之后、函数体之前。

```cpp
class Entity {
public:
    Entity(std::string name, int score)
        : m_name(std::move(name)),
          m_score(score) {
    }

private:
    std::string m_name;
    int m_score;
};
```

进入构造函数体之前，所有基类和成员对象都已经完成初始化。因此在函数体内写赋值并不是“初始化成员”，而是在成员已存在后再次赋值。

## 2.2 必须使用初始化列表的成员

以下成员不能先默认构造再赋值，必须在初始化列表中完成：

| 成员类型 | 原因 |
|---|---|
| `const` 成员 | 创建后不能再赋值 |
| 引用成员 | 引用必须在创建时绑定 |
| 无默认构造函数的成员对象 | 无法先默认构造 |
| 基类子对象 | 基类构造必须在派生类构造体之前完成 |

```cpp
class Config {
public:
    Config(int id, std::string& name)
        : m_id(id),
          m_name(name),
          m_file("config.json") {
    }

private:
    const int m_id;
    std::string& m_name;
    std::ifstream m_file;
};
```

## 2.3 初始化顺序

成员的真实初始化顺序只取决于**成员声明顺序**，不取决于初始化列表中的书写顺序。

```cpp
class Bad {
public:
    Bad() : b(1), a(b) {}  // a 先声明，所以 a 先初始化；此时 b 尚未初始化

private:
    int a;
    int b;
};
```

> [!warning]
> 初始化列表的书写顺序应与成员声明顺序保持一致。这样既避免隐藏 bug，也能消除编译器关于初始化顺序的警告。

# 3. 构造函数类型

## 3.1 默认构造函数

默认构造函数是可以不传实参调用的构造函数。它可以完全无参，也可以所有参数都有默认值。

```cpp
struct Point {
    int x = 0;
    int y = 0;
};

Point p;  // 调用默认构造函数
```

如果类中声明了任意构造函数，编译器通常不再隐式声明无参默认构造函数。

```cpp
struct Point {
    Point(int x, int y) : x(x), y(y) {}

    int x;
    int y;
};

// Point p;  // 错误：没有默认构造函数
```

需要保留默认构造能力时，可以显式写出：

```cpp
struct Point {
    Point() = default;
    Point(int x, int y) : x(x), y(y) {}

    int x = 0;
    int y = 0;
};
```

## 3.2 有参构造函数

有参构造函数用于根据输入参数建立对象状态。

```cpp
class Rectangle {
public:
    Rectangle(int width, int height)
        : m_width(width),
          m_height(height) {
        if (width <= 0 || height <= 0) {
            throw std::invalid_argument("invalid size");
        }
    }

private:
    int m_width;
    int m_height;
};
```

## 3.3 转换构造函数与 explicit

只有一个实参可调用的构造函数可能成为隐式转换入口。

```cpp
class UserId {
public:
    UserId(int value) : m_value(value) {}

private:
    int m_value;
};

void load(UserId id);

load(42);  // 允许：int 隐式转换为 UserId
```

如果这种隐式转换不是明确想要的，应加 `explicit`。

```cpp
class UserId {
public:
    explicit UserId(int value) : m_value(value) {}

private:
    int m_value;
};

// load(42);       // 错误
load(UserId{42});  // 正确
```

> [!tip]
> 单参数构造函数默认考虑加 `explicit`。只有当类型本来就是轻量包装且隐式转换语义自然时，才放开隐式转换。

# 4. 委托构造函数

委托构造函数允许一个构造函数调用同一个类中的另一个构造函数，以复用公共初始化逻辑。

```cpp
class Player {
public:
    Player() : Player("Unknown", 100) {}

    Player(std::string name, int health)
        : m_name(std::move(name)),
          m_health(health) {
        validate();
    }

private:
    void validate() const {
        if (m_health < 0) {
            throw std::invalid_argument("health must be non-negative");
        }
    }

    std::string m_name;
    int m_health;
};
```

委托构造函数的初始化列表中只能调用目标构造函数，不能同时初始化其他成员。

# 5. default 与 delete

## 5.1 default

`= default` 表示要求编译器生成默认实现。

```cpp
class Token {
public:
    Token() = default;
    ~Token() = default;
};
```

它常用于显式表达“这个特殊成员函数使用默认语义”。

## 5.2 delete

`= delete` 表示禁止某个函数被调用。

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
```

这比把函数声明为 `private` 更清晰，因为编译错误会直接说明该函数已被删除。

# 6. 平凡构造与非平凡构造

## 6.1 平凡构造

平凡构造函数通常由编译器生成，不执行用户自定义逻辑。此类类型常用于底层数据、二进制兼容或性能敏感场景。

```cpp
struct Point {
    int x;
    int y;
};

Point p;  // 局部对象中 x 和 y 未初始化
```

平凡不等于安全。它通常意味着没有自动初始化逻辑。

## 6.2 非平凡构造

只要构造过程需要执行用户逻辑、调用非平凡成员构造、处理虚继承或初始化复杂成员，构造函数就可能是非平凡的。

```cpp
struct Person {
    std::string name;
    int age = 0;
};
```

`std::string` 需要执行构造逻辑，因此 `Person` 的默认构造不是简单的“什么都不做”。

## 6.3 为什么区分重要

| 维度 | 平凡类型 | 非平凡类型 |
|---|---|---|
| 构造成本 | 通常极低 | 可能有运行时代码 |
| 内存操作 | 更容易安全地按字节搬移 | 不能随意 `memcpy` |
| C 兼容 | 更适合 ABI 交互 | 通常不适合直接二进制复制 |

# 7. 实践准则

1. 构造函数应建立完整有效的对象状态。
2. 成员初始化优先使用初始化列表，而不是构造函数体内赋值。
3. 初始化列表顺序与成员声明顺序保持一致。
4. 单参数构造函数默认加 `explicit`。
5. 能用默认语义就用 `= default`，不能安全使用的操作用 `= delete`。
6. 构造函数不要调用依赖派生类行为的虚函数。

> [!summary]
> 构造函数的核心不是“把字段填上”，而是把对象从原始内存变成一个满足不变式、可安全析构、可安全使用的实体。
