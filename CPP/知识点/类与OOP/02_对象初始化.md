# 1. 初始化的核心问题

**初始化**发生在对象创建时，负责建立对象的初始状态；**赋值**发生在对象已经存在之后，负责用新值覆盖旧状态。

```cpp
std::string a("hello");  // 初始化：构造对象
std::string b;
b = "hello";             // 赋值：对象已存在
```

这个区别非常重要，因为 `const` 成员、引用成员、没有默认构造函数的成员只能在初始化阶段确定，不能先默认创建再赋值。

> [!summary]
> 初始化解决“对象如何出生”，赋值解决“对象出生后如何改变”。构造函数、成员初始化列表和列表初始化都属于初始化体系。

# 2. 常见初始化形式

## 2.1 语法总览

| 形式 | 示例 | 常见用途 |
|---|---|---|
| 默认初始化 | `T obj;` | 创建对象但不提供显式初值 |
| 值初始化 | `T obj{};` | 创建确定的零值或默认状态 |
| 直接初始化 | `T obj(args);` | 明确调用匹配构造函数 |
| 拷贝初始化 | `T obj = value;` | 允许隐式转换构造 |
| 直接列表初始化 | `T obj{args};` | 推荐的通用初始化方式 |
| 拷贝列表初始化 | `T obj = {args};` | 列表初始化的赋值式写法 |
| 聚合初始化 | `Agg obj{a, b};` | 初始化公开数据聚合 |
| 指定初始化 | `Agg obj{.x = 1};` | C++20 聚合成员指定 |

## 2.2 默认初始化与值初始化

默认初始化和值初始化最容易混淆。

```cpp
struct Data {
    int x;
    double y;
};

Data a;    // 默认初始化：局部对象中 x 和 y 的值不确定
Data b{};  // 值初始化：x = 0, y = 0.0
```

对内置类型来说，`T obj;` 在局部作用域下不会自动清零；`T obj{};` 会执行值初始化，通常更安全。

> [!warning]
> 不要把 `int x;` 理解成“默认就是 0”。局部自动变量未初始化时读取会产生未定义行为。

# 3. 列表初始化

## 3.1 直接列表初始化

直接列表初始化使用 `{}`，是现代 C++ 中最常用的初始化写法之一。

```cpp
struct Vertex {
    int x;
    int y;
    int z;
};

Vertex v{1, 2, 3};
int count{10};
std::vector<int> nums{1, 2, 3};
```

它的主要优点是：

- 语法统一，适用于内置类型、数组、类类型和容器。
- 避免 `T obj();` 被解析为函数声明的 Most Vexing Parse。
- 禁止隐式收窄转换。
- 对聚合类型可以直接逐成员初始化。

## 3.2 拷贝列表初始化

```cpp
Vertex v = {1, 2, 3};
```

它仍然属于列表初始化，也会执行收窄转换检查。和 `Vertex v{1, 2, 3};` 的差异主要体现在 `explicit` 构造函数参与重载决议时：拷贝列表初始化不能调用 `explicit` 构造函数。

```cpp
class UserId {
public:
    explicit UserId(int value) : m_value(value) {}

private:
    int m_value;
};

UserId a{42};     // 正确
// UserId b = {42};  // 错误：不能通过拷贝列表初始化调用 explicit 构造函数
```

## 3.3 收窄转换检查

列表初始化会拒绝可能丢失信息的隐式转换。

```cpp
double d = 3.14;

int a = d;                 // 允许，但小数部分被截断
// int b{d};               // 错误：列表初始化禁止收窄转换
int c{static_cast<int>(d)}; // 正确：显式表达截断意图
```

常见收窄转换包括：

| 转换 | 是否可能被 `{}` 拒绝 | 原因 |
|---|---|---|
| `double` 到 `int` | 是 | 小数部分丢失 |
| 大整数到小整数 | 是 | 可能溢出 |
| 大整数到 `float` | 是 | 可能无法精确表示 |
| `int` 到 `double` | 通常允许 | `double` 可精确表示 32 位 `int` |

# 4. 直接初始化与拷贝初始化

## 4.1 直接初始化

```cpp
class Vertex {
public:
    Vertex(int x, int y, int z) : x(x), y(y), z(z) {}

private:
    int x;
    int y;
    int z;
};

Vertex v(1, 2, 3);
```

直接初始化强调“用这些参数直接构造对象”。它会考虑 `explicit` 构造函数。

## 4.2 拷贝初始化

```cpp
class Name {
public:
    Name(const char* text) : value(text) {}

private:
    std::string value;
};

Name n = "Alice";
```

拷贝初始化可能触发隐式转换构造。如果构造函数被标记为 `explicit`，这种写法就不再允许。

```cpp
class Name {
public:
    explicit Name(const char* text) : value(text) {}

private:
    std::string value;
};

Name a("Alice");  // 正确
// Name b = "Alice"; // 错误
```

# 5. 聚合初始化与指定初始化

## 5.1 聚合初始化

聚合类型可以按成员声明顺序初始化。

```cpp
struct Rect {
    int x;
    int y;
    int width;
    int height;
};

Rect r{0, 0, 1920, 1080};
```

未显式提供的成员会被值初始化。

```cpp
Rect r{10, 20};  // width = 0, height = 0
```

## 5.2 指定初始化

C++20 支持对聚合类型使用成员名指定初始化。

```cpp
struct Point {
    int x;
    int y;
    int z;
};

Point p{.x = 1, .y = 2, .z = 3};
```

指定初始化的限制：

- 目标类型必须是聚合类型。
- 成员名必须真实存在。
- 标准 C++ 要求按成员声明顺序书写。
- 不能重复初始化同一成员。

# 6. initializer_list 的优先级

当一个类同时存在 `std::initializer_list` 构造函数和普通构造函数时，`{}` 会优先尝试匹配 `initializer_list`。

```cpp
class MagicBox {
public:
    MagicBox(int count, int value);
    MagicBox(std::initializer_list<int> values);
};

MagicBox a(10, 1);  // 调用 MagicBox(int, int)
MagicBox b{10, 1};  // 调用 MagicBox(initializer_list<int>)
```

`std::vector` 是最经典的例子：

```cpp
std::vector<int> a(10, 1);  // 10 个元素，每个都是 1
std::vector<int> b{10, 1};  // 2 个元素：10 和 1
```

> [!warning]
> `{}` 不总是比 `()` 更符合意图。需要表达“数量、容量、尺寸”等构造参数时，优先确认是否会被 `initializer_list` 抢先匹配。

# 7. 实践准则

1. 对普通对象优先使用 `T obj{};` 或 `T obj{args};`，减少未初始化与收窄转换风险。
2. 需要调用 `explicit` 构造函数时，使用直接初始化或直接列表初始化。
3. 初始化容器时区分“元素列表”和“构造参数”，尤其是 `std::vector`。
4. 对简单聚合可使用聚合初始化；对需要校验不变式的类型，应使用构造函数。
5. 不要把初始化和赋值混为一谈，尤其是包含 `const`、引用或资源成员的类。

> [!summary]
> 对象初始化的重点不是记住所有语法，而是判断：对象是否已经存在、是否需要隐式转换、是否允许收窄、是否会优先匹配 `initializer_list`。
