# 1. 问题引入

## 1.1 错误示例

先看一个包含错误的自定义 `String` 类：

```cpp
#include <cstring>
#include <iostream>

class String {
private:
    char*        m_buffer;
    unsigned int m_size;

public:
    // 构造函数
    String(const char* string) {
        m_size   = strlen(string);
        m_buffer = new char[m_size + 1];
        memcpy(m_buffer, string, m_size + 1);
    }

    // 析构函数
    ~String() {
        delete[] m_buffer;
    }

    // 重载 []
    char& operator[](unsigned int index) { return m_buffer[index]; }

    friend std::ostream& operator<<(std::ostream& stream, const String& string);
};

std::ostream& operator<<(std::ostream& stream, const String& string) {
    stream << string.m_buffer;
    return stream;
}

int main() {
    String str1 = "loskyertt";
    String str2 = str1;   // 问题在这里

    str2[2] = 'a';

    std::cout << str1 << std::endl;  // 期望输出 loskyertt
    std::cout << str2 << std::endl;  // 期望输出 loakyertt
}
```

编译并运行后，出现如下错误：

```bash
❯ ./build/example/02_example
loakyertt
loakyertt
free(): double free detected in tcache 2
zsh: abort      ./build/example/02_example
```

这里暴露了两个问题：

1. `str2[2] = 'a'` 修改了 `str2`，但 `str1` 的内容也跟着变了。
2. 程序退出时发生 `double free`，直接崩溃。

## 1.2 原因分析

执行 `String str1 = "loskyertt";` 后，`str1.m_buffer` 指向堆上的一块内存：

```
栈 (Stack)                    堆 (Heap)
┌─────────────────┐           ┌────────────────┐
│ str1            │           │                │
│  m_size  = 9    │           │  loskyertt\0   │
│  m_buffer ──────┼──────────►│                │
└─────────────────┘           └────────────────┘
                                地址: 0x12345678
```

执行 `String str2 = str1;` 时，由于没有定义拷贝构造函数，编译器自动生成了一个**浅拷贝**版本，仅把 `str1.m_buffer` 的**指针值**复制给 `str2.m_buffer`：

```
栈 (Stack)                    堆 (Heap)
┌─────────────────┐           ┌───────────────────┐
│ str1            │           │                   │
│  m_size  = 9    │     ┌────►│  loskyertt\0      │
│  m_buffer ──────┼─────┤     │                   │
└─────────────────┘     │     └───────────────────┘
                        │       地址: 0x12345678
┌─────────────────┐     │
│ str2            │     │      ← 两个指针指向同一块内存！
│  m_size  = 9    │     │
│  m_buffer ──────┼─────┘
└─────────────────┘
```

因此：

- `str2[2] = 'a'` 修改了这块共享内存，导致 `str1` 的内容也被改变。
- `main` 函数结束时，**局部变量按构造的逆序析构**：`str2` 先析构，`delete[] str2.m_buffer` 释放了 `0x12345678`；紧接着 `str1` 析构，再次 `delete[] str1.m_buffer`，对**同一地址二次释放**，这是标准明确定义的**未定义行为（Undefined Behavior）**，典型表现为 `double free` 崩溃。

## 1.3 核心问题：三法则

上述案例**违反了"三法则"（Rule of Three）**。

在 C++98/03 中，如果一个类显式定义了以下三个函数中的**任意一个**：

- 析构函数（Destructor）
- 拷贝构造函数（Copy Constructor）
- 拷贝赋值运算符（Copy Assignment Operator）

那么通常**应该同时定义另外两个**。

上述 `String` 类只定义了析构函数，却没有定义另外两个，导致编译器自动生成的浅拷贝版本制造了问题。C++11 之后，三法则进一步扩展为"五法则"（Rule of Five），加入了移动构造和移动赋值。

# 2. 浅拷贝与深拷贝

**拷贝（Copy）** 是用一个已有对象创建一个完全独立的新对象。但当类成员中含有**指向堆内存的指针**时，"拷贝指针"和"拷贝指针指向的内容"是两种截然不同的行为：

| | **浅拷贝（Shallow Copy）** | **深拷贝（Deep Copy）** |
|---|---|---|
| **定义** | 逐字节复制成员的值；指针成员只复制地址，不复制内容 | 为指针成员**重新分配**一块内存，并将原内容完整复制过来 |
| **内存状态** | 多个对象共享同一块堆内存 | 每个对象拥有独立的堆内存 |
| **问题** | `double free`、一个对象改动影响另一个 | 无上述问题，但需要手动管理内存 |
| **来源** | 编译器自动生成的默认拷贝 | 需要手动实现 |

深拷贝后的内存状态：

```
栈 (Stack)                    堆 (Heap)
┌─────────────────┐           ┌───────────────────┐
│ str1            │           │                   │
│  m_size  = 9    │     ┌────►│   loskyertt\0     │
│  m_buffer ──────┼─────┘     │                   │
└─────────────────┘           └───────────────────┘
                                地址: 0x12345678

┌─────────────────┐           ┌───────────────────┐
│ str2            │           │                   │
│  m_size  = 9    │     ┌────►│   loskyertt\0     │
│  m_buffer ──────┼─────┘     │                   │
└─────────────────┘           └───────────────────┘
                                地址: 0x87654321   ← 不同的独立内存块
```

# 3. 拷贝构造函数

## 3.1 语法与定义

拷贝构造函数是一种特殊的构造函数，用于通过**同类型的已有对象**来初始化新对象。

```cpp
// 参数必须是 const 引用，防止拷贝时再次触发拷贝构造，造成无限递归
ClassName(const ClassName& other);
```

## 3.2 触发时机

拷贝构造函数会在以下三种情况下被调用：

**情况一：对象初始化**

```cpp
String str1("Hello");
String str2 = str1;   // 拷贝初始化，调用拷贝构造函数
String str3(str1);    // 直接初始化，同样调用拷贝构造函数
```

> 注意：`String str2 = str1;` 是**初始化**而非赋值，调用的是拷贝构造函数，而非 `operator=`。

**情况二：按值传参（Pass by Value）**

```cpp
void printString(String s) {   // s 是实参的副本，通过拷贝构造函数创建
    std::cout << s << std::endl;
}

printString(str1);   // 此处发生一次拷贝
```

> 为避免不必要的拷贝开销，应优先使用 `const String& s` 引用传参。

**情况三：按值返回（Return by Value）**

```cpp
String createString() {
    String temp("Temporary");
    return temp;   // 理论上触发拷贝构造（实践中编译器通常通过 RVO/NRVO 优化掉）
}
```

> **RVO / NRVO（返回值优化）**：现代编译器（C++17 起部分场景强制要求）会直接在调用方的栈空间构造对象，完全省略这次拷贝，因此实际运行中这里不一定发生拷贝。

## 3.3 深拷贝的实现

```cpp
// 深拷贝构造函数
String(const String& other) {
    m_size   = other.m_size;
    m_buffer = new char[m_size + 1];          // 1. 独立申请新内存
    memcpy(m_buffer, other.m_buffer, m_size + 1);  // 2. 复制内容，而非地址
}
```

# 4. 拷贝赋值运算符

## 4.1 与拷贝构造函数的区别

```cpp
String str2 = str1;   // ① 初始化：对象尚不存在 → 调用拷贝构造函数
str2 = str1;          // ② 赋值：对象已存在   → 调用 operator=
```

两者的本质区别：拷贝构造函数面对的是**一个尚未存在的对象**（无旧内存需要处理）；拷贝赋值运算符面对的是**一个已存在的对象**（必须先释放旧内存，否则内存泄漏）。

## 4.2 正确实现

```cpp
String& operator=(const String& other) {
    // 1. 防止自我赋值（str1 = str1）
    //    若不检查，第 2 步会释放自己的内存，第 3 步读取已被释放的数据 → UB
    if (this == &other) return *this;

    // 2. 释放当前对象持有的旧内存，防止内存泄漏
    delete[] m_buffer;

    // 3. 深拷贝：申请新内存并复制内容
    m_size   = other.m_size;
    m_buffer = new char[m_size + 1];
    memcpy(m_buffer, other.m_buffer, m_size + 1);

    // 4. 返回 *this 以支持链式赋值（str1 = str2 = str3）
    return *this;
}
```

## 4.3 Copy-and-Swap 惯用法（进阶）

上面的实现有一个缺陷：如果 `new` 抛出异常，`delete[] m_buffer` 已执行但新内存未申请成功，对象进入不合法状态。**Copy-and-Swap 惯用法**可以提供**强异常安全保证（Strong Exception Safety）**：

```cpp
// 前提：需要实现 swap 成员函数
friend void swap(String& a, String& b) noexcept {
    using std::swap;
    swap(a.m_buffer, b.m_buffer);
    swap(a.m_size,   b.m_size);
}

// copy-and-swap：参数 other 按值传入，已经完成了深拷贝
String& operator=(String other) {   // 注意：按值传参，不是引用
    swap(*this, other);             // 交换内部资源
    return *this;
    // other 在此处析构，释放掉原来 *this 持有的旧内存
}
```

这种写法的优势：
- 拷贝（`new`）发生在参数传入阶段；若 `new` 抛出异常，`*this` 完全未被修改。
- 代码复用了拷贝构造函数和析构函数的逻辑，减少重复代码。
- 自动处理自我赋值（交换后 `other` 析构，`*this` 数据不变）。

# 5. 三法则与五法则

## 5.1 三法则（Rule of Three，C++98/03）

**如果一个类需要显式定义以下三者之一，通常就需要同时定义全部三个：**

| 函数 | 签名 | 缺失时编译器的行为 |
|---|---|---|
| 析构函数 | `~ClassName()` | 生成空析构，不释放任何资源 |
| 拷贝构造函数 | `ClassName(const ClassName&)` | 生成逐成员**浅拷贝** |
| 拷贝赋值运算符 | `ClassName& operator=(const ClassName&)` | 生成逐成员**浅拷贝赋值** |

## 5.2 五法则（Rule of Five，C++11 起）

C++11 引入**移动语义**后，三法则扩展为五法则，在三法则的基础上再加入：

| 函数 | 签名 | 作用 |
|---|---|---|
| 移动构造函数 | `ClassName(ClassName&&)` | **转移**资源所有权，而非复制 |
| 移动赋值运算符 | `ClassName& operator=(ClassName&&)` | **转移**资源所有权 |

**移动 vs 拷贝的区别**：

```
拷贝（Copy）：
  str1 ──► [内存A]        str1 ──► [内存A]
                   ─────►
  str2 = ?         str2 ──► [内存B]  ← 新申请，复制内容，开销 O(n)

移动（Move）：
  str1 ──► [内存A]        str1 ──► nullptr（资源已转移）
                   ─────►
  str2 = ?         str2 ──► [内存A]  ← 直接接管指针，开销 O(1)
```

移动语义的典型触发场景：函数按值返回、`std::move()` 显式转移、容器扩容时转移元素。

**`String` 类的移动构造函数实现示例：**

```cpp
// 移动构造函数：从右值引用"窃取"资源
String(String&& other) noexcept
    : m_buffer(other.m_buffer),
      m_size(other.m_size)
{
    // 将 other 置于可安全析构的"空"状态
    other.m_buffer = nullptr;
    other.m_size   = 0;
}

// 移动赋值运算符
String& operator=(String&& other) noexcept {
    if (this == &other) return *this;

    delete[] m_buffer;              // 释放自己原有资源

    m_buffer = other.m_buffer;      // 窃取 other 的资源
    m_size   = other.m_size;

    other.m_buffer = nullptr;       // 置空 other
    other.m_size   = 0;

    return *this;
}
```

## 5.3 零法则（Rule of Zero，现代 C++ 最佳实践）

如果一个类的成员全部使用**RAII 对象**（`std::string`、`std::vector`、`std::unique_ptr` 等）管理资源，那么编译器自动生成的五个函数往往已经正确，**无需手动定义任何一个**，这被称为**零法则（Rule of Zero）**。

```cpp
// 遵循零法则的 String 类：完全不需要手动定义五法则中的任何函数
class String {
private:
    std::string m_buffer;   // RAII：由 std::string 自动管理内存

public:
    String(const char* str) : m_buffer(str) {}

    char& operator[](size_t index) { return m_buffer[index]; }

    friend std::ostream& operator<<(std::ostream& stream, const String& s) {
        stream << s.m_buffer;
        return stream;
    }
    // 析构、拷贝构造、拷贝赋值、移动构造、移动赋值全部由编译器正确生成
};
```

# 6. 禁止拷贝

有些资源在语义上**不应该被复制**（如独占文件句柄、互斥锁、网络连接等）。此时应主动删除拷贝函数，让编译器在误用时报错，而非在运行时崩溃。

## 6.1 语法

```cpp
class NonCopyable {
public:
    NonCopyable() = default;

    // 删除拷贝构造函数和拷贝赋值运算符
    NonCopyable(const NonCopyable&)            = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;

    // 可选：允许移动（转移所有权），但禁止拷贝
    NonCopyable(NonCopyable&&)            = default;
    NonCopyable& operator=(NonCopyable&&) = default;
};
```

## 6.2 应用于错误示例

```cpp
class String {
private:
    char* m_buffer;
    int   m_size;

public:
    String(const char* str) {
        m_size   = strlen(str);
        m_buffer = new char[m_size + 1];
        memcpy(m_buffer, str, m_size + 1);
    }

    ~String() { delete[] m_buffer; }

    // 明确禁止拷贝
    String(const String&)            = delete;
    String& operator=(const String&) = delete;
};

int main() {
    String str1 = "loskyertt";
    String str2 = str1;   // 编译错误：拷贝构造函数已被删除
}
```

编译器会在**编译期**给出明确的错误，而非在运行时出现难以调试的 `double free`。

# 7. 修复方案总结

针对第 1 章的错误示例，有三种修复方案：

## 7.1 方案一：实现深拷贝（遵循 Rule of Three）

```cpp
class String {
private:
    char* m_buffer;
    int   m_size;

public:
    // 构造函数
    String(const char* str) {
        m_size   = strlen(str);
        m_buffer = new char[m_size + 1];
        memcpy(m_buffer, str, m_size + 1);
    }

    // 深拷贝构造函数
    String(const String& other) {
        m_size   = other.m_size;
        m_buffer = new char[m_size + 1];          // 申请独立内存
        memcpy(m_buffer, other.m_buffer, m_size + 1);  // 复制内容
    }

    // 拷贝赋值运算符
    String& operator=(const String& other) {
        if (this == &other) return *this;
        delete[] m_buffer;
        m_size   = other.m_size;
        m_buffer = new char[m_size + 1];
        memcpy(m_buffer, other.m_buffer, m_size + 1);
        return *this;
    }

    // 析构函数
    ~String() { delete[] m_buffer; }

    char& operator[](unsigned int index) { return m_buffer[index]; }

    friend std::ostream& operator<<(std::ostream& stream, const String& s) {
        stream << s.m_buffer;
        return stream;
    }
};
```

修复后的运行结果：

```bash
loskyertt    ← str1 不受 str2 修改影响
loakyertt    ← str2 修改正常
             ← 程序正常退出，无 double free
```

## 7.2 方案二：禁止拷贝

如果业务上不需要支持拷贝，直接删除拷贝函数，让编译器在误用时报错（见第 6 章）。

## 7.3 方案三（推荐）：使用 RAII 容器，遵循零法则

使用 `std::string` 替代裸指针，彻底消除手动内存管理，编译器自动生成的拷贝函数即为正确的深拷贝：

```cpp
class String {
private:
    std::string m_buffer;

public:
    String(const char* str) : m_buffer(str) {}

    char& operator[](size_t index) { return m_buffer[index]; }

    friend std::ostream& operator<<(std::ostream& stream, const String& s) {
        stream << s.m_buffer;
        return stream;
    }
    // 无需手动定义析构、拷贝构造、拷贝赋值、移动构造、移动赋值
};
```

**三种方案的对比：**

| 方案 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| 深拷贝（Rule of Three/Five） | 需要拷贝，且必须手动管理资源 | 完全掌控内存 | 代码量大，容易出错 |
| 禁止拷贝 | 资源不应被复制的类 | 编译期报错，安全 | 失去拷贝能力 |
| RAII 容器（Rule of Zero） | 绝大多数情况 | 代码简洁，零错误 | 依赖标准库 |
