# 1. 编译器层面的默认行为差异

`struct` 与 `class` 在 C++ 标准中**功能等价**，均可支持成员函数、继承、多态、模板等完整面向对象特性。二者仅在**默认访问控制**与**默认继承权限**上存在语法级差异。

## 1.1 默认访问权限规则

|         |  默认权限  |
|---------|------|
| struct 成员 | 默认 public，成员/方法可外部访问 |
| class 成员 | 默认 private，成员/方法需显式声明 public |

代码示例：

```cpp
struct Point {
    double x;  // ✅ 默认 public，外部可直接访问
    double y;
};

class Account {
    double balance;  // ⚠️ 默认 private，外部无法直接访问
public:
    double getBalance() const { return balance; }
};
```

> [!note] 访问控制的作用域边界
> 默认访问权限仅影响**直接声明的成员**。嵌套类型、友元声明、继承关系中的访问控制需单独指定，不受外层关键字影响。

## 1.2 默认继承权限规则

继承时的默认权限差异是易被忽视的关键点，直接影响派生类对基类成员的访问能力。

```text
【struct 继承】
struct Base { public: int pub; protected: int prot; private: int priv; };
struct Derived : Base {  // 等价于 : public Base
    // pub  → public 继承，Derived 外部可访问
    // prot → protected 继承，Derived 内部可访问
    // priv → 不可访问（基类私有成员永远不可派生访问）
};

【class 继承】
class Base { public: int pub; protected: int prot; private: int priv; };
class Derived : Base {  // 等价于 : private Base
    // pub  → private 继承，Derived 外部不可访问
    // prot → private 继承，Derived 外部不可访问
    // priv → 不可访问
};
```

继承权限默认值对比：

```cpp
// 验证代码：编译通过/失败直观展示默认继承差异
struct Base {
    int publicMember;
protected:
    int protectedMember;
};

struct S_Derived : Base {  // 默认 public 继承
    void test() {
        publicMember = 1;      // ✅ 可访问
        protectedMember = 2;   // ✅ 可访问
    }
};
void external_test() {
    S_Derived s;
    s.publicMember = 3;  // ✅ public 继承，外部可访问基类 public 成员
}

class C_Derived : Base {  // 默认 private 继承
    void test() {
        publicMember = 1;      // ✅ 类内部可访问
        protectedMember = 2;   // ✅ 类内部可访问
    }
};
void external_test_class() {
    C_Derived c;
    // c.publicMember = 3;  // ❌ 编译错误：private 继承使基类 public 成员在派生类外部不可见
}
```

> [!warning] 私有继承的语义陷阱
> `class Derived : Base`（私有继承）表示"实现复用"而非"类型兼容"，派生类对象**不能**隐式转换为基类指针/引用。若需多态行为，必须显式声明 `: public Base`。

# 2. 语义约定与工程实践规范

尽管语法等价，C++ 社区通过长期实践形成了清晰的**语义分工**，遵循约定可显著提升代码可读性与可维护性。

## 2.1 struct 的典型应用场景

`struct` 适用于**数据聚合**场景，强调"是什么"（What it is）而非"能做什么"（What it does）。

| 场景类型 | 特征描述 | 代码示例 |
|:---|:---|:---|
| **纯数据载体** | 仅含公有数据成员，无或仅有简单构造函数 | `struct Point { double x, y; };` |
| **C 兼容接口** | 与 C 语言 ABI 交互，需保持内存布局一致 | `struct sockaddr_in { ... };` |
| **模板元编程** | 作为类型标签（Tag）或策略容器 | `struct DefaultPolicy { /* ... */ };` |
| **聚合初始化** | 支持 `{}` 列表初始化，语义清晰 | `Rect r{0, 0, 100, 200};` |

```cpp
// 现代 C++ 中的 struct 最佳实践
struct Config {
    std::string host;
    uint16_t port;
    bool enable_tls;
    
    // ✅ 允许简单构造函数，保持聚合特性（C++20 起）
    Config(std::string h, uint16_t p) 
        : host(std::move(h)), port(p), enable_tls(true) {}
};

// 使用：语义清晰，强调"数据定义"
Config cfg{"localhost", 8080};
```

> [!tip] 聚合类型判定（C++20 标准）
> `struct` 保留聚合初始化能力的条件：
> 1. 无用户声明的**非平凡**构造函数（C++20 放宽：允许显式默认构造函数）
> 2. 无私有/受保护的非静态数据成员
> 3. 无虚函数、无虚基类
> 4. 无基类（C++20 允许有基类但需满足其他条件）

## 2.2 class 的典型应用场景

`class` 适用于**行为封装**场景，强调"能做什么"及"如何保护内部状态"。

| 场景类型 | 特征描述 | 代码示例 |
|:---|:---|:---|
| **资源管理** | 遵循 RAII，含析构函数/移动语义 | `class FileHandle { ~FileHandle(); };` |
| **多态体系** | 含虚函数、抽象基类、接口设计 | `class Shape { virtual double area() = 0; };` |
| **状态封装** | 私有成员 + 公有接口，不变式保护 | `class BankAccount { private: double balance; };` |
| **复杂逻辑** | 成员函数含业务规则、异常处理 | `class Parser { bool parse(const std::string&); };` |

```cpp
// class 的封装性实践：不变式（Invariant）保护
class Circle {
public:
    explicit Circle(double r) : radius(r) { validate(); }
    
    double getArea() const { return 3.14159 * radius * radius; }
    
    void setRadius(double r) {
        radius = r;
        validate();  // ✅ 每次修改后验证不变式
    }
    
private:
    double radius;
    
    void validate() const {
        if (radius < 0) throw std::invalid_argument("Radius must be non-negative");
    }
};
```

# 3. 历史演进与设计哲学

## 3.1 向后兼容性的技术约束

```text
C++ 语言演进时间线：

1979-1985  "C with Classes" 阶段
├─ 保留 C 语言 struct 语法
├─ 新增 class 关键字支持封装/继承
└─ 为兼容 C 代码，struct 默认 public 保持不变

1985-1998  C++98 标准化
├─ struct/class 功能完全等价（除默认权限）
├─ 模板引入：template <class T> 与 template <typename T> 等价
└─ 社区形成"struct=数据，class=对象"的语义约定

2011-2020  现代 C++ 演进
├─ C++11：统一初始化{}、constexpr 增强 struct 表达能力
├─ C++17：结构化绑定、聚合类型规则放宽
├─ C++20：允许聚合类型含用户声明构造函数
└─ 语义分工更加明确：struct 用于"被动数据"，class 用于"主动对象"
```

## 3.2 模板参数中的关键字选择

```cpp
// 以下两种声明完全等价，class 仅为历史习惯
template <class T> void func1(T param);
template <typename T> void func2(T param);  // ✅ 更推荐：语义更清晰

// 特例：当模板参数本身是模板时，class 可读性略优
template <template <class> class Container>  // 嵌套 class 更易区分层级
void process(const Container<int>& c);
```

> [!note] 前向声明的兼容性
> `struct Name;` 与 `class Name;` 在大多数场景下可互换，但若后续定义与声明关键字不一致（如声明用 struct，定义用 class），可能触发编译器警告。建议保持声明与定义关键字一致。

# 4. 常见误区澄清

- **误区一**：`struct` 不能有成员函数或虚函数

```cpp
// ✅ 完全合法：struct 支持完整 OOP 特性
struct Drawable {
    virtual void render() const = 0;  // ✅ 纯虚函数
    virtual ~Drawable() = default;    // ✅ 虚析构函数
};

struct Circle : Drawable {
    void render() const override { /* ... */ }  // ✅ 重写虚函数
};
```

- **误区二**：`class` 不能用于 POD 类型

```cpp
// ✅ 合法：class 可设计为平凡类型（Trivial Type）
class Point {
public:  // ✅ 显式声明 public，模拟 struct 行为
    double x, y;
    // 无用户声明构造函数/析构函数 → 平凡类型
};

static_assert(std::is_trivial_v<Point>, "Point is trivial");  // ✅ 编译通过
```

- **误区三**：默认继承权限可忽略

```cpp
// 错误示例：私有继承导致的接口污染

class Logger {
public:
    void log(const std::string& msg);
};

class Service : Logger {  // ⚠️ 默认 private 继承！
    // log() 在 Service 内部可用，但 Service 对象不能当作 Logger 使用
};

void process(Logger& l) { l.log("test"); }

int main() {
    Service s;
    // process(s);  // ❌ 编译错误：Service 不能隐式转换为 Logger&
    // s.log("x");  // ❌ 编译错误：log() 在 Service 外部不可见
}
```
