# 1. 栈分配

这是最简单、最基础的写法。数组的大小必须在 **编译时** 确定。

```cpp
void stack_array_example() {
    // 定义一个 3x4 的二维数组
    int array[3][4] = {0}; 

    // 内存布局：在栈上连续分布（12 个 int 紧挨着）
    array[1][2] = 5; 
}
```

- **优点**：分配速度快（只需移动栈指针）；内存完全连续，对 Cache 极其友好。
    
- **缺点**：大小固定，不能根据用户输入动态改变；栈空间有限（通常只有 1MB-8MB），分配超大数组会导致 **Stack Overflow**。

---

# 2. 堆分配

> 当数组大小在运行时决定，或者数组非常大时，必须使用堆分配。

## 2.1 写法一：指针数组（不推荐）

这种写法在很多老旧教材中很常见，但在实际开发中因性能低下而被嫌弃。

```cpp
int rows = 3, cols = 4;
int** array = new int*[rows]; // 分配一个存放指针的数组
for (int i = 0; i < rows; i++) {
    array[i] = new int[cols]; // 每一行单独分配
}

// 释放时需要循环 delete
```

> 由于 **内存不连续**，每一行都可能分布在堆的不同角落。CPU 访问时需要多次跳转，Cache 命中率极低。

---

## 2.2 写法一：一维数组模拟多维（推荐）

现代 C++ 性能优化的核心技巧是：**将多维数组展平（Flatten）为一维数组。**

```cpp
void flattened_array_example() {
    int rows = 100, cols = 100;
    // 在堆上分配一整块连续内存
    int* array = new int[rows * cols];

    // 访问 array[row][col] 转换为：
    // array[row * cols + col]
    for (int y = 0; y < rows; y++) {
        for (int x = 0; x < cols; x++) {
            array[y * cols + x] = 0;
        }
    }
}
```

- **优势**：
    1. **内存连续性**：保证了最高级别的 Cache 命中率。
    2. **管理简单**：只需要一次 `new` 和一次 `delete`。
    3. **兼容性**：可以轻松传递给需要连续内存的 C 接口或图形 API。

---

# 4. 容器替代方案

如果你不想手动处理 `new/delete` 和复杂的索引计算：

- **固定大小**：使用 `std::array<std::array<int, 4>, 3>`。
- **动态大小**：使用 `std::vector<int>` 并配合上面的 **“展平”方式**。
- **专业矩阵运算**：使用成熟的库如 **Eigen** 或 **xtensor**，它们底层自动优化了内存布局和 SIMD 指令。

# 5. 其他问题

## 5.1 Q.1

> Q：一维数组的 Cache Hits 是否更高？

是的，一维数组（或展平后的多维数组）的 Cache 命中率通常远高于“指针数组”形式的多维数组。原因如下：

1. **空间局部性 (Spatial Locality)**：CPU 读取内存时会一次性加载一个 **Cache Line**（通常是 64 字节）。在一维连续数组中，当你访问 `arr[0]` 时，`arr[1]` 到 `arr[15]` 往往已经提前被加载进了 L1 Cache。
    
2. **指针跳转开销**：在 `int**` 形式的数组中，访问 `array[i][j]` 需要先读取 `array[i]` 的地址，这是一个“跳转”动作。如果那一行在内存的其他位置，之前预取的所有 Cache 全都失效了（Cache Miss）。
    
3. **硬件预取器 (Hardware Prefetcher)**：现代 CPU 的预取器对**线性扫描**极其敏感。它能识别出你正在按顺序访问内存，并提前把接下来的数据准备好。多维指针数组的乱序分布会让预取器彻底失效。

## 5.2 Q.2

> 多维数组的遍历顺序对性能有什么影响？

即便内存是连续的，遍历顺序也会影响 Cache：

- **快**：先循环行，再循环列（Row-major order），顺着内存地址读。
- **慢**：先循环列，再循环行，每次访问都跳过一整行，会导致频繁的 Cache 抖动（根据 Cache 块的频繁换入换出）。

```cpp
// 极快：内存连续访问
for(int i=0; i<rows; ++i)
    for(int j=0; j<cols; ++j)
        sum += array[i * cols + j];

// 极慢：内存跳跃访问
for(int j=0; j<cols; ++j)
    for(int i=0; i<rows; ++i)
        sum += array[i * cols + j];
```

# 6. 补充：指针数组

## 6.1 特点

示例：

```cpp
int rows = 3, cols = 4;
int** array = new int*[rows]; // 分配一个存放指针的数组
for (int i = 0; i < rows; i++) {
    array[i] = new int[cols]; // 每一行单独分配
}

// 释放时需要循环 delete
```

- **行内连续**：当你执行 `new int[cols]` 时，这一行里的所有 `int` 是在内存中紧挨着的。
    
- **行间随机（列不连续）**：每一行都是独立的一次 `new` 操作，所以“第一行的结尾”和“第二行的开头”在内存中可能相隔很远。

## 6.2 内存布局模型

我们可以把 `int** array` 想象成一个**“索引目录”**。

- Step 1：分配目录

```cpp
int** array = new int*[3];
```

这会在堆上分配一个连续的阵列，里面装的是 3 个 **指针**。

- Step 2：分配具体的每一行

```cpp
for (int i = 0; i < 3; i++) {
    array[i] = new int[4];
}
```

这会触发 3 次独立的内存申请。

内存分配如下图所示：

|**索引 (目录)**|**存储的指针值**|**实际指向的数据块 (Row)**|**内存特性**|
|---|---|---|---|
|`array[0]`|`0xf0b4`|`[ (0,0), (0,1), (0,2), (0,3) ]`|这一横排 4 个 int 地址连续|
|`array[1]`|`0xa020`|`[ (1,0), (1,1), (1,2), (1,3) ]`|这一横排 4 个 int 地址连续|
|`array[2]`|`0x4307`|`[ (2,0), (2,1), (2,2), (2,3) ]`|这一横排 4 个 int 地址连续|

![二维数组内存模型](内存管理/imgs/09_多维数组/二维数组内存模型.png)

> `array[0]`、`array[1]` 和 `array[2]` 所指向（存放）的都是 `int` 类型的指针。

- **水平方向（行）**：`array[0][0]` 和 `array[0][1]` 的地址差刚好是一个 `int` 的大小。
- **垂直方向（列）**：`array[0][0]` 和 `array[1][0]` 的地址差是 **随机** 的（取决于堆分配器的分配结果）。
