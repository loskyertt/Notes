# 1. 内存分配位置：栈 (Stack) vs 堆 (Heap)

> 这里主要以 `std::array` 和 `std::vector` 作为对比例子，来探讨两者内存分配的区别。

## 1.1 栈分配

> 比如：std::array

- **原理**：栈的分配非常简单，只是 **移动一下栈指针（Stack Pointer）**。这在 CPU 指令级别几乎是瞬间完成的。
- **特性**：`std::array` 的所有数据都直接嵌套在它所属的对象中。如果 `array` 是局部变量，它就在栈上；如果它是类的成员，它就在该类的连续内存块里。

## 1.2 堆分配（std::vector）：

- **原理**：`std::vector` 对象本身（存指针、大小、容量的那部分）在栈上，但其**数据部分**是在堆上申请的。
- **开销**：调用 `new` 或 `malloc` 需要在内存管理器中查找合适的空闲块，涉及复杂的控制逻辑，甚至可能引发系统调用，速度比移动栈指针慢几个数量级。

# 2. 性能差异

## 2.1 指针跳转

- **std::array**：由于数据就在对象内部，访问 `arr[0]` 时，CPU 知道地址就是 `arr` 的起始地址。
	
- **std::vector**：访问 `vec[0]` 需要**二次寻址**。CPU 必须先读取栈上的指针，通过指针找到堆上的地址，然后再去读数据。这种“跳转”会带来微小的延迟。

## 2.2 CPU Cache 命中率（核心原因）

> 空间局部性（Spatial Locality）

CPU 从内存读取数据时，不是按字节读，而是按 **缓存行（Cache Line，通常是 64 字节）** 读取。

- **std::array**：因为它存在于栈上或类内部，它周围通常也是你正在处理的其他相关变量。当你读取数组时，由于 Cache Line 的机制，周边的变量也顺便被加载进了高速缓存（L1/L2 Cache）。
    
- **std::vector**：数据在堆区。当你从栈跳转到堆去读数据时，大概率会发生 **Cache Miss（缓存缺失）**。CPU 必须停下来等数据从缓慢的内存（RAM）传输过来。

> Q：什么时候追求这种极致性能？

在游戏开发（处理几万个顶点）、高频交易或嵌入式开发中，这种差异会被无限放大。对于普通的业务代码，`std::vector` 的方便性通常超过了那点性能损失。
