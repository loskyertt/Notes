你现在觉得这些概念绕，主要是因为它们之间存在关联，而且有些名称非常相似。我们先不急着背定义，而是建立一个完整的框架：程序访问的虚拟地址，经过页表查询，最终转换为物理地址。

理解了这条主线，虚拟页、物理页框、页表项、页表和多级页表就容易区分了。

# 一、先建立整体认识

操作系统的分页式存储管理，主要解决一个问题：

程序使用的地址，和数据实际存放在内存中的地址，如何对应起来？

例如，程序想读取某个变量。CPU 产生一个虚拟地址，操作系统和硬件通过页表找到对应的物理位置。

程序产生虚拟地址

例如：虚拟地址 0x1234

拆分为虚拟页号 + 页内偏移

查询页表

根据虚拟页号找到对应页表项

取得物理页框号

得到物理地址

物理页框号 + 原来的页内偏移

先记住这条链路：

虚拟地址 → 虚拟页号 → 页表项 → 物理页框号 → 物理地址。

下面逐个解释其中的概念。

# 二、最基础的四个概念：页面、虚拟页、物理页框、物理页

## 1. 页面（Page）

页面是虚拟地址空间中划分出来的固定大小的块。

例如，假设页面大小是 4KB：

- 第 0 个页面：虚拟地址空间中的第一个 4KB 区域。
    
- 第 1 个页面：接下来的 4KB 区域。
    
- 第 2 个页面：再接下来的 4KB 区域。
    

页面大小由系统的分页机制规定，例如 4KB。

## 2. 虚拟页（Virtual Page）

虚拟页就是虚拟地址空间中的一个页面。

假设一个进程有如下虚拟页面：

进程的虚拟地址空间

虚拟页 0

0x0000–0x0FFF

虚拟页 1

0x1000–0x1FFF

虚拟页 2

0x2000–0x2FFF

虚拟页 3

0x3000–0x3FFF

示例：每个虚拟页大小为 4KB。

这些虚拟页属于进程的虚拟地址空间。它们不一定都已经分配物理内存，也不一定都同时驻留在物理内存中。

## 3. 物理页框（Page Frame）

物理页框是物理内存被划分出来的固定大小的块。

如果页面大小为 4KB，那么物理内存也按 4KB 的单位划分成页框。

物理内存

物理页框 0

4KB

物理页框 1

4KB

物理页框 2

4KB

物理页框 3

4KB

物理页框 4

4KB

物理页框 5

4KB

示意图：物理内存中的每个页框大小相同。

注意，物理页框是物理内存的空间单位，而虚拟页是虚拟地址空间的空间单位。

它们大小通常相同，但属于不同的地址空间。

## 4. “物理页”是什么？

这是一个容易产生歧义的叫法。

在操作系统教材中，规范而清晰的说法通常是：

- 页面（Page）：虚拟地址空间中的分页单位。
    
- 页框（Page Frame）：物理内存中的分页单位。
    

有些资料会把物理页框简称为“物理页”。如果看到这种说法，可以先结合上下文判断它指的是不是物理页框。

为了避免混淆，后面我们统一使用“虚拟页”和“物理页框”。

# 三、虚拟页和物理页框如何对应？

假设：

- 页面大小为 4KB；
    
- 进程有 4 个虚拟页；
    
- 物理内存中当前有 3 个可供该进程使用的页框。
    

操作系统可以建立如下映射：

|虚拟页号|对应物理页框号|含义|
|---|---|---|
|0|2|虚拟页 0 存放在页框 2|
|1|0|虚拟页 1 存放在页框 0|
|2|3|虚拟页 2 存放在页框 3|
|3|暂无|当前没有驻留在物理内存中|

这张表展示了两个重要结论。

第一，虚拟页号和物理页框号不必相等。

虚拟页 0 可以映射到物理页框 2，而虚拟页 1 可以映射到物理页框 0。

第二，虚拟页不一定全部同时驻留在物理内存中。

如果进程访问虚拟页 3，而它当前不在物理内存中，就可能触发缺页异常，由操作系统负责处理。

此外，虚拟内存还允许某些映射具有共享等特殊情况；上表只是最基本的示例。

# 四、页内偏移是什么？

虚拟地址不仅要告诉系统“访问哪个虚拟页”，还要告诉系统“访问这个虚拟页中的哪个字节”。

这个页内位置，就是页内偏移（Offset）。

假设：

- 页面大小为 4KB，即 \(2^{12}\) B；
    
- 那么页内偏移需要 12 位。
    

因此，虚拟地址可以划分为：

虚拟地址

虚拟页号

页内偏移

示例为 32 位虚拟地址：高 20 位是虚拟页号，低 12 位是页内偏移。

为什么偏移位数是 12？

因为一个页面有 4096 个字节，页面内部的字节位置从 0 到 4095，一共需要 \(2^{12}\) 个不同的编码。

当虚拟页映射到物理页框后，页内偏移保持不变。

例如：

- 虚拟页号：5
    
- 页内偏移：100
    
- 页表中记录虚拟页 5 映射到物理页框 12
    

那么物理地址就是：

\[ 12\times4096+100=49252 \]

也就是说，地址转换时改变的是页号部分，偏移部分不变。

# 五、页表项（PTE）是什么？

页表项，全称 Page Table Entry，简称 PTE。

它是页表中的一个条目，记录一个虚拟页对应的映射信息及管理状态。

例如：

|页表索引（虚拟页号）|页表项中的物理页框号|有效/存在状态|
|---|---|---|
|0|2|有效|
|1|0|有效|
|2|3|有效|
|3|—|无效或未驻留|

这里要特别注意：

虚拟页号通常不需要重复存储在页表项中，因为它可以通过页表项的位置（索引）确定。

比如：

- 第 0 个页表项对应虚拟页 0。
    
- 第 1 个页表项对应虚拟页 1。
    
- 第 2 个页表项对应虚拟页 2。
    

页表项通常需要存储的内容包括：

- 物理页框号；
    
- 存在位或有效位；
    
- 读写、执行等权限位；
    
- 访问位、修改位等管理信息。
    

具体字段和位数取决于硬件架构。

## 页表项大小由什么决定？

页表项大小不是由虚拟页号位数直接决定的，而是由硬件架构和页表项格式规定的。

例如，假设每个页表项是 4B，那么每个表项占 32 位。

这 32 位需要编码物理页框号及相关控制信息，但具体怎么划分，要看该架构的定义。

# 六、页表（Page Table）是什么？

页表就是由许多页表项组成的数据结构，用于记录虚拟页到物理页框的映射关系。

你可以把它理解成一个数组：

```
page_table[0]  // 虚拟页 0 对应的页表项
page_table[1]  // 虚拟页 1 对应的页表项
page_table[2]  // 虚拟页 2 对应的页表项
```

虚拟页号相当于数组下标，页表项相当于数组中的内容。

在传统分页机制中，页表存放在物理内存中，处理器通过页表基址寄存器或相关硬件机制定位页表。

## 单级页表为什么可能很大？

假设：

- 虚拟地址为 32 位；
    
- 页面大小为 4KB；
    
- 每个页表项为 4B。
    

虚拟页号位数为：

\[ 32-12=20 \]

因此虚拟页面数量为：

\[ 2^{20} \]

单级页表通常需要 \(2^{20}\) 个页表项，大小为：

\[ 2^{20}\times4\text{ B}=4\text{ MiB} \]

这里的 4MiB 是完整单级页表的大小。它并不意味着所有虚拟页面都已经分配物理页框，而是因为单级页表要能够直接索引整个虚拟页号范围。

# 七、多级页表是什么？

多级页表是把原本的一张大页表分成多个层级来组织。

例如，三级页表可以理解为：

1. 一级页表项：找到二级页表。
    
2. 二级页表项：找到三级页表。
    
3. 三级页表项：找到最终的物理页框。
    

一级页表

根据虚拟地址中的一级索引

二级页表

根据二级索引找到三级页表

三级页表

根据三级索引找到物理页框号

物理页框 + 页内偏移

得到最终物理地址

多级页表最重要的优势是：可以按需创建下级页表，避免为大量未使用的虚拟地址区域分配完整的页表空间。

例如，某个进程只使用虚拟地址空间的两个区域，那么系统可能只需要为这两个区域创建相应的下级页表，而不必建立所有区域的完整映射结构。

不过，多级页表不是免费午餐：在没有 TLB 命中的情况下，地址转换可能需要多次访问内存来逐级查表。

# 八、最后区分：页表、页表项、页框、页面

|概念|一句话理解|
|---|---|
|页面（Page）|虚拟地址空间的固定大小分块|
|虚拟页|虚拟地址空间中的一个页面|
|页框（Page Frame）|物理内存的固定大小分块|
|物理页框号|物理内存中页框的编号|
|页内偏移|页面内部的字节位置|
|页表项（PTE）|记录某个虚拟页的映射和控制信息|
|页表|由多个页表项组成的映射结构|
|单级页表|通过一张页表直接索引虚拟页|
|多级页表|通过多层页表逐级定位最终映射|
|页表基址寄存器|保存或定位当前地址空间页表的起始位置|

最建议你牢牢记住的关系是：

\[ \boxed{ \text{虚拟页号} \xrightarrow{\text{查页表}} \text{物理页框号} } \]

\[ \boxed{ \text{物理地址} = \text{物理页框号}\times\text{页面大小} + \text{页内偏移} } \]

如果你能够把这两个公式和“虚拟页属于虚拟地址空间、物理页框属于物理内存”这三个概念联系起来，分页式存储管理的大部分基础题就有了清晰的逻辑起点。
